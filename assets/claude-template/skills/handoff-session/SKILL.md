# 会话交接 (Handoff Session)

## 定位

探索或澄清结束后,把工作交给 1~N 个新会话继续:每个目标落一个产出目录 + 一份交接文件,新会话凭启动语接着干;当前会话尚未确定归属时,先写主任务目录即绑定到主任务。

## 流程

1. **列出交接目标(1~N 个)** —— 问清每个新会话要继续做什么。每个目标确认一个 feature-id:
   - `docs/features/` 下已有对应目录 → 直接复用,不重新命名。
   - 没有 → 按 write-spec 的命名规则新建:`YYYY-MM-DD-[业务ID-]<标题>`;业务 ID 有无、标题语言(中/英/混合)由用户确认,**禁止中文转英文 slug**;重名追加短后缀。
   - feature-id 一旦确认即固定,新会话里的 `/write-spec` 直接复用。
2. **确认主任务与负责人** —— 多个目标时让用户指定主任务(默认第一个);负责人取 `git config user.name`,向用户展示确认。负责人必须与该负责人本人的 `git config user.name` **逐字一致**——平台由负责人的客户端按它判定是否创建任务,写成显示名(如把 `zhangsan` 写成「张三」)任务就建不出来。
3. **看当前会话归属,再写交接文件** —— 先跑 `cgraphx task current`:
   - 未绑定,或来源是「自动(读)」→ 先写主任务目录,当前会话由此确定绑定到主任务。
   - 来源是「自动(写)」或「显式绑定」→ 写交接文件**不改变**当前会话的归属(确定后不切换),如实告诉用户当前会话仍归哪个任务;此时主任务只决定共享背景放在哪里。
   - 然后先写主任务目录的交接文件,再写其余目录;路径 `docs/features/<feature-id>/<文件前缀>-交接提示词.md`,文件前缀 = 有业务ID `<业务ID>-<标题>`,无则 `<标题>`。正文按下方样例的固定小节写;「未决问题」没有就省略,有则「下一步」写 `/clarify-requirements`。
4. **输出启动语** —— 每个目录一条,原样给用户;内容只有 `先读 docs/features/<feature-id>/<文件前缀>-交接提示词.md 再继续。`,不附加摘要或交接全文。

## 交接文件样例

两个交接目标:主任务「积分发放规则」,另一任务「积分兑换」。

`docs/features/2026-10-18-REQ-1024-积分发放/REQ-1024-积分发放-交接提示词.md`:

```markdown
# 交接: 积分发放规则

> feature-id: 2026-10-18-REQ-1024-积分发放
> 负责人: zhangsan
> 日期: 2026-10-18
> 主任务: 本任务

## 本任务范围

- 按会员等级重算下单积分:普通会员 1 元 = 1 分,黄金会员 1 元 = 2 分
- 发放记录写入积分流水,带订单号与规则版本
- 不含兑换侧改动(见 `2026-10-18-REQ-1024-积分兑换`)

## 已锁定决策

- 退款时按原发放比例扣回积分
- 积分有效期为自然年,次年 1 月 1 日清零

## 依赖

- `2026-10-18-REQ-1024-积分兑换`:兑换扣减依赖本任务产出的积分流水

## 共享背景

运营侧会员积分改版:原「下单统一返 1%」改为按会员等级差异化返积分,并支持退款扣回。规则已由运营确认,不再调整;兑换比例不变,由另一个会话实现。

## 下一步

`/write-spec`
```

`docs/features/2026-10-18-REQ-1024-积分兑换/REQ-1024-积分兑换-交接提示词.md`:

```markdown
# 交接: 积分兑换

> feature-id: 2026-10-18-REQ-1024-积分兑换
> 负责人: zhangsan
> 日期: 2026-10-18
> 主任务: 2026-10-18-REQ-1024-积分发放

## 本任务范围

- 兑换页改为按新积分流水校验余额
- 不含积分发放规则(见主任务)

## 已锁定决策

- 兑换比例维持 100 积分 = 1 元

## 未决问题

- 兑换失败时已扣积分是否自动退回——待运营确认;推荐自动退回,否则要人工补发

## 依赖

- `2026-10-18-REQ-1024-积分发放`:需要其积分流水结构

## 共享背景

见 `docs/features/2026-10-18-REQ-1024-积分发放/REQ-1024-积分发放-交接提示词.md`。

## 下一步

`/clarify-requirements`(先定「未决问题」,再 `/write-spec`)
```

给用户的启动语(每个目录一条,原样分别发给对应新会话):

```text
先读 `docs/features/2026-10-18-REQ-1024-积分发放/REQ-1024-积分发放-交接提示词.md` 再继续。
先读 `docs/features/2026-10-18-REQ-1024-积分兑换/REQ-1024-积分兑换-交接提示词.md` 再继续。
```

## 不做什么

- 不写 spec / plan / 代码——交接文件只记录本任务范围、已锁定决策、未决问题、依赖。
- 不把用户没拍板的推荐写进「已锁定决策」——放「未决问题」并附推荐。
- 不自动开启新会话——启动语交给用户,由用户贴给新会话。
- 不把交接全文或摘要塞进启动语。
- 非主任务文件不复制共享背景,只写一行指向主任务交接文件。
