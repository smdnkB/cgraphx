# Schema 变更约定(约定文本)

> init-project-guides 生成 data-standards.md 时,将下文**逐字拷入**「## Schema 变更约定」节(`<工程>` 替换为项目实际工程名;单工程项目去掉工程分层表述)。不得改写、概括或省略。

## Schema 变更约定

- **全量(最终态,写透)**:`docs/schema-knowledge/<工程>/ddl/<表名>.sql` 一表一文件、表名命名,始终是该表的最终 CREATE TABLE——模型一变就直接改成最终版,不保留历史;新表登记 INDEX.md。基线与周期校准由 `/export-table-ddl` 负责。
- **增量(流水,只增不改)**:需求变更脚本落在 `docs/features/<feature-id>/sql/[<工程>/]`(多工程加一层工程目录,单工程平铺),一次动作一个文件,命名 `<两位序号>-<动作名>.sql`(如 `01-新建用户表.sql`、`02-用户表新增手机号字段.sql`);执行顺序即序号顺序;开发期模型反复 → 追加新文件,不回头改旧的。DML(初始化/订正数据)同目录同命名。
- 改造既有功能:全量直接改到最终,需求内只记增量;全新功能:建表语句同样进需求 sql/(它是一条增量动作),全量正常维护到最终。
- 发版增量集合 = 上次发版以来各需求 `sql/` 的汇集,按需求目录日期 + 文件序号执行。
- **交付自检**:全量终态 = 增量动作依次执行的结果;不一致 = 漏维护,视为交付未完成。
