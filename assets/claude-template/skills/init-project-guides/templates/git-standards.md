# git-standards.md 生成模板

git-standards.md 是**提交门禁文件**(precommit-check hook 指向它),含两部分。门禁触发时 agent 自己跑 `git diff --cached` 对照逐项判断,命中报告用户,不替用户改代码。

## 第一部分 · 提交消息规范

从最近 50-100 条历史 message 挖风格,按 SKILL「生成形态纪律」生成——**一条带标注的正例 + 行为规则,不写反例画廊、不写散文解释**。形态照此(标注写实际来源):

```
## 提交格式(就这一种,照抄)
CRM-req74442 单元测试 --2 @req74442
├─ CRM-req74442   需求号,来自 <实际票据系统,如 Jira 需求单>;同一需求贯穿同一编号(含 @ 处)
├─ 单元测试 --2    本步做了什么(中文);多步任务末尾 --序号
└─ @req74442      编号收尾,便于 git log 按号追溯
bug 同构:bug58017 <描述> @bug58017

## 行为规则
- 编号拿不到 → 停下来问用户,不提交无编号 commit,不许猜
- <署名行决策:加 / 不加 co-author 署名——这是「没有」型规范,示例传不出「无」,必须显式一句(覆盖 agent 默认时尤其)>
- <breaking change / schema 变更等正文标注——挖到才写,无则不写>
```

挖掘口径:标题格式(如 `CRM-req74181<描述>-client@req74181` 这类项目独有格式)**挖不出来就问用户,不得编造**;票据关联、语言、多步约定全部落进标注与行为规则,不单开段落解释;「历史风格已废」只写「只认上述格式」一句,不枚举废格式。

**新项目(无历史)**:给常见模式选项让用户选(Conventional Commits `type(scope): subject` / 票据前缀式),或用户直接给团队规范,选定后仍按上述形态生成。

## 第二部分 · 提交前检查点(项目自定义)

按技术栈给默认检查点 + 用户确认增删;每项写"查什么 + 为什么危险"。通用种子:

- 被注释掉的开关/注册项(写该项目实际语法:Spring `@Component`/`@Scheduled`/`@JmsListener` 等注解、前端组件注册、配置开关)——被注释 = 功能静默失效,高危
- 被注释掉的业务调用(监听注册、定时任务、关键链路入口)
- 未闭合逻辑(括号失衡、if/try/for 未配对)
- 写死的魔法字符串/数字(密码、URL、ID、阈值)
- 新增 TODO/FIXME/临时标记

项目特有项由用户补充(历史事故点、团队红线)。
