# Write UI Test

## 定位

造弹药 skill:从需求 spec 派生 UI 功能测试的用例规格——agent 打开浏览器按它执行是 `/run-ui-test` 的事,本 skill 只做用例派生,不碰浏览器。

用例规格是**自然语言用例**,不是可执行脚本:执行期由 agent 读用例、通过 Playwright MCP 实时驱动浏览器。

## HARD-GATE

- **不碰浏览器** —— 本 skill 全程不启动/不驱动浏览器,不截图
- **不编造功能点** —— 用例必须来自需求 spec 的功能点/验收标准,spec 里没有的功能点不派生
- **用例清单未经用户确认不落盘**
- **不重新定义 spec 已锁定的业务规则** —— 发现 spec 与代码现实不符,标注【待确认】而不是自行解释

## Trigger

**使用此 skill 当**:
- 用户要求"写 UI 功能测试用例""生成界面功能测试""write-ui-test"
- 用户在 `/implementation` 或 `/subagent-implement` 完成编码后,要在界面上验一遍需求
- 接口测试跑完,用户要继续验 UI 层(推荐顺序,非硬前置)

**不要使用此 skill 当**:
- 跑测试 / 驱动浏览器 → 用 `/run-ui-test`
- 接口测试 → 用 `/write-api` / `/run-api-test`
- 视觉回归 / 跨浏览器兼容 / 性能测试 → 非本流程目标,不接
- 写 spec / plan → 用 `/write-spec` / `/write-plan`

## 与既有 skill 边界

| skill | 关系 | 说明 |
|---|---|---|
| `run-ui-test` | 下游 + 独立 | 消费本 skill 产的用例规格驱动浏览器;本 skill 不调它,执行由用户显式触发;同一份用例规格可被多次 run-ui-test 复用 |
| `write-api` / `run-api-test` | 平行 | 接口层测试;本流程推荐在其之后跑,但非硬前置 |
| `implementation` / `subagent-implement` | 上游 | 编码完成后触发本 skill |

## 依赖

- `docs/features/<feature-id>/<文件前缀>-spec.md` 存在(U1 派生输入)
- 目标项目编码已完成(推荐;纯前端需求同理)
- **不依赖** Playwright MCP(本 skill 不碰浏览器;执行期才需要,归 `/run-ui-test` 校验)

## feature-id 与文件前缀规则

复用既有规则(同 `/write-api` / `/run-api-test` / `/write-spec` 的算法):

- feature-id 格式:`YYYY-MM-DD-[业务ID-]<标题>`
- 文件前缀:有业务ID = `<业务ID>-<标题>`,无业务ID = `<标题>`
- 标题段允许中文、英文或混合,**不得**对中文做英文 slug 转换
- 文件名不得包含 `/`、`:`、`*`、`?`、`"`、`<`、`>`、`|`

产物文件名:

- 用例规格:`docs/features/<feature-id>/ui功能测试/<文件前缀>-ui功能测试-spec.md`

`ui功能测试/` 目录不存在则创建(与 plan/ 平级,按需求隔离;截图与报告同目录,由 `/run-ui-test` 产)。

## 工作流

按 U1-U3 顺序执行,格式规范见 `references/用例规格-format.md`。

### U1. 确认需求与功能点范围

- **前置**:用户指定需求(feature-id / spec / 需求名)
- **行为**:
  - 读 `docs/features/<feature-id>/<文件前缀>-spec.md`
  - 从功能描述/验收标准识别功能点(用户可显式给功能点清单,优先级最高)
- **功能点清单必须显示给用户确认**——避免 AI 理解偏差测错范围;用户确认后才进 U2
- **拿不到功能点**(spec 缺失 / 无验收标准可派生)→ 报错退出,不产空产物

### U2. 派生用例

- **前置**:U1 功能点清单已确认
- **行为**:按 `references/用例规格-format.md` 派生——**一功能点一用例**,每条含五要素:
  - 功能点名(与截图命名对应)
  - 操作步骤(自然语言,页面动线)
  - 预期表现(UI 上应看到什么——渲染/跳转/提示/输入回显;**不写 DB 断言**,本流程不验库)
  - 数据前提(需要什么存量数据;无则写「无」)
  - 登录账号(需要登录时记测试账号;拿不到留【待用户填写】;无需登录写「无需登录」)
- **入口 URL**:记入用例规格 §1 概览;拿不到留【需用户填写】
- **结果**:用例草稿

### U3. 确认落盘

- **前置**:U2 用例草稿就绪
- **行为**:用例清单(功能点名 + 步骤摘要 + 数据前提)显示给用户确认;确认后按格式规范落盘
- **用户校正**:增删用例、改步骤/预期/数据前提,以校正后为准
- **结果**:`docs/features/<feature-id>/ui功能测试/<文件前缀>-ui功能测试-spec.md` 落盘

## 工作流结束

U3 完成后 skill 结束。**不碰浏览器、不执行用例、不出报告**。

## 异常速查

| 场景 | 行为 |
|---|---|
| 需求 spec 缺失 | 报错退出,提示先跑 `/write-spec` |
| spec 无可派生功能点/验收标准 | 报错退出,不产空产物 |
| 登录账号拿不到 | 留【待用户填写】,继续派生其余内容 |
| 入口 URL 拿不到 | §1 概览留【需用户填写】,继续派生 |
| 同需求重复触发 | 覆盖该需求已有用例规格(从当前需求 spec 重新派生) |

## 质量检查

跑完后自检:
- 用例规格落盘 `ui功能测试/` 目录,四节齐全(概览/用例/数据前提清单/登录说明)
- 一功能点一用例,五要素齐全,无编造的功能点
- 预期表现只写 UI 表现,无 DB 断言
- 功能点清单与用例清单都有用户确认环节
- 没碰浏览器,没执行用例,没出报告

## 收尾

提示用户:
1. 用例规格位置(`<文件前缀>-ui功能测试-spec.md`)
2. 待用户填写项(登录账号 / 入口 URL,若有)
3. 下一步:**跑 `/run-ui-test` 驱动浏览器执行 + 截图 + 出报告**

不主动调用 `/run-ui-test` 或其他下游 skill。不写 knowledge 文件。不修改 spec / plan / 代码。
