# R6 UI 功能测试报告规范

## 产物

均在 `docs/features/<feature-id>/ui功能测试/`:

| 产物 | 文件名 | 谁产出 | 用途 |
|---|---|---|---|
| 结构化结果 | `<文件前缀>-ui功能测试结果.json` | agent 按本规范写 | 生成命令的输入;服务端读它在线展示用例表 |
| 测试报告 | `<文件前缀>-ui功能测试报告.xlsx` | `cgraphx report ui-test` 生成,**agent 不手写** | 给人看:汇总 + 逐用例 + 行内截图 |
| 截图 | `<功能点名>.png`(同功能点多张追加 `-2`/`-3`) | agent(R5) | 预期验证点留证,嵌入 xlsx |

三类文件名是对外约定,不得改动。存量的 `<文件前缀>-ui功能测试报告.md` 在重跑生成成功后由命令删除。

## 报告归属规则

报告永远归用户触发时指定的需求目录。同需求重复触发 → 覆盖,不增量合并。

## 结构化结果 JSON

服务端会直接读取,字段名、类型、枚举值即契约。

### 顶层

| 字段 | 类型 | 含义 |
|---|---|---|
| `schemaVersion` | 整数 | 固定 `1` |
| `featureId` | 字符串 | 所属需求的 feature-id |
| `executedAt` | 字符串 | 执行时间,ISO 8601 带时区偏移,如 `2026-10-15T14:30:00+08:00` |
| `mode` | 字符串 | `headed` / `headless` |
| `entryUrl` | 字符串 | 本次实际使用的入口 URL |
| `cases` | 数组 | 用例结果,至少 1 条,顺序即报告行序 |

### 用例(`cases[]`)

| 字段 | 类型 | 含义 |
|---|---|---|
| `index` | 整数 ≥1 | 与用例规格中的用例编号一致,不重复 |
| `featurePoint` | 字符串 | 功能点名 |
| `steps` | 字符串数组 | 操作步骤,每步一项,不带序号 |
| `expected` | 字符串数组 | 预期表现,每条一项 |
| `actual` | 字符串 | 实际表现;通过写「同预期」 |
| `result` | 字符串 | 六状态之一(见下) |
| `reachedStep` | 整数 或 `null` | 失败时执行到的步骤号;不适用为 `null` |
| `note` | 字符串 | 失败的疑似原因 / 跳过的原因 |
| `screenshots` | 字符串数组 | 截图路径,相对本 JSON 所在目录;可为空数组;只认 PNG / JPEG |

### 视结果必填

| `result` | `actual` | `note` |
|---|---|---|
| `通过` | 必填(通常「同预期」) | 可空 |
| `失败-预期不符` / `失败-元素缺失` | 必填,并填 `reachedStep` | 写疑似原因 |
| `失败-环境` / `失败-登录` | 必填 | 可空 |
| `跳过` | 可空 | 必填(跳过原因) |

用例规格确认清单里的**每条用例都要出现**:用户取消的、浏览器/MCP 崩溃未执行到的,记 `跳过`,`note` 写原因(如「执行中断,未执行」)。汇总数字不写进 JSON,由命令从 `cases` 计算。

## xlsx 报告(由命令生成)

`cgraphx report ui-test <JSON>` 校验通过后在同目录生成,结构固定:

- **「汇总」表**(打开即见):需求、执行时间、运行模式、入口 URL、总数、通过、失败、跳过、通过率、四种失败各自计数
- **「用例」表**:每用例一行,列为 序号 / 功能点 / 操作步骤 / 预期表现 / 实际表现 / 结果 / 执行到 / 备注 / 截图;结果底色 通过绿、失败红、跳过灰;截图嵌在本行,多张横排;表头冻结、可筛选

校验不过(字段缺失、结果不在六状态内、截图不存在或不是 PNG/JPEG)→ 退出码 2,stderr 逐条列出,不生成 xlsx。

## 状态枚举(与 SKILL.md 一致)

`通过` / `失败-预期不符` / `失败-元素缺失` / `失败-环境` / `失败-登录` / `跳过`

**前置暂停不记入报告,不算失败**(MCP 缺失/服务未就绪/数据未备齐时 skill 在 R0/R3 暂停,根本没进 R5)。
