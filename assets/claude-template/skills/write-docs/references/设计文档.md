# 设计文档

面向研发、技术负责人和后续维护者。发布后按需生成,写实际交付的行为。

## 素材来源

`docs/knowledge/`(用 `cgraphx docs find --concept=<名>` 找条目,用 `cgraphx docs show <path> --body` 读正文)加需求目录里的 spec、plan。两类都没有就不生成,提示先补素材。

## 章节

````markdown
# 设计文档: <需求名称>

> 产物: design_doc
> 依据: spec@<前 7 位>

## 架构总览

系统定位一句话,加架构图,加关键取舍表。

```
组件 A ──→ 组件 B ──→ 组件 C
```

| 关键取舍 | 选了 | 没选 | 为什么 |
|---|---|---|---|
| ... | ... | ... | ... |

## 核心模块

### 模块 A

职责描述、关键接口和依赖关系。

## 技术决策

### 决策标题

- **选择**:xxx
- **原因**:xxx
- **替代方案**:xxx

## 已知限制

| 限制 | 影响范围 | 应对措施 |
|---|---|---|
| 限制描述 | 影响范围 | 应对措施 |

## 扩展方向

1. **方向 A**:描述和优先级
2. **方向 B**:描述和优先级
````

## 架构总览范例

````markdown
## 架构总览

原来积分在下单流程里按 1% 直接算,没有独立的规则。现在发放规则抽成积分规则服务,下单和退款都经它写积分流水。

```
订单服务 ──付款成功──→ 积分规则服务 ──→ 积分流水表
  │                         ↑
  └────────退款─────────────┘
```

| 关键取舍 | 选了 | 没选 | 为什么 |
|---|---|---|---|
| 流水记下规则版本 | 每条流水存发放时的规则版本 | 退款时按当前规则倒推 | 规则会改,只有记下当时的版本才能按原比例扣回 |
````

## 合成规则

- 来源:所有事实性内容来自 knowledge 或 spec/plan,不编造;缺失如实标「待补充」或省略;可归纳但必须忠实原文。
- 结构重组:按知识传递组织,不照搬 knowledge 的标题或 spec/plan 的章节;相关信息进同一章节;重复信息合并只出现一次。
- 引用溯源:不引用 knowledge 文档路径,不引用 spec/plan 路径;引代码用相对路径,引外部文档用 URL 或标题。

## 语言与风格

正文中文,标识符、路径、专有名词保留英文;精炼直接,不确定的地方明确标注。

## 图表

优先 Mermaid;图表放相关章节、紧跟解释文字;md 用 mermaid 代码块,HTML 用 `<pre class="mermaid">`。

## 输出格式

- HTML:单文件自包含(内联 CSS,不依赖外部样式表),响应式,带可点击目录。
- Markdown:不加 YAML frontmatter,围栏代码块标语言。

## 设计文档 HTML 章节内容指南

| 章节 | 主来源 | 辅来源 | 改写方向 |
|------|------------------------|----------|----------|
| 概述 | spec 目标与范围 | knowledge Summary | 保留技术精确度,增加架构上下文 |
| 架构设计 | spec 系统行为/接口边界 | knowledge Summary + Read 原文 | 补充系统级架构图(文本框图)、数据流描述 |
| 核心模块 | plan 任务拆分 | knowledge Summary | 按模块分组,说明职责和交互关系 |
| 数据模型 | plan schema 任务 | spec 数据口径 + Read 原文 | 用表格展示节点类型、属性、关系 |
| 技术决策 | spec 不可留实现期决策 | knowledge Decisions + Read 原文 | 保留决策理由,补充替代方案对比 |
| API 参考 | spec 接口边界 | plan backend 任务 + Read 原文 | 按 endpoint 分组,包含请求/响应示例 |
| 性能特征 | knowledge Findings | Read 原文 | 用表格展示瓶颈和优化方向 |
| 已知限制 | spec 待确认项 | knowledge Findings/Risks + Read 原文 | 按严重程度排序,说明影响范围 |
| 扩展方向 | knowledge Outlook | Read 原文 | 按优先级排序,说明实现复杂度 |
| 运维指南 | knowledge Operations | Read 原文 | 按"部署 / 监控 / 排障"分组 |

## HTML 格式要点

- 所有 CSS 内联在 `<style>` 标签中,不引用外部样式表
- `<title>` 包含文档标题和项目名称
- 使用 `<nav class="toc">` 作为目录容器
- 每个章节使用 `<section id="章节锚点">` 包裹
- 章节锚点使用中文 ID(如 `id="架构设计"`)
- 重要提示或注意事项使用 `<div class="callout">` 样式
- 代码示例使用 `<pre><code>` 标签
- 表格使用 `<thead>` + `<tbody>` 结构
- 架构图使用 `<pre class="diagram">` 包裹 ASCII 文本框图
- 技术决策使用 `<div class="decision-block">` 结构,包含 `<dl>` 列表
- 已知限制使用表格,按严重程度降序排列
- 模块描述使用 `<section id="模块名">` + `<h3>` 子标题
- API 端点使用 `<span class="api-method">GET</span>` 标注 HTTP 方法
- 技术标签使用 `<span class="tag">标签名</span>` 样式
