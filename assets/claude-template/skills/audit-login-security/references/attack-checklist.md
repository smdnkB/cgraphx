# 认证攻击面清单

按「先绕过与越权,再凭据/会话,最后加固项」的顺序逐条核查。每条给 **命中 / 未命中 / 无法判定** 三态之一,未命中也要写依据。

符号:**查** = 读哪里、搜什么;**命中** = 判定条件;**修** = 修复方向(一句话,不改代码)。

---

## A. 认证绕过与逻辑缺陷(优先)

**A1 认证逻辑短路**
- 查:登录 service 从入参到签发 token 的**完整控制流**;密码比对的返回值是否真的参与判断;`catch` 分支是否兜底放行。
- 命中:校验失败仍走到签发;`if (user == null || !matches(pwd, user.pwd))` 条件写反;`try{check}catch{return ok}`;验证码分支 `if (captcha != null && !valid(captcha))`(不传就跳过校验);异常被吞后返回登录成功。
- 修:单一出口,先校验后签发,失败直接抛。

**A2 后门账号与万能密码**
- 查:硬编码凭据、magic code、`debug`/`test` 分支、`X-Debug` header、环境变量兜底密码、被注释掉的绕过代码;git 历史里删掉的判断。
- 命中:源码/SQL 里有固定用户名密码;`code.equals("888888")`;`if (isDev) return adminToken`;`if (request.getHeader("X-Admin") != null)`。
- 修:删除;测试账号只能来自测试环境配置。

**A3 未挂鉴权的接口**
- 查:拦截器 `excludePathPatterns`、网关白名单、`SecurityFilterChain` 的 `permitAll`、方法级注解缺失;把**路由表**与**放行表**逐条对比,不要只看放行表。
- 命中:业务接口(用户信息、导出、审批、管理后台)在放行列表里;放行规则用 `/**`、`/api/*`、`*.do` 过宽;新增接口默认不加鉴权。
- 修:白名单收敛为精确路径,默认拒绝。

**A4 验证码/短信绕过**
- 查:发送端与校验端成对看——code 的存储 key(手机号? session? 全局?)、有效期、是否一次性、失败计数、发送频控、有无万能码、响应体是否回带 code、校验是否只在前端。
- 命中:key 只用 code 不含手机号(任意手机号共用);校验通过后不删除(可复用);`000000`/`123456` 固定通过;发送接口响应含 code;失败不计数;图形验证码校验结果存在 cookie/前端。
- 修:绑定(手机号+场景+一次性 nonce),校验即失效,失败计数入库,发送端按手机号+IP 限频。

**A5 免密登录 / 注册即登录 / 记住我**
- 查:自动登录凭据从哪来;token 是否可预测;注册后是否验证邮箱/手机就自动登录并绑定身份。
- 命中:记住我 token = `hash(用户名)`;注册未验证邮箱即登录,且该邮箱可用于找回密码;免密登录只凭手机号 + 验证码但验证码可绕过。
- 修:自动登录用高熵一次性令牌,注册后先验证再建立会话。

**A6 参数污染与角色覆盖**
- 查:登录/注册入参是否用 `Map`/实体全量接收;是否 `BeanUtils.copyProperties`;`role`/`tenantId`/`status` 能否从入参覆盖;重复参数取第一个还是最后一个。
- 命中:`user.setRole(req.getRole())`;`user.setStatus(1)` 随注册入参;同一参数重复出现时前后端解析不一致。
- 修:入参白名单;角色、租户、状态一律服务端赋值。

**A7 JWT 不验签 / alg:none / 算法混淆**
- 查:解析 API 用的是「解码」还是「验签」;算法是否固定;是否忽略过期;密钥来源。
- 命中:Java `parseClaimsJwt`(非 `parseClaimsJws`)、`setSigningKey` 缺失或为常量;Node `jwt.decode()`、`jsonwebtoken.verify` 传 `{algorithms:['none']}` 或 `ignoreExpiration`;Python `jwt.decode(..., options={'verify_signature': False})`;RS256 公钥被当 HMAC secret(算法混淆);`kid` 拼进文件路径或 SQL;`jku`/`x5u` 可外联。
- 修:算法白名单 + 强制验签 + 密钥来自 KMS/环境变量,拒绝 `none`。

**A8 claims 信任 / 过期 / 撤销**
- 查:`role`/`tenantId`/`userId` 是否直接取自 token 且从不复核;`exp` 多长;登出/改密后服务端如何失效。
- 命中:token 内 `role` 决定权限且签名可控(密钥泄漏/校验缺失);`exp` 7 天且无 refresh 机制;无 `jti`/黑名单,登出只清前端。
- 修:短时 access + 轮换 refresh;敏感操作回库复核;无效化列表。

**A9 会话固定 / 可预测**
- 查:登录成功是否重建 session id;自定义 token 的生成源。
- 命中:登录前后 session id 不变;token = `userId + timestamp`、自增 ID、`Math.random`、`UUID` 以外的可预测源。
- 修:登录成功 rotate session;CSPRNG 生成。

**A10 token 出现在 URL / 日志 / Referer**
- 查:query 传 token;日志打印密码/token/完整 body;异常上报带敏感字段;前端 localStorage 存长期 token。
- 命中:`?token=`、`log.info("pwd={}", password)`、`console.log(response.data)` 含 token、Referer 外跳带 token。
- 修:token 走 header;日志脱敏;避免 localStorage 存长期凭据。

## B. 越权与登录后边界

**B1 水平越权(IDOR)**
- 查:按 id 取/改/删资源的接口,是否校验资源归属;路径参数、body 参数、批量接口都要看。
- 命中:`select * from order where id = ?` 且不校验 `userId`;A 的 token 能读写 B 的 id。
- 修:查询条件强制带当前主体,或取回后校验归属。

**B2 垂直越权**
- 查:角色校验是否存在、是否在服务端;是否用「前端隐藏菜单」当权限;角色是否取自 header/body。
- 命中:普通用户可调管理接口;`role` 从请求头读取;接口只校验「已登录」不校验「是谁」。
- 修:统一在服务端按会话主体做角色/权限判定。

**B3 租户/组织隔离**
- 查:多租户系统的 `tenantId`/`orgId` 来源;跨租户查询是否被过滤。
- 命中:tenantId 取自请求参数;SQL 无租户条件;登录时租户可任选且不校验用户归属。
- 修:租户从会话派生,数据层强制过滤。

**B4 改密 / 改绑 / 加白名单不验旧凭据**
- 查:改手机、改邮箱、改密码、绑定第三方、加登录白名单,是否要求旧密码或旧手机验证码。
- 命中:登录态即可直接改绑,无需原手机验证码;改密不校验旧密码;改绑后旧会话仍有效。
- 修:敏感变更二次验证,变更后失效全部会话。

**B5 批量 / 导出 / 列表越权**
- 查:导出、分页查询、批量操作是否按主体过滤;是否存在「查全部再前端过滤」。
- 命中:接口一次返回全量用户;导出不按权限裁剪列(手机号、身份证)。
- 修:服务端按权限裁剪数据与列。

## C. 凭据与找回

**C1 密码存储**
- 查:注册/改密/登录三处用的哈希算法与盐;有没有可逆加密;有没有明文列。
- 命中:明文、MD5/SHA1、无盐、`md5(pwd+salt)` 但盐固定、可逆加密、bcrypt cost < 10、自研哈希。
- 修:bcrypt/argon2id/scrypt + 每用户随机盐。

**C2 默认口令与初始密码**
- 查:初始密码规则(手机号后 6 位、`123456`)、是否强制首登修改、运维/后台默认账号。
- 命中:初始密码可推导;默认账号未改;`admin/123456` 存在。
- 修:随机初始密码 + 强制改密 + 首次登录绑定设备。

**C3 密码策略**
- 查:长度/复杂度/弱口令库/历史密码/有效期。
- 命中:允许 1 位密码;无弱口令黑名单;可立即改回旧密码。
- 修:最小长度 8+、弱口令库、历史 N 次不可复用。

**C4 用户名枚举**
- 查:登录失败文案/状态码/响应时间是否区分「用户不存在」与「密码错误」;注册、找回、邀请接口同样会枚举。
- 命中:「用户不存在」vs「密码错误」;`404` vs `401`;存在用户耗时明显更长(会跑哈希);注册接口「已注册」。
- 修:统一失败文案与状态码;不存在用户也跑一次假哈希;注册/找回走异步统一提示。

**C5 找回密码**
- 查:重置 token 的生成、有效期、一次性、绑定用户;重置链接发往哪个地址;能否指定账号。
- 命中:token 为时间戳/自增/用户 ID 编码;可复用、不过期;改邮箱后旧链接仍可用;接口可传任意 username 直接改密;密保问题可猜(生日/姓名)。
- 修:高熵一次性 token + 短有效期 + 绑定账号与邮箱,改密后失效。

**C6 凭据泄漏**
- 查:日志、异常上报、前端源码/打包产物、`.env`/配置文件是否入库、Swagger 示例、git 历史。
- 命中:仓库里有生产数据库密码;日志打印明文密码;前端硬编码第三方 secret;Swagger 默认账号。
- 修:轮换并移出仓库,日志脱敏。

## D. 会话与令牌

**D1 Cookie 属性**
- 查:登录态 cookie 的 `HttpOnly`/`Secure`/`SameSite`/`Domain`/`Path`/`Max-Age`。
- 命中:缺 HttpOnly(可被 XSS 读)、缺 Secure(可降级)、SameSite=None 且无 CSRF 防护、Domain 过宽。
- 修:HttpOnly + Secure + SameSite=Lax/Strict。

**D2 过期与超时**
- 查:会话/token 的绝对过期与空闲超时;服务端是否真校验。
- 命中:token 永不过期;session 30 天且无空闲超时;过期时间只在前端判断。
- 修:服务端强制过期,敏感系统加空闲超时。

**D3 Refresh token**
- 查:是否轮换、是否绑定设备/指纹、能否重复使用、存储位置。
- 命中:refresh 永久有效;旧 refresh 换新后仍可用(可重放);refresh 存 localStorage。
- 修:一次性轮换 + 重用即吊销整条链 + HttpOnly cookie。

**D4 多端会话与踢人**
- 查:并发登录策略;禁用/删除用户后在线会话是否仍有效。
- 命中:停用账号的 token 仍可用;管理员无法踢人;改密后其他端不掉线。
- 修:会话表 + 失效广播。

**D5 CSRF**
- 查:登录、改密、改绑、登出是否校验 CSRF token/Origin;禁用了框架默认防护的理由。
- 命中:`csrf().disable()` 且无替代;改密接口只靠 cookie 鉴权;GET 触发状态变更。
- 修:同步 token 或 SameSite + Origin 校验。

**D6 开放重定向**
- 查:`returnUrl`/`redirect`/`next`/`callback` 是否白名单。
- 命中:`//evil.com`、`https://evil.com`、`/\evil.com` 可跳;白名单用 `contains`/`startsWith` 判断。
- 修:精确白名单或只允许站内相对路径。

**D7 缓存**
- 查:登录响应、用户信息响应是否带 `Cache-Control: no-store`;CDN/反代是否缓存带身份的内容。
- 命中:登录响应可缓存;反代按 URL 缓存用户信息。
- 修:敏感响应 `no-store`,按身份区分缓存键。

## E. 爆破与限流

**E1 限流缺失或可绕**
- 查:是否有 IP 维度 + 账号维度双限流;限流键是否来自可伪造头(`X-Forwarded-For`、`X-Real-IP`);网关限流是否只针对主登录接口。
- 命中:无限流;只按 IP 限流(换 IP 即绕);只限账号(换账号即绕);`X-Forwarded-For` 直接作限流键;短信接口无限频(短信轰炸)。
- 修:账号 + IP + 设备指纹多维限流,代理场景只信任受控头。

**E2 锁定策略 DoS**
- 查:失败 N 次锁账号?锁多久?能否自解?
- 命中:锁账号不锁 IP,可锁死任意用户;锁定后无解锁途径;锁定时长递增无上限。
- 修:IP 为主 + 账号轻量退避,提供验证码/邮件解锁。

**E3 撞库与 MFA**
- 查:是否有设备指纹、风控、异地登录提醒、MFA;密码泄漏后的兜底。
- 命中:仅密码单因子;无异常登录检测;泄漏库命中后可长期登录。
- 修:MFA 或风险触发二次验证。

**E4 时序攻击**
- 查:密码/验证码比对是否用短路比较;用户不存在时是否直接返回。
- 命中:逐字节 `equals` 且错误提前返回(远程可利用需网络稳定,置信度按实际定)。
- 修:恒定时间比较 + 不存在用户也执行等价计算。

## F. 注入、传输与浏览器侧

**F1 SQL 注入**
- 查:登录、找回、用户搜索、排序字段是否拼接;MyBatis `${}`、`Statement` 拼接、`ORDER BY` 动态列。
- 命中:`where username='${u}'`;`${orderBy}`;`String.format` 拼 SQL。
- 修:参数化查询,动态列用白名单映射。

**F2 NoSQL / LDAP / 模板注入**
- 查:Mongo `$where`/对象入参(`{"$ne":null}`)、LDAP filter 拼接、SSTI 模板。
- 命中:登录查询直接吃 JSON 对象;`(&(uid=${u})(userPassword=${p}))` 拼接。
- 修:类型收窄 + 转义,禁止对象入参进入查询。

**F3 XSS 与错误回显**
- 查:登录页是否反射 `next`/`error`/`msg` 参数;错误页是否输出异常栈。
- 命中:`?error=<script>` 原样回显;异常栈含 SQL/路径/版本。
- 修:输出编码,统一错误页。

**F4 传输安全**
- 查:登录是否强制 HTTPS;密码是否走 query;是否有 HTTP 到 HTTPS 跳转;内部服务间是否明文。
- 命中:登录页可 HTTP 访问;`POST /login?password=`;跳转可被降级。
- 修:HSTS + 全站 HTTPS + 禁止 query 传凭据。

**F5 错误信息**
- 查:登录失败是否区分「账号不存在/密码错误/账号锁定/账号停用」;是否回带堆栈。
- 命中:四种状态文案不同(配合 C4 直接枚举);堆栈回显。
- 修:对外统一文案,内部日志分级。

## G. 第三方登录与 SSO

**G1 OAuth state**
- 查:授权请求是否带 state、回调是否校验、state 是否绑定会话。
- 命中:无 state;state 固定/可预测;回调不校验 → 登录 CSRF 绑定攻击者账号(账号劫持)。
- 修:随机 state 存会话并一次性校验。

**G2 redirect_uri 校验**
- 查:是否精确匹配;是否允许通配/子路径/参数追加。
- 命中:`redirect_uri=https://evil.com` 可用;`@evil.com`、路径穿越绕过;code 可被换到任意域。
- 修:注册制精确匹配。

**G3 社交登录按邮箱自动合并**
- 查:第三方返回的 email 是否已验证;是否按 email 合并到已有本地账号。
- 命中:未验证邮箱即合并 → 攻击者用受害者邮箱注册第三方账号 → 接管本地账号。
- 修:仅合并已验证邮箱,否则要求二次验证(密码/短信)。

**G4 SAML / OIDC 校验**
- 查:签名是否强制校验;断言是否校验 audience/recipient/时间窗;是否防 XML 签名包装。
- 命中:`validateSignature=false`;不校验 audience;接受未签名断言。
- 修:强制签名 + 全字段校验,用成熟库。

**G5 扫码登录**
- 查:二维码内容是否含敏感信息;轮询接口是否裸返回 token;二维码是否可被替换/复用。
- 命中:poll 返回 `token` 无绑定校验;二维码 scene 可预测;扫码后不确认即登录。
- 修:一次性 scene + 绑定会话 + 短有效期。

## H. 终结与审计

**H1 登出不失效**
- 查:登出接口做了什么;服务端是否有吊销动作。
- 命中:只清前端 localStorage/cookie;JWT 登出后仍可重放直到过期。
- 修:服务端黑名单/版本号 + 短 token。

**H2 改密 / 停用 / 删除后的会话**
- 查:改密、停用、删除用户、改绑手机后,旧会话是否失效。
- 命中:改密后旧 token 仍可用;停用用户仍能调接口。
- 修:会话版本号随用户状态变更递增。

**H3 登录审计与告警**
- 查:成功/失败登录是否记录(账号、IP、UA、时间、结果);是否有异常登录告警;日志保留。
- 命中:无失败日志;日志无来源 IP;日志可被普通用户删除。
- 修:结构化审计日志 + 异常登录告警(属风险项,不单列高危)。
