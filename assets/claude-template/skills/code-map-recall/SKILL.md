# 代码地图召回 (Code Map Recall)

## 定位

- **底图,不是事实**:新鲜的视图可直接当底图;过期的视图只作线索,结论要读代码确认。
- **只读**:召回阶段不重生成视图——plan 阶段的理解是"计划",混进地图会污染现状。缺视图 / 过期由实现收尾的 `code-map-write` 提示补上。

## 流程

1. **收线索**:本次涉及的概念(knowledge-recall 命中 / spec 术语,用知识库规范名)+ 预计改动的文件或模块(spec 的接口与页面、plan 草稿)。
2. **匹配视图**:`docs/code-map/` 不存在 → 直接返回"无代码地图"。存在 → 读各视图 frontmatter(`for f in $(find docs/code-map -name "*.md"); do echo "== $f"; head -25 "$f"; done`):
   - `concepts` 与线索概念有交集 → 命中;
   - `related_code` 与预计改动文件有交集 → 命中;
   - 涉及跨服务/外部系统 → `系统交互*.md` 命中。
3. **判新鲜度**:对每个命中视图跑

```bash
git diff --name-only <source_commit> HEAD -- <related_code...>   # 非空 → 过期,列出变了的文件
git status --porcelain -- <related_code...>                      # 非空 → 含未提交改动
```

4. **返回**:

| 视图 | 命中原因 | 状态 | 路径 |
|---|---|---|---|
| 开发时间线记录 | concepts: 开发时间线 | 新鲜 | `docs/code-map/flows/开发时间线记录.md` |
| 系统交互 | 涉及外部 HTTP 查询服务 | 过期:`src/core/dbquery/drivers/http.ts` 已改 | `docs/code-map/系统交互.md` |

## 怎么用召回结果

| 状态 | 设计预览怎么画 |
|---|---|
| 新鲜 | 架构图的灰色邻居、主流程的已有部分直接取自视图,再叠加本次新增/修改 |
| 过期 | 视图作线索;变了的文件对应的部分读代码确认后再画 |
| 无视图 | 读代码画;实现收尾时提示 `code-map-write` 新建 |

## 红线(绝对不能做)

1. ❌ **不在召回时生成或刷新视图**。
2. ❌ **不把过期视图当事实**——变了的部分必须读代码确认。
