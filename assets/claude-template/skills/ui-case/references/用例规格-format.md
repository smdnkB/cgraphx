# U2/U3 UI 功能测试用例规格格式规范

## 结构(必须完整)

用例规格文档 `<文件前缀>-ui功能测试-spec.md` 开头一节「覆盖范围」,后面四节,顺序固定。

### 开头:标题、头部和覆盖范围

```markdown
# UI 功能测试用例规格: 客户管理

> 产物: ui_test_spec
> 依据: spec@3f9a1c2

## 覆盖范围

原来客户资料只能在后台数据库里改;这次新增客户管理页面,测 2 个功能点、2 条用例:新建客户、编辑客户;不测导出(spec 没要求)。
```

### §1. 概览

```markdown
## 1. 概览

| 项 | 值 |
|---|---|
| 来源需求 | <文件前缀>-spec.md |
| 入口 URL | http://127.0.0.1:5173/admin |
| 需要登录 | 是 |

截图约定:截图存本目录,按功能点命名(`<功能点名>.png`,同功能点多张追加 `-2`/`-3`)。
```

- 入口 URL 拿不到 → 填【需用户填写】,`/ui-run` 执行前会向用户要
- 入口 URL 是执行默认值,用户触发 `/ui-run` 时可覆盖

### §2. 用例

**一功能点一小节**,五要素齐全。最好案例:

```markdown
## 2. 用例

### 用例 1:新建客户

- **功能点名**:新建客户
- **操作步骤**:
  1. 左侧菜单点「客户管理」进入列表页
  2. 点右上角「新建」按钮,弹出新建表单
  3. 填写:客户名称「测试客户-0825」、联系电话「13800138000」、所属行业选「制造业」
  4. 点「保存」
- **预期表现**:
  - 表单校验通过,无红色错误提示
  - 提示「保存成功」
  - 返回列表页,第一行出现「测试客户-0825」
- **数据前提**:无(本用例自行创建)
- **登录账号**:见 §4

### 用例 2:编辑客户

- **功能点名**:编辑客户
- **操作步骤**:
  1. 客户列表页找到「华东贸易」
  2. 点该行「编辑」,表单回填现有值
  3. 把联系电话改为「13900139000」,点「保存」
- **预期表现**:
  - 列表里有正常客户「华东贸易」,没有已停用的「华北物流」(K1:停用的客户不算)
  - 提示「保存成功」;列表中「华东贸易」的联系电话显示为「13900139000」
- **数据前提**:存在客户「华东贸易」、已停用的客户「华北物流」(见 §3)
- **登录账号**:见 §4
```

要求:

- 操作步骤写**页面动线**(点什么、填什么),不写接口/代码细节
- 预期表现只写 **UI 上可观察的**(渲染/跳转/提示/回显),**不写 DB 断言**——本流程不验库,数据层归接口测试
- 用到业务口径的用例,预期表现把「算 / 不算」两边都写上并标 K 编号(如用例 2 的「华北物流」)
- 功能点名同时是截图文件名,不得含 `/`、`:`、`*`、`?`、`"`、`<`、`>`、`|`

### §3. 数据前提清单

汇总各用例的数据前提,供 `/ui-run` 执行前人工核对备齐:

```markdown
## 3. 数据前提清单

| 用例 | 数据前提 | 状态 |
|---|---|---|
| 用例 1:新建客户 | 无 | - |
| 用例 2:编辑客户 | 存在客户「华东贸易」、已停用的客户「华北物流」 | 待人工备 |
```

- 数据前提一律**人工准备**(本流程不自动造数据);「状态」列初始全填「待人工备」
- 用例自行创建的(如用例 1)填「无」

### §4. 登录说明

```markdown
## 4. 登录说明

- 登录页:`/login`(入口 URL 跳转后第一个页面)
- 测试账号:`admin` / 【待用户填写】
- 登录动线:输入账号密码 → 点「登录」→ 跳转首页

若登录遇到验证码/SSO,`/ui-run` 会暂停请人工介入。
```

- 账号拿不到 → 密码留【待用户填写】
- 无需登录的应用写「无需登录」并省略登录动线
