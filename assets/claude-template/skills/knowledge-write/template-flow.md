# 业务流程主条目模板

适用的 `document_type` 值：

```text
business-flow
```

流程主条目记录一个**业务流程**（礼包新装、订单退款、准三层续订）：触发、参与者、主干状态流转、异常分支与跨文件约束。与实体主条目（business-entity）互补——实体给定位，流程给链路；两者靠 `concepts` 引用连接。同样只存代码给不了的东西：跨文件才看得出的规则、状态迁移的边界、文件级代码入口。逐步时序与代码复述一律不写（重构幸存测试：重构后仍成立的才写）。

## 完整模板

```markdown
---
title: 礼包新装流程
document_type: business-flow
domains:
  - 商品
concepts:
  - 礼包                  # 所涉实体：必须与实体条目 concepts 里的规范名严格一致（反查锚点）
  - 订单
aliases:
  - 新装
  - 礼包开通               # 黑话/别名：同时写进 Summary 一句话，才能被 find --q 命中
tags:
  - so-service             # 服务/模块信息放 tags，不放 domains
status: active             # 只从一两个视角抽出、尚未补全时用 draft
source_type: work_context
owners:
  - platform
related_code:
  - so-service/so-busi/src/main/java/.../PkgInstallScene.java   # 文件级入口，不写行号
related_documents:
  - docs/knowledge/礼包.md
created: 2026-07-31
updated: 2026-07-31
---

# 礼包新装流程

## Summary

一句话定义 + 系统定位。黑话别名在此各出现一次（如"又称新装/礼包开通"）。
与邻近流程的边界一句话说清（如"新装止于首单生效，续订归礼包续订流程"）。
不写逐步时序、不复述代码。

## 触发与前置

触发事件（用户下单 / 上游回调 / 定时任务）与前置条件（已存在的实体与状态）。

## 参与者与系统

涉及的角色、系统、服务——文件级列举，不展开实现。

## 主链路与状态流转

主干步骤与关键状态迁移（如 待支付 → 生效 → 完成）。
只给状态名与文件级入口指针，不写行号、不复述每一步的代码逻辑。

## 异常分支

失败 / 回滚 / 补偿路径：什么情况触发、回到哪个状态。

## 关键约束与陷阱

只写**跨文件才看得出的**业务规则、隐式约束、历史地雷。
示例：新装校验先于库存扣减；准三层对礼包成员的校验顺序。

## 代码入口

流程入口类、关键 Scene/Atom/Handler —— 文件级路径，agent 从这里进去读真实逻辑。
不写行号（重构即失效）、不复述代码逻辑。

## Open Questions

尚未确认的分支、边界未清的相邻流程。用 status: draft 配合此章节。
```

## 各章节填写要点

| 章节 | 用途 | 注意事项 |
|------|------|----------|
| Summary | 定义 + 黑话 + 边界 | 唯一进索引的章节（标题必须正好 `## Summary`，两个 # 一个空格）；黑话要在此出现才能被关键词搜到；不写逐步时序 |
| 触发与前置 | 触发事件与前置条件 | 写清由什么启动、依赖哪些已存在的实体/状态 |
| 参与者与系统 | 角色/系统/服务 | 文件级列举，不展开实现细节 |
| 主链路与状态流转 | 主干步骤与状态迁移 | 给状态名与文件级入口；**绝不写行号、不复述每步代码** |
| 异常分支 | 失败/回滚/补偿 | 写触发条件与回到的状态，不复述异常处理代码 |
| 关键约束与陷阱 | 跨文件规则与隐式约束 | 单个文件能读出的东西不写（代码是事实来源） |
| 代码入口 | agent 读代码的起点 | 文件级路径；**绝不写行号**；不解释代码做了什么 |
| Open Questions | 未确认分支 | 与已确认内容分开跟踪；配合 status: draft |

## 不应写入流程条目的内容

| 不写 | 理由 |
|------|------|
| 行号（`Foo.java:372`） | 一次重构全部失效 |
| 逐步代码逻辑复述 | 代码是事实来源，agent 应从代码入口去读 |
| 全量分支 / 全量状态清单 | 只写主干与关键分支，全量让 agent 读代码 |
| "参与业务"全量清单 | 由 `find --concept=<实体>` 反查派生，手动维护必陈旧 |
| 可从代码直接读出的字段/参数 | 索引层只给指针，不抄内容 |
