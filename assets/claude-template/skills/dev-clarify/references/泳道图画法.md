# 泳道图画法

mermaid 仿 PlantUML 活动图。dev-clarify 的功能方案讨论稿和 doc-delivery 的设计文档共用这套画法;完整的图见同目录 `功能方案-讨论稿范例.md` 和 doc-delivery 的 `references/设计文档.md`。

- 每张图第一行照抄,画出来是直角连线、灰底黑框、泳道白底:

  ```text
  %%{init: {"theme": "base", "themeVariables": {"primaryColor": "#F1F1F1", "primaryBorderColor": "#181818", "primaryTextColor": "#000000", "lineColor": "#181818", "clusterBkg": "#FFFFFF", "clusterBorder": "#181818", "edgeLabelBackground": "#FFFFFF"}, "flowchart": {"curve": "stepAfter"}}}%%
  ```

- 泳道用 `subgraph`,从右往左写:最右边的泳道先写,用户或调用方最后写,才会排在最左边。
- 起点 `s((" ")):::start`,步骤 `( )`,判断 `{{ }}`,结果 `([ ])`;这次新增或改动的步骤加 `:::changed` 标黄。图末尾按用到的写 `classDef start fill:#181818`、`classDef changed fill:#FFF3B0`。
- 用户或调用方的泳道要有起点也要有结果,泳道才会左右并排;每个分支各接一个结果,不要汇到同一个点。
- 讲一个环节或一个功能点怎么走的图,正常走通的路径用 `linkStyle` 标绿:序号按连线在源码里出现的顺序从 0 数,`a --> b --> c` 算两条;改了连线要跟着改序号。
- 一张图不超过 15 个框,超了就拆。
- 图里只写业务语言,不写类名、方法名、行号和 SQL。
- 框里的文字不用半角括号、分号和引号,换行用 `<br/>`。
