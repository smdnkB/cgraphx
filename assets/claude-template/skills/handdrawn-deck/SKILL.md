# 手绘系列演示编排器 · SKILL

> 哲学：**编排与执行分离。** 本 skill 是“导演”：想清楚讲什么、分几页、每页什么结构；
> 每一页的“摄影”交给 `handdrawn-sketch-engine`（引擎、动画、图标库、纸墨气质全是它的）。
> 导演不画分镜之外的东西，摄影不改剧本——所以系列图天然统一，翻页像翻一本书。

## 0. skill 结构与分工

```
.claude/skills/handdrawn-deck/
├── SKILL.md（本文档）        编排流程 / 故事线确认 / 组装规范 / 验收
└── references/
    └── deck-template.html    放映壳模板（iframe 堆叠 + 手绘 HUD + 键盘导航）
```

| 角色 | skill | 管什么 | 不管什么 |
|---|---|---|---|
| 导演 | **handdrawn-deck（本）** | 目标、叙事、拆页、每页内容与布局类型、组装、通读节奏 | 具体坐标、动画时刻表、图标画法 |
| 摄影 | handdrawn-sketch-engine | 单页渲染执行、视觉 DNA、图标库治理、单页验收 | 页与页之间的关系 |

委托时引用的引擎资产（路径相对仓库根）：
- `.claude/skills/handdrawn-sketch-engine/references/reference-render.html` —— 金样张（每页的质量基线）
- `.claude/skills/handdrawn-sketch-engine/assets/icon-library.js` —— 图标唯一来源（全 deck 共享同一套图标）

## 1. 编排工作流（六步 · 顺序不可乱）

**① 澄清目标**：先弄清三件事——**讲给谁**（决定深浅与黑话密度）、**讲完要干嘛**
（知晓 / 认同 / 行动，决定收尾页形态）、**素材从哪来**（用户口述 / 现有文档页面 / 参考图）。
任一不明 → 主动问（一次问完，别挤牙膏）。

**② 叙事拆页**：把内容压成一条**翻页动线**（抛出→展开→收束），切成 N 页。
页数预算：汇报 4–8 页为宜；每页只讲**一个**信息结构（超过 6 个节点 → 拆页，不塞）。

**③ 故事线确认（硬步骤：未确认不得画任何一页）**：向用户输出「页面计划」——
每页的 标题 / 一句话内容 / 布局类型 / 图标预案，外加整 deck 的翻页节奏与页数。
格式见 §2。用户确认或调整后才锁定。

**④ 逐页执行（委托引擎）**：对每一页，按 handdrawn-sketch-engine 的流程执行，
但**布局确认被故事线确认吸收，不再逐页问**：
- 引擎 §4 步骤 0 照做：对齐金样张 + 查图标库（按 `META.use` 匹配）；
- 引擎 §4 步骤 1 **跳过**（结构已在故事线里锁定）；
- 引擎 §4 步骤 2–3 照做：写 `buildScene` → 按引擎验收清单自检；
- 引擎 §5 图标治理照走：复用 → 草稿 → 稳定后沉淀（全 deck 共享一个库，
  前一页的草稿沉淀后，后一页立刻能复用）。

**⑤ 组装 deck**：交付目录 `docs/handdrawn-deck-<topic>/`，含 `deck.html` + `p1-*.html … pN-*.html`；
复制 `references/deck-template.html` → 只改脚本顶部 `PAGES` 数组（`{file, title}`，顺序即放映顺序）。

**⑥ 通读自检**：从头到尾“放”一遍（§4 验收），重点是**页间**问题：节奏、重复、断裂、漂移。

## 2. 页面计划格式（故事线确认单范本）

```
系列：<名称>（N 页 · 讲给 <受众> · 目标 <知晓/认同/行动>）
翻页动线：抛出 → 展开 → 收束

- P1 封面 「<标题>」              布局：标题大字 + 涂鸦散点 + 系列角标
- P2 问题页 「<标题>」            布局：场景式（<左什么 / 右什么>）· 内容点 ×N
- P3 解法页 「<标题>」            布局：闭环环形（四阶段 <…>）· 内容点 ×N
- P4 收益页 「<标题>」            布局：三栏并列（<栏1/栏2/栏3>）· 内容点 ×N
- P5 收尾页 「<标题>」            布局：行动号召 + 回顾钩子

布局多样性：本页计划覆盖 <X> 种布局，相邻页不重复 ✓
图标预案：复用 ×<n>（<列出>）· 预计草稿 ×<m>（<列出，标注哪页产出>）
每页各自独立可放映（单文件交付不变）
```

> 与引擎的「布局确认单」同构但更高一层：锁的是**页与页之间的关系**，
> 页内细节（坐标、文案逐字、动画节奏）仍归引擎执行阶段。

## 3. 布局词表（系列沉淀 · 可扩展）

| 布局类型 | 适合讲什么 | 已验证案例 |
|---|---|---|
| 三栏并列 | 3 个平行卖点 / 优势 / 原则 | 金样张 reference-render.html |
| 放射式 | 一个核心 + 5–7 个发散点（痛点、要素） | handdrawn-ai-pains.html |
| 闭环环形 | 流程循环、飞轮、自增强机制 | handdrawn-knowledge-loop.html |
| 场景式 | 讲故事、摆冲突（左困境 / 右发问） | handdrawn-data-model-pain.html |
| 横向流水线 | 阶段推进、管线（3–5 段，≠ 并列） | 待首例 |
| 竖向时间轴 | 历程、版本演进 | 待首例 |
| 对比分栏 | 前后 / 有无 / 对错 | 待首例 |

**多样性规则**：
- 相邻两页**不得同布局**（翻页疲劳 = PPT 死因）；
- ≥4 页的 deck 至少覆盖 3 种布局；
- 封面 / 收尾页允许轻量布局（标题 + 涂鸦），不算重复；
- 新布局首次使用后，回写本词表（标注首例文件）。

## 4. deck 级验收清单

**故事线**：
- [ ] 故事线确认单已获用户确认，才进入执行。
- [ ] 每页只承载一个信息结构；无“塞不下”的页。
- [ ] 翻页动线成立：单看任意一页能懂大概，连起来看有递进。

**页间一致性**：
- [ ] 相邻页布局不重复；全 deck 覆盖 ≥3 种布局（≥4 页时）。
- [ ] 同一概念跨页用同一图标（全 deck 共享 icon-library）。
- [ ] 标题系列感（同一话术风格 / 同一问句体等，刻意设计过）。
- [ ] 六旋钮全 deck 一致（同一模板复制，天然满足）。

**放映**：
- [ ] `PAGES` 数组完整，顺序即叙事顺序；页名徽章逐页正确。
- [ ] ←/→/空格/Home/End/F 全部可用；圆点页码可点。
- [ ] 翻回已看过的页，逐笔绘制重播（模板 `handdrawn:show` 消息生效）。
- [ ] 每页单独打开仍是完整活页（独立交付物不被破坏）。

**页内**：逐页执行 handdrawn-sketch-engine §9 验收清单。

## 5. deck 组装规范

- 交付目录：`docs/handdrawn-deck-<topic>/`，内含 `deck.html` 与 `p1-<slug>.html … pN-<slug>.html`
  （序号前缀保证文件系统排序 = 放映顺序）。
- 页面由引擎 skill 生成后**原样搬入**目录，不改内容；壳通过 `?deck=1` 让页面隐藏自带控制条。
- `PAGES` 数组是唯一需要手填的地方：`{file:'p1-cover.html', title:'封面 · …'}`。
- 放映：本地起任意静态服务打开 `deck.html`（iframe 读同目录文件；`file://` 直开部分浏览器受限）。
- 深链：`deck.html#3` 直达第 3 页，可用于“从第 N 页开始讲”。

## 6. 反模式

- ❌ 跳过故事线确认，想到哪页画哪页 → 系列必然散。
- ❌ 全 deck 一个布局复制 N 份 → 翻页疲劳，不如做长图。
- ❌ 一页塞七八个节点 → 手绘不是文档，塞不下就拆页。
- ❌ 页内容离开上下文就看不懂 → 每页必须独立成片。
- ❌ 每页重新问一遍布局 → 故事线确认已锁结构，逐页执行不重问。
- ❌ 跨页同一概念换图标 → 系列感塌方；图标全 deck 共享一个库。
- ❌ 壳里魔改页面内容 → 壳只管翻页，页面是独立交付物。

## 7. 引擎协作备忘（写给执行阶段的自己）

- **壳不碰几何**：iframe 铺满视口，页面大小 100% 由内容页自己决定（引擎模板在 deck
  模式下自动解除 1180px 宽度上限、按视口自适应）；壳只管编排、切换、HUD 贴纸。
- **壳接管播放**：deck 模式下页内控制条隐藏，播放权归壳——HUD 的 ▶ 重放本页
  （R 键同效）+ 全局抖动滑块（`handdrawn:rough` 实时广播到所有已加载页；
  新页加载时自动对齐壳当前值，值相同则不打断首播动画）。
- 引擎模板原生支持 deck 模式：URL 带 `?deck=1` 时隐藏页面自带控制条；
  页面收到 `{type:'handdrawn:show'}` 消息即重播逐笔绘制。
- 键盘穿透：壳会给每个加载完的 iframe `contentWindow` 挂同一套翻页键监听——
  用户点进页面内容（焦点落进 iframe）后，方向键依然翻页。
- 历史页面（模板增强前生成的）装进 deck 也能放映，只是翻回时不重播动画、
  宽度仍按页面自己的设计（如自带 1180px 上限）——可接受，勿为此重写成品页。
