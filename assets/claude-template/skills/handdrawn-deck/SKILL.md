# 手绘系列演示编排器 · SKILL（讲稿先行版）

> 哲学一：**讲稿先行，画面是讲稿的投影。** 逐字稿是唯一生产轴——框架确认锁「讲什么」，
> 逐字稿确认锁「怎么讲」，拆页与绘制都是讲稿的派生。倒过来（先画页再补稿）必然漂移到
> 「三份都在，没一份能信」。
>
> 哲学二：**编排与执行分离。** 本 skill 是“导演”：想清楚讲什么、怎么讲、分几页、
> 每段画什么；每一页的“摄影”交给 `handdrawn-sketch-engine`（引擎、动画、图标库、
> 纸墨气质全是它的）。导演不画分镜之外的东西，摄影不改剧本——所以系列图天然统一。

## 0. skill 结构与分工

```
.claude/skills/handdrawn-deck/
├── SKILL.md（本文档）        流程 / 确认单格式 / 组装规范 / 验收
└── references/
    ├── deck-template.html    放映壳模板（深色放映台 + 16:9 画幅 + 演讲者视图 + cue 导播 + 键盘导航）
    ├── gen-script-md.cjs     逐字稿 → 可读讲稿 .md 的生成器（口播逐字插值，零漂移）
    └── seg.cjs               呼吸段切分器（从壳提取 segmentScript + 自检 + 切口播 + 查 stages 行数）
```

| 角色 | skill | 管什么 | 不管什么 |
|---|---|---|---|
| 导演 | **handdrawn-deck（本）** | 草稿打磨、框架确认、逐字稿、拆页与单元规划、组装、通读节奏 | 具体坐标、动画时刻表、图标画法 |
| 摄影 | handdrawn-sketch-engine | 单页渲染执行、视觉 DNA、图标库治理、单页验收 | 页与页之间的关系、讲稿 |

委托时引用的引擎资产（路径相对仓库根）：
- `.claude/skills/handdrawn-sketch-engine/references/reference-render.html` —— 金样张（每页的质量基线）
- `.claude/skills/handdrawn-sketch-engine/assets/icon-library.js` —— 图标唯一来源（全 deck 共享同一套图标）

## 1. 编排工作流（讲稿先行 · 七步 · 顺序不可乱）

**① 澄清 / 打磨（两种入口）**：
- **空手来**（用户只说主题 / 模糊想法）：对话式澄清，一次问完——**讲给谁**
  （决定深浅与黑话密度）、**讲完要干嘛**（知晓 / 认同 / 行动，决定收尾形态）、
  **素材从哪来**（用户口述 / 现有文档页面 / 参考图）、**预计多长**。
- **带稿来**（用户给了演讲草稿）：**打磨**——理顺结构（抛出→展开→收束）、
  补论证链的缺口、对齐口径、砍冗余，**保留用户的语气和素材**（做结构手术与补漏，
  不代笔换血）。产出打磨后的草稿给用户过目。

两个入口汇合于同一产物：**内容定稿**（讲什么已定，但还没拆页、没写逐字稿）。

**② 讲稿框架确认（硬步骤：未确认不得写逐字稿）**：输出「框架确认单」（格式见 §2）——
中心思想（一句话）、论证链（每步推理）、段落骨架（每段角色 + 关键信息 + 素材）、
预计时长，外加**声明的偏离**（哪些刻意不讲、为什么——给用户核对偏离的关键项）。
这一步的核心问题只有一个：**“我有没有理解错你的意图？哪里偏了？”**——
这是消息保真度核对，不是布局确认。用户确认或调整后才锁定。

**③ 逐字稿（硬步骤：未确认不得画任何一页）**：按段落骨架逐段写口播——
产出 **notes.js**（契约见 §5：每页 `{no, kind, title, sec, 口播逐字照读稿, cue 提示}`），
再用 `references/gen-script-md.cjs` 渲染成可读讲稿 .md，两份一起交用户确认
（通读一遍：语气对不对、意思偏没偏、时长合不合理）。
**篇幅自检**：口播字数 ≈ `sec × 4`（按 240 字/分钟语速），明显超了就减字或拆段。
**文稿口径是口语**：短句、有钩子、讲例子——这是要照读出来的稿子，不是文档。
用户确认 → 讲稿锁定；此后改动走「改 notes.js → 重渲染讲稿 .md」单一数据源流程。
> 纯放映 deck（确实不需要讲）可简化：③ 只写每页一句话要点（无口播、无 stages，
> 页面整幅播放）；但**汇报 / 宣讲 / 培训**类必须走全流程。

**④ 拆页 + 单元规划（讲稿 → 分镜）**：
- **拆页**：把段落骨架切成 N 页——每页只承载**一个**信息结构（超过 6 个节点 → 拆页，
  不塞）；**页边界落在讲稿的自然节拍上**（一页可对应多个呼吸段，一段不要跨两页）。
  页数预算：汇报 4–8 页为宜。
- **呼吸段**：把 `references/seg.cjs` 拷进 deck 目录跑（从同目录 `deck.html` 提取壳的
  `segmentScript`——提取源自检断言后才切，输出每页段数 + stages 行数核对），**禁止目测手切**。
  口播断句用 `。！？；`（恒切段）；>120 字无句末点的长段落才退按半角逗号/顿号切——
  **全角逗号「，」不是退避分隔符**，别指望它切段。
- **单元规划**：把该页的视觉元素按旁白节拍拆成**单元**（unit = 一组「讲到才画」的
  内容，起叙事名如 `g-db`、`g-ex1-frame`），逐段写进 **stages 表**
  （一段一行，`draw` = 该段新增单元；契约见 §5）。讲到什么画什么——
  旁白没讲到的元素不许提前画。
- 产出「页面计划」（格式见 §2）：每页的 标题 / 关键信息 / 对应段落与呼吸段 /
  布局类型 / 单元规划 / 图标预案，并**布局多样性自检**：相邻两页不得同布局；
  ≥4 页至少覆盖 3 种布局（词表见 §3）。页面计划是内部设计稿——框架与讲稿
  已确认，布局是 agent 的专业活，**不再逐页问用户**。

**⑤ 逐页执行（委托引擎）**：对每一页，按 handdrawn-sketch-engine 的流程执行，
但委托输入**必须带上该页的呼吸段与单元规划**：
- 引擎 §4 步骤 0 照做：对齐金样张 + 查图标库（按 `META.use` 匹配）；
- 引擎 §4 步骤 1 **跳过**（结构已在页面计划里锁定）；
- 引擎 §4 步骤 2–3 照做：写 `buildScene`，**单元按单元规划分组**
  （讲到哪段画哪组——这是渐进绘制的灵魂，单元命名与 stages 表逐字一致）；
  按引擎验收清单自检；
- 引擎 §5 图标治理照走：复用 → 草稿 → 稳定后沉淀（全 deck 共享一个库，
  前一页的草稿沉淀后，后一页立刻能复用）。

**⑥ 组装 deck**：交付目录 `docs/handdrawn-deck/<topic>/`（全部 deck 收在这一个父目录下，
不在 docs/ 根平铺 `handdrawn-deck-*` 兄弟目录）：
- `notes.js`（③ 已产出；④ 已补 stages 表）；
- 复制 `references/deck-template.html` → `deck.html`，只填脚本顶部 `PAGES` 数组
  （`{file, title, no}`，顺序即放映顺序）；**改过页 / 讲稿就 bump 壳顶部的 `V`**
  （并同步 `notes.js?v=`），强制浏览器重拉、不留旧缓存；
- 复制 `references/gen-script-md.cjs` 进目录跑一遍 → 逐页讲稿 .md（脱稿排练 / 打印）；
- 壳是**深色放映台**（幻灯片置于 16:9 投影画幅内）；有 notes.js 自动开演讲者视图 +
  cue 导播台（呼吸段 = cue 键：点段 = 页面演到那，`↑↓` 逐段推进，`←→` 翻页）。

**⑦ 通读自检**：在 cue 导播台里从头到尾“放”一遍（§4 验收）——**旁白到哪、笔到哪**；
用 `↑↓` 逐段模拟真实演讲走一遍，重点查**页间**问题：节奏、重复、断裂、漂移。

## 2. 确认单与页面计划格式

**框架确认单范本（② 的输出 · 用户核对偏离就看这张）**：

```
系列：<名称> · 讲给 <受众> · 目标 <知晓/认同/行动> · 预计 <N> 分钟
中心思想（一句话）：<听完最想让人记住的那句>
论证链：<抛出> → <立问题> → <解法> → <为什么可行> → <行动>
段落骨架：
- §1 开场（0.5 分）：角色 <钩子/泼冷水/自介> · 关键信息「<一句话>」
- §2 <段名>（3 分）：关键信息「<一句话>」· 素材 <真实例子/数据/引用>
- …
- §N 收尾（1 分）：行动号召「<一句话>」+ 回顾钩子
声明的偏离：<哪些刻意不讲、为什么 —— 逐条列>
```

**页面计划范本（④ 的输出 · 内部设计稿）**：

```
系列：<名称>（N 页 · 布局覆盖 <X> 种，相邻不重复 ✓）
系列级设计（全 deck 共享，拆页时一次定死，不逐页现定）：
    色彩语义 <如 桃 = 问题侧 / 薄荷 = 解法侧> · 系列锚 <角标 / 高亮块 / 吊牌角色标注> · 标题话术 <逗号短句 / 问句体>

- P1 封面 [§1 · 呼吸段 1–2 · 0.5 分]  布局：标题大字 + 涂鸦散点
    关键信息：「<一句话>」
    单元规划：seg1 → g-speaker, g-title · seg2 → g-sub, g-oss
    图标预案：复用 ×<n>（<列出>）· 草稿 ×<m>（<哪页产出 → 哪几页复用>）
- P2 <标题> [§2 · 呼吸段 1–4 · 3 分]  布局：对比分栏
    关键信息：「<一句话>」
    单元规划：seg1 → g-title, g-lh, g-bub · seg2 → g-erase, g-l1 · seg3 → g-l2, g-l3 · seg4 → …
    图标预案：…
```

> 单元 id 直接进 notes.js 的 stages 表与页面 `unit('id')`——**三处逐字一致**，
> 命名贴叙事（g-db 而非 g-group3），这是对齐数据的唯一命名源。

## 3. 布局词表（系列沉淀 · 可扩展）

| 布局类型 | 适合讲什么 | 已验证案例 |
|---|---|---|
| 三栏并列 | 3 个平行卖点 / 优势 / 原则 | 金样张 reference-render.html |
| 放射式 | 一个核心 + 5–7 个发散点（痛点、要素） | handdrawn-ai-pains.html |
| 闭环环形 | 流程循环、飞轮、自增强机制 | handdrawn-knowledge-loop.html |
| 场景式 | 讲故事、摆冲突（左困境 / 右发问） | handdrawn-data-model-pain.html |
| 横向流水线 | 阶段推进、管线（3–5 段，≠ 并列） | handdrawn-deck/no-redo-demo/p7-script-first.html（四阶段 + 确认勾） |
| 竖向时间轴 | 历程、版本演进 | 待首例 |
| 对比分栏 | 前后 / 有无 / 对错 | handdrawn-deck/no-redo-demo/p4-seed.html（左随机/右固定）· p6-engine-orch.html（双卡） |

**多样性规则**：
- 相邻两页**不得同布局**（翻页疲劳 = PPT 死因）；
- ≥4 页的 deck 至少覆盖 3 种布局；
- 封面 / 收尾页允许轻量布局（标题 + 涂鸦），不算重复；
- 新布局首次使用后，回写本词表（标注首例文件）。

## 4. deck 级验收清单

**框架与讲稿（讲稿先行版的根）**：
- [ ] 框架确认单（中心思想 / 论证链 / 段落骨架 / 声明的偏离）已获用户确认，才写逐字稿。
- [ ] 逐字稿（notes.js + 讲稿 .md）已获用户确认，才画任何一页。
- [ ] 口播是口语风格（短句 / 有钩子），字数 ≈ `sec × 4`（240 字/分钟）；
      讲稿 .md 由生成器逐字渲染自 notes.js（零漂移）。
- [ ] 每页 stages 行数 = 该页呼吸段数（壳同款 `segmentScript` 切分，非目测）；
      每个单元属于且仅属于一行 stages；单元 id 与页面 `unit('id')` 逐字一致。

**故事线**：
- [ ] 每页只承载一个信息结构；无“塞不下”的页。
- [ ] 页边界落在讲稿自然节拍上（一段不跨两页）；连起来听有递进。

**页间一致性**：
- [ ] 相邻页布局不重复；全 deck 覆盖 ≥3 种布局（≥4 页时）。
- [ ] 同一概念跨页用同一图标（全 deck 共享 icon-library）。
- [ ] 标题系列感（同一话术风格 / 同一问句体等，刻意设计过）。
- [ ] 六旋钮全 deck 一致（同一模板复制，天然满足）。

**放映**：
- [ ] `PAGES` 数组完整，顺序即叙事顺序；顶栏页号/标题逐页正确。
- [ ] ←/→/空格/Home/End/F 全部可用；圆点可点、跳页输入回车直达。
- [ ] 16:9 画幅在窗口内居中 contain，缩放窗口不裁切、不变形。
- [ ] 翻回已看过的页渲染开场态（或整幅重播，视页能力）；每页单独打开仍是完整活页。
- [ ] 改过页 / 讲稿后 `V` 已 bump，刷新无「旧缓存页整幅加载」残留。

**演讲者视图 + 渐进绘制**：
- [ ] 顶栏页型徽章（`kind`）+ 常驻跑表（超时变红）；右侧**清晰无衬线**备注栏 +
      页标题 + 本页/累计时长 + 全局进度条；当前页无 notes 条目 → 显示「本页暂无备注」。
- [ ] 讲稿按「呼吸段」渲染（长段落自动按句读切段、带序号）。
- [ ] **旁白到哪、笔到哪**：点呼吸段（或 `↑↓`）= 页面渐进绘制到该段——讲到才画的单元
      逐段落笔、已讲单元保留、未讲单元隐藏；回点已讲段可确定性复现；`R` 重演当前段。
- [ ] `↑↓` 在当前页呼吸段间移动播放头；跨页仍走 `←→`（左右翻页、上下切段，不冲突）。
- [ ] 无 `stages` 的页 / 缓存旧页：呼吸段点击只移动播放头，页面整幅播放，不报错。
- [ ] `PAGES[i].built:false` 的页 → 显示占位卡，右侧备注照常（视觉页没建完也能排练）。
- [ ] 各页 `sec` 累加 = 目标总时长。

**页内**：逐页执行 handdrawn-sketch-engine §9 验收清单。

## 5. deck 组装规范

- 交付目录：`docs/handdrawn-deck/<topic>/`（deck 作品统一收在 `docs/handdrawn-deck/`
  父目录下，一 deck 一子目录），内含 `deck.html`、`notes.js`（讲稿先行：
  ③ 创建，不是后置补的）、`p1-<slug>.html … pN-<slug>.html`（序号前缀保证
  文件系统排序 = 放映顺序）与逐页讲稿 .md。
- 页面由引擎 skill 生成后**原样搬入**目录，不改内容；壳通过 `?deck=1` 让页面隐藏自带控制条。
- `PAGES` 数组是唯一需要手填的地方：`{file:'p1-cover.html', title:'封面 · …'}`。
  可加 `no`（页序，缺省回退为数组下标+1，用于匹配 notes.js）与 `built`（见下）。
- 放映：本地起任意静态服务打开 `deck.html`（iframe 读同目录文件；`file://` 直开部分浏览器受限）。
- 深链：`deck.html#3` 直达第 3 页，可用于“从第 N 页开始讲”。

**notes.js 契约（讲稿单一数据源）**：

```js
window.DECK_NOTES = {
  meta: { talk: '…' },                 // 可选
  pages: [
    { no: 1, kind: 'cover', title: '封面', sec: 30, 口播: '逐字照读稿…', cue: '可选提示',
      stages: [                          // 可选 · 渐进绘制对齐表（④ 规划），与呼吸段一一对应
        { draw: ['u-title'] },           // 第 1 段落的笔：这些 unit 逐位绘入（顺序即落笔顺序）
        { draw: ['u-lh','u-bub'] },      // 第 2 段；已讲单元自动保留，无需重复列
      ] },
    // no 匹配 PAGES 的 no（缺省按下标+1）；kind 页型（cover/content/overview/closing →
    // 顶栏中文徽章「封面/正文/全景图/收尾」，缺省不显示）；sec 本页时长(秒)，累计由壳累加，勿手写
  ],
};
```

- **stages 契约（渐进绘制）**：数组下标 = 呼吸段下标（壳用 `segmentScript` 切 `口播` 的
  输出顺序）；`draw` = 该段绘入的 unit id 列表（页内 `<g data-unit="id">`，由引擎 `unit()` 助手产出，
  命名贴叙事）。累计可见集由壳自动并出（前段画过的自动保留），`draw` 只写**本段新增**。
  收束段可 `{draw:[]}`（全板定格，不落新笔）。`stages` 缺省 / 短于段数 → 对应段只移动播放头、
  页面整幅播放（向后兼容）。
- **能力握手与缓存**：页 boot 完成后上报 `{type:'handdrawn:ready', staged}`（staged = 页内
  有 `data-unit`），壳重访时按页的真实能力派发 stage / show——**缓存了改造前的旧页**（不上报、
  不认 stage 消息）会自动降级为整幅重播，不会哑在整幅静态。改了页文件 / notes.js 后，bump
  壳顶部的 `V`（并同步 `<script src="notes.js?v=…">` 的 v）让壳强制重拉，症状是「有的页进来
  就整幅画完」。
- **增量建造友好**：`PAGES` 某页标 `built:false`，放映该页时显示占位卡（不加载其 iframe），右侧备注照常 →
  视觉页没建完也能完整排练；建好后删 `built:false`（或置 `true`）。
- **逐页讲稿 .md**：`references/gen-script-md.cjs` 从 notes.js 渲染按页索引讲稿，口播/提示
  **逐字插值**（零漂移）；改口播只改 notes.js 再重跑生成器，勿手改生成的 .md。

## 6. 反模式

- ❌ **跳过框架确认直接写逐字稿** → 返工最贵的是逐字稿，框架确认就是用来便宜的。
- ❌ **逐字稿没确认就开始画页** → 画面是讲稿的投影；稿没定，画了白画。
- ❌ **口播写成书面语** → 讲稿是照读出来的：短句、有钩子、讲例子；长从句一出口就散。
- ❌ **单元脱离旁白节拍** → 没讲就画出来（剧透）、讲了还没画（空等），渐进绘制就失去意义。
- ❌ **呼吸段目测手切** → 与壳的 `segmentScript` 错位一格，整页 stages 全歪；必须提取函数跑。
- ❌ 全 deck 一个布局复制 N 份 → 翻页疲劳，不如做长图。
- ❌ 一页塞七八个节点 → 手绘不是文档，塞不下就拆页。
- ❌ 页内容离开上下文就看不懂 → 每页必须独立成片。
- ❌ 每页重新问一遍布局 → 页面计划已锁结构，逐页执行不重问。
- ❌ 跨页同一概念换图标 → 系列感塌方；图标全 deck 共享一个库。
- ❌ 壳里魔改页面内容 → 壳只管编排与派发，页面是独立交付物。
-  跑无头浏览器做「验证」→ 耗时远大于收益(壳只是 iframe 堆叠 + 键盘绑定，JS 语法合法即可)。**验收交给打开文件肉眼看一次**，不做 headless 自动化。

## 7. 引擎协作备忘（写给执行阶段的自己）

- **委托要带讲稿**：逐页委托引擎时，把**该页的呼吸段 + 单元规划**（④ 的页面计划）
  一并给出——引擎按单元规划给元素分组（`unit('id')`），节拍 = 旁白节拍，
  单元 id 与 stages 表逐字一致。
- **串行与并行**：图标预案声明了草稿图标的「产出页 → 复用页」依赖——有依赖的页
  必须串行（产出页先画、草稿定型后复用页才能引用），无依赖的页可以并行委托。
  系列级设计（色彩语义 / 系列锚 / 标题话术）在 ④ 一次定死，逐页执行时只执行不新定。
- **壳摆画幅、页定内容**：壳提供 16:9 投影画幅（contain 居中 + 投影幕质感），iframe 铺满
  画幅；页内几何仍 100% 由内容页自定（引擎模板 deck 模式下按画幅视口自适应）。页自带
  `(100vh-150px)` 内缩，双重 contain 下会在画幅内留少量同底纸边——可接受，**勿为严丝合缝
  重写成品页**。
- **壳接管播放**：deck 模式下页内控制条隐藏，播放权归壳——HUD 的 ▶ 重放本页
  （R 键同效）+ 全局抖动滑块（`handdrawn:rough` 实时广播到所有已加载页；
  新页加载时自动对齐壳当前值，值相同则不打断首播动画）。
- **旁白驱动绘制（有 stages 时）**：壳是导播台——呼吸段 = cue 键，点段 / `↑↓` 切段
  时把对齐表翻译成 `handdrawn:stage {show, draw, pace}` 发给页（`show` 已讲单元累计集、
  `draw` 本段新增、`pace` 段内节拍默认 0.45s/单元）；页侧通用渲染器整板确定性重建
  （同 seed，回跳可复现）。**对齐表唯一存放处是 notes.js 的 `stages`**——壳算、页渲，
  页自身不带表，保持独立成品地位。无 stages 的页收不到该消息，行为同旧版。
- **按键分工（铁律）**：`← → 空格 Home End` 永远归**翻页**；`↑ ↓` 归**段落推进**
  （在当前页呼吸段内移动播放头并驱动页面，不跨页——跨页走 `← →`）；也可以点备注栏
  cue 键。左右归翻页、上下归段落，互不冲突——单页体验样本里「左右键推段落」的写法
  一进 deck 就和翻页打架，样本是特例，成品照这条来。
- **键盘穿透**：壳会给每个加载完的 iframe `contentWindow` 挂同一套翻页键监听——
  用户点进页面内容（焦点落进 iframe）后，方向键依然翻页。
- 引擎模板原生支持 deck 模式：URL 带 `?deck=1` 时隐藏页面自带控制条；
  页面收到 `{type:'handdrawn:show'}` 消息即重播逐笔绘制。
- 历史页面（模板增强前生成的）装进 deck 也能放映，只是翻回时不重播动画、
  宽度仍按页面自己的设计（如自带 1180px 上限）——可接受，勿为此重写成品页。
