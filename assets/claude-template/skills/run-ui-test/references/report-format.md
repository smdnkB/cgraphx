# R6 UI 功能测试报告规范

## 产物

| 产物 | 路径 | 用途 |
|---|---|---|
| Markdown 报告 | `docs/features/<feature-id>/ui功能测试/<文件前缀>-ui功能测试报告.md` | 给人看:汇总 + 逐用例结果 + 失败汇总 + 下一步建议 |
| 截图 | `docs/features/<feature-id>/ui功能测试/<功能点名>.png` | 预期验证点留证,报告内相对路径引用 |

**不产 JSONL**——本流程不验库,无程序化消费方。

## 报告归属规则

报告永远归用户触发时指定的需求目录。同需求重复触发 → 覆盖,不增量合并。

## Markdown 报告章节

### §1. 汇总

| 指标 | 值 |
|---|---|
| 总用例数 | N |
| 通过 | N |
| 失败 | N |
| 跳过 | N |
| 通过率 | % |
| 运行模式 | headed / 无头 |
| 入口 URL | … |

### §2. 逐用例结果 ⭐ 核心

每用例一节。失败用例必须详细(步骤执行到哪一步、预期 vs 实际、截图);通过用例可简写。

```markdown
### 用例 1:新建客户 —— ✅ 通过

步骤全部执行,预期验证通过。截图:![新建客户](新建客户.png)

### 用例 2:编辑客户 —— ❌ 失败-预期不符

- 执行到:步骤 3(点「保存」)
- 预期:提示「保存成功」,列表联系电话更新为 13900139000
- 实际:提示「保存成功」,但列表联系电话仍显示旧值;刷新后才更新
- 截图:![编辑客户](编辑客户.png)
- 原因分类:失败-预期不符(疑似保存后列表未重新拉取)
```

### §3. 失败汇总

| 状态 | 数量 | 用例 |
|---|---|---|
| 失败-预期不符 | N | 用例名 |
| 失败-元素缺失 | N | 用例名 |
| 失败-环境 | N | 用例名 |
| 失败-登录 | N | 用例名 |
| **合计** | **N** | |

无失败则写「本次无失败用例」。

### §4. 下一步建议

按失败类型给建议,不自动调下游 skill:

- 失败-预期不符 → 疑似功能 bug,走 `/implementation` 修,修完重跑 `/run-ui-test`
- 失败-元素缺失 → 确认页面结构是否改版;用例过时 → 走 `/write-ui-test` 重新派生
- 失败-环境 → 服务/浏览器问题,恢复后重跑
- 失败-登录 → 核对用例规格 §4 的测试账号

### §5. 产物清单

固定三项:用例规格、本报告、截图(列文件名)。

## 状态枚举(与 SKILL.md 一致)

`通过` / `失败-预期不符` / `失败-元素缺失` / `失败-环境` / `失败-登录` / `跳过`

**前置暂停不记入报告,不算失败**(MCP 缺失/服务未就绪/数据未备齐时 skill 在 R0/R3 暂停,根本没进 R5)。
