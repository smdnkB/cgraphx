db schema skills 闭环

两个 skill + 一个共享知识库,让 agent 越用越懂业务数据

1. 共享的目录结构(知识库本体)

docs/schema-knowledge/ ├── order-svc/ │ ├── INDEX.md ← agent 进目录第一件事读(表清单+注释) │ ├── pending-comments.sql ← DBA 待执行 COMMENT SQL(action 队列,不在 agent 读路径) │ └── ddl/ │ ├── work_order.sql ← DDL + DISCOVERED 块(积累的隐式关系/含义/陷阱) │ ├── users.sql ← DDL + DISCOVERED 块 │ └── payment.sql └── cust-svc/ ├── INDEX.md ├── pending-comments.sql └── ddl/...

绿色 = agent 必经节点(INDEX.md 是入口,ddl/<table>.sql 是详情); 橙色 = db-query 探索补充的部分,export 重 dump 时会保留; 灰色 pending-comments.sql = DBA action 队列,不在 agent 读路径上(所以可以独立文件)。

2. 时序:知识怎么积累起来

T0 · 跑 export-table-ddl
建基线 → ddl/work_order.sql 只有 DDL,无 DISCOVERED 块
T1 · db-query 任务:"查 work_order 待派单的数据"
Read ddl/work_order.sql(首选)→ cgraphx db query --sql "SELECT ... LIMIT 5"(查数据)
T1 续 · 发现 work_order.assignee_id 实际对应 users.staff_code
知识 → append 到 ddl/work_order.sql 和 ddl/users.sql 的 DISCOVERED 块(双向)
DB 注释缺失 → action 进 pending-comments.sql(DBA 待执行)
T2 · DBA 改了 schema,重跑 export-table-ddl
DDL 部分刷新(拿新结构),DISCOVERED 块自动保留(不覆盖);pending-comments.sql 不动
T2 续 · DBA 执行 pending-comments.sql 里的 COMMENT
DB 注释固化 → 删 pending-comments.sql 里那条 + 删 DISCOVERED 对应的 [字段含义] 行(DB 已是单一事实源)
T3 · 下一次 db-query 读 work_order
Read ddl/work_order.sql → 看到 DDL + DISCOVERED 块(积累生效,不用重新踩坑)
闭环核心:知识库是 便宜 + 丰富 的首选信息源(本地读 + DISCOVERED 块),DB 是 昂贵 + 不可替代 的兜底(连库 + 只读铁律)。agent 默认走知识库,只在"知识库没有"或"要实际数据"时连库 —— 这样新沉淀的知识才会被读到,闭环才转得起来。
