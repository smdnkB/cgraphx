# 盘点子 agent 说明

第 1 步派子 agent 时,主会话照下面写一份说明放进 scratchpad(尖括号处填好),每个子 agent 的提示词只写「先读说明 + 你的组名 + 你的入口表」。

````markdown
# 盘点子任务说明(所有组共用)

你在为「<系统名>迁移」做 dev-migrate 第 1 步「盘点:行为清单」的一部分。旧系统是标准答案,你只读不改。

## 先读
1. <新工程>/.claude/skills/dev-migrate/SKILL.md 的「1 · 盘点」
2. 同目录 references/产物范例.md 的「行为清单」节——行格式、记号表、疑点表照它
3. 本次的记号表:<主会话定好的公共链路记号,如 L=登录收尾、W=操作日志 @Log、DS=数据权限>

## 位置
- 旧系统后端:<路径>(<模块说明:启动模块、业务模块、框架模块>)
- 调用方仓库(冗余取证要全部搜,来自迁移总图「基线」):
  - <前端 1>/src、<前端 2>/src……
  - <服务间调用它的后端>(Java 和 **XML、yml 配置**都搜:RMI/Feign/网关按「前缀 + 方法名」拼路径)
  - <监控探活>
  - 旧系统自带的静态页(如 `static/*.html`)
- 业务知识:<旧工程>/docs/knowledge/*.md

## 每个入口一行
列:| 编号 | 入口 | 行为(用户看得到的) | 规则分支 | 读写表 | 副作用 | 来源 | 处置 | 片 | 状态 |
- 编号 `B-<简码>-NN`,NN 按文件内出现顺序。
- 入口:HTTP 写「方法 + 完整路径」(类级前缀 + 方法路径),不限方法的写 `* /path`;非 HTTP 写「类名#方法 + 触发方式」。同一个方法既是 HTTP 又是定时 → HTTP 组和定时组各写一行,规则分支里注明「同 B-xx」。
- 规则分支:读 controller → service → mapper 得到的关键分支,①②③ 编号,写具体的状态值、字段名、提示文案;权限注解、数据权限、防重复提交、操作日志用记号。脚手架标准增删改查写「<脚手架名 版本> 标准」,只记和标准不一样的地方。
- 读写表:追到真实表名;流程引擎表可写 `ACT_RU_*/ACT_HI_*(引擎)`。
- 来源:映射注解所在行 `文件名.java:行号`,关键逻辑再加 service 的 `xxxServiceImpl.java:行号`。
- 处置:以「迁移」「🗑️候选」「待查」三者之一开头,后面括号写证据或原因;主会话按开头统计。一行迁移、只删其中一段代码的,删的那段写进规则分支,处置照写「迁移」。单元格里的 `|` 写成 `\|`。

## 冗余取证(每个入口都做)
1. 路径静态部分(去掉 {变量})**带和不带前导 `/`** 各搜一次,覆盖全部调用方仓库;下载、上传类还要搜 `download('…')`、`uploadUrl` 这类写法;前端路由的 `path:` 命中不算。
2. 命中前端 api 文件里的函数 → 再搜这个函数名有没有**非注释的调用**;只定义、只 import 的算无调用。
3. 判定:有活的调用 → 迁移。全部没有 → 🗑️候选(调用方仓库均无调用);只在注释里有要写明。所在模块没打进可部署产物 → 🗑️候选,即使前端在调(写「前端调用必然 404」)。免登录接口搜不到调用方 → 待查(可能外部直调)。知识库或 spec 写明运维在用的手动入口 → 待查。
4. 整模块判同一结论时,在文件开头定义证据代号(D1、D2…),每行只引代号。

## 冗余候选 · Mapper 方法
只有说明里指定的那一组做:全量 Mapper 接口方法 + XML statement,找没有调用方的(按 `mapper实例.方法(` 搜,避免和同名 service 方法撞名),放「冗余候选 · Mapper 方法」表:| Mapper | 方法 | 证据 |。删某个入口后它独占的 service、Mapper 方法也变成冗余的,写进同一张表的「连带」列。

## 产出
写到 <scratchpad>/inventory/<组名>.md:
1. `## 简码表`:| 简码 | 类 | 预期入口数 | 实际行数 |
2. `## 清单`
3. `## 冗余候选 · Mapper 方法`(指定组才有)
4. `## 疑点`:| 编号 | 类型 | 疑点 | 代码说 | 文档说 / 影响 |;类型 = 文档冲突 / 代码疑点(bug、安全)/ 缺取证手段;编号 `Q1` 起,主会话合并时加组号
5. `## 自检`:每个简码「预期 = 实际」是否成立,不成立写原因

## 规矩
- 只读:不改任何仓库、不做 git 操作、不连网络、不起服务;只有说明里指定的组查库,只读、带 LIMIT,先测连通,连不上就留 SQL、标「未枚举」后继续别的类别。
- 批量搜索写成 python 或 bash 脚本跑(zsh 不对未加引号的变量分词、BSD sed 不认 `\s`),先用一个已知会命中的路径自检;用 `command grep` 或 `rg`,绕开 shell 里包装过的 grep。
- 拿不准就写待查,不猜。

## 回报(简短)
- 每个简码的行数、🗑️候选数、待查数
- 跨组问题(某行为其实由别组入口触发、共用的 service)
- 高危安全问题单列
- 对 dev-migrate skill 的卡点
````
