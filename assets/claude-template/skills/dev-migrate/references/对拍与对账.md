# 对拍与对账

每片验收两件事:**对拍**——同一请求打新旧两个系统,响应和副作用一致;**对账**——迁移脚本搬过去的数据和旧数据按表映射一一对上。两件都过,清单行才能标 ✅。

## 前提:同一份数据

新旧系统对着同一时刻的同一份数据:测试环境从旧库取一份快照 → 旧系统连快照;已完成各片加本片的迁移脚本把同一份快照搬进新库 → 新系统连新库。写接口每轮对拍前,两边都重置回这份快照。快照时间、两边的 commit 写进对拍报告头部。

## 接口对拍

1. **用例**:`/api-case` 按本片 spec 的接口契约生成 .bru;接口契约兼容(总图 G1)时同一套 .bru 两边都能跑,环境里加 `old` / `new` 两个,各自登录取 token。覆盖要求:
   - 每个清单行至少一个用例,规则分支每条一个(B-TKT-03 有 ①②③ → 三个用例);
   - 列表类再加:空结果、第二页、每个数据权限层级的账号各一个;
   - 错误分支要断言错误码和提示文案——前端可能按文案判断。
2. **跑**:

   ```bash
   bru run <本片用例目录> --env old --reporter-json 对拍/old.json
   bru run <本片用例目录> --env new --reporter-json 对拍/new.json
   node <本 skill 目录>/scripts/compare-runs.mjs --old 对拍/old.json --new 对拍/new.json --rules 对拍/规则.json --out 对拍/明细.md
   ```

   退出码 1 = 有差异或有只在一边出现的用例。
3. **规则只许放过两类**,每条在报告里写理由:本次运行生成的值(新 ID、当前时间、traceId,用 `ignore`);旧 SQL 没写 `ORDER BY` 的列表顺序(用 `unordered` 按主键排,理由引用旧 SQL 的 `file:line`)。其余一律算差异——字段缺失和字段为 `null` 也算,前端可能靠它判断。

   ```json
   {
     "ignore": ["traceId", "data.createTime"],
     "unordered": { "data.rows": "id" }
   }
   ```

4. **写接口**:响应照上面比;再比副作用——两边各跑完后,按表映射比被写的行(SQL 写法同下面「逐行比对」,范围限定到本次写入的 ID);流程引擎比流程定义 key、当前节点、办理人(查各自的 `ACT_RU_TASK`、`ACT_HI_PROCINST`);短信、消息、推送比各自的发送记录(记录表或日志),内容和接收人一致才算过。

## 数据对账

每片的对账 SQL 写在 `sql/<两位片号>-<切片>-对账.sql`,每条注明期望;每次演练迁移后全部跑一遍,每条都得到期望值才算过。新旧在同一数据库实例时直接跨 schema 写(下面是 MySQL):

```sql
-- 01 行数:旧表和新表一样多(表映射规定丢弃某些行的,旧侧加同样的过滤条件)。期望:diff = 0
SELECT (SELECT COUNT(*) FROM old_sch.t_ticket)
     - (SELECT COUNT(*) FROM new_sch.ticket) AS diff;

-- 02 聚合:按映射后的状态分组计数一致。期望:0 行
SELECT s.status, s.old_cnt, s.new_cnt FROM (
  SELECT m.status, COUNT(*) AS old_cnt,
         (SELECT COUNT(*) FROM new_sch.ticket n WHERE n.status = m.status) AS new_cnt
  FROM (SELECT CASE status WHEN '0' THEN 'DRAFT' WHEN '1' THEN 'AUDITING' WHEN '2' THEN 'DONE' END AS status
        FROM old_sch.t_ticket) m
  GROUP BY m.status) s
WHERE s.old_cnt <> s.new_cnt;

-- 03 逐行比对:旧行按表映射算出期望值,和新行逐字段比(<=> 让 NULL 也参与比较)。期望:0 行
SELECT o.id
FROM old_sch.t_ticket o
LEFT JOIN new_sch.ticket n ON n.id = o.id
WHERE n.id IS NULL
   OR NOT (n.customer_id <=> o.cust_id)
   OR NOT (n.status <=> CASE o.status WHEN '0' THEN 'DRAFT' WHEN '1' THEN 'AUDITING' WHEN '2' THEN 'DONE' END)
   OR NOT (n.deleted <=> COALESCE(o.del_flag = '2', false))
LIMIT 100;

-- 04 反向:新表里没有旧来源的行。期望:0 行
SELECT n.id FROM new_sch.ticket n LEFT JOIN old_sch.t_ticket o ON o.id = n.id WHERE o.id IS NULL LIMIT 100;

-- 05 引用完整:新表外键都指向存在的行。期望:0
SELECT COUNT(*) FROM new_sch.ticket_log l LEFT JOIN new_sch.ticket t ON t.id = l.ticket_id WHERE t.id IS NULL;
```

- 表映射里每个「转换」都要出现在 03 的某个比较条件里;合并的表(两张旧表 → 一张新表)01、03 对 `UNION ALL` 后的旧数据做,拆分的表对每张新表各写一组。
- 新旧不在同一实例(或换了数据库种类):两边各导出「主键 + 映射后各字段拼接的 md5」按主键排序成文件,用 `diff` 比,01、02 照样两边各跑。
