- 风险/注意事项:
  - **顺序**:`postAction` 天然在 action 之后(补录已跑过),所以「判过没有」只能认 `dirs_checked`;不要改成读 `timeline_roots`。
  - **不写记录的分支**:根为空、旧库模式、项目目录不在、git 出错、项目库读失败、已经判过——这些都不要写 `dirs_checked`,否则下次没机会判断。
  - **提示只写 stderr**:`--json` 的 stdout 不能混进提示;提示的返回值已带 `[cgraphx] `,别再加第二遍。
  - **install 的时序**:`recordProjectName` 在并旧数据之前,新项目此时可能还没有项目目录 → `checkDuplicateName` 返回 null 且不记录,这是预期的;`install` 结束后的 `postAction` 会再判断一次(那时项目目录已在)。
  - **判过就不再提示**:`dirs_checked` 不过期,`project remove` 后同一目录也不再提示(spec D7 的取舍),不要顺手加清理。
  - **`project name` 之后也会判断一次**:如果这个目录还没判过,改名后的第一条 `project name` 命令会走 postAction 判断新名字;`renameProject` 自己已经打过「X 已经有数据」,两处说的是一回事,不额外排除(spec 只沿用 `NON_SESSION_COMMAND_NAMES`)。
  - 判断里的写操作(origin、dirs_checked)失败只吞掉自己,不要让提示消失或命令退出码变化。
