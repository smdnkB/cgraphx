### T-3: 补录归属与重建——目录还在就现认、不改名的历史不重复

- 目标: D4——会话文件的开始目录还在就现认归属(不再信 `start_dirs` 缓存,同一趟按目录记住,git 仍按根记忆只跑一次),目录不在了才用缓存、再退到 `timeline_roots` 与副本登记;D5——全量重建时,`session_files` 里已记到别的项目、偏移大于 0 的文件不从头读,保持偏移交给增量,避免改名后新项目把旧历史再解析一遍。
- 对应 spec 编号: D4、D5;K1、K5 的补录侧口径
- 强制引用: `docs/guides/coding-standards.md` 的「边界与结构」(分层、中文注释)「选型」(单文件 ≤600 行)
- 涉及范围(2 个文件):
  - `src/core/timeline/ingest/ingest.ts`
  - `src/core/timeline/ingest/rebuild.ts`
- 必须严格执行:
  - C-9(开始目录归属的顺序、`ClassificationContext.classified`、写 `start_dirs` 的时机)
  - C-10(重建的跳过规则与偏移不推进)
  - 不改 `session_files` 的语义与推进时机(项目库提交之后才写);不改事件的映射、去重、`upsertRoot`;不改 `ingest.lock`
  - spec D5 影响面里那句「实现时加用例确认」由后续 unit-spec → unit-code 覆盖(设计验收 #5),本任务不新写测试(测试不进 plan)
- 允许局部适配:
  - 判定函数内部的辅助函数拆分与命名
  - 注释措辞
- 具体要求:

  **1. `src/core/timeline/ingest/ingest.ts`**
  - `ClassificationContext` 增加 `readonly classified: Map<string, DirClassification>`;`IngestContext` 继承它,不用另加字段。
  - `classifyStartDir` 按 C-9 重写:
    1. 先查 `ctx.classified.get(cwd)`,命中直接返回;
    2. `cwd` 还在(用 `fs.statSync(cwd, { throwIfNoEntry: false })`,抛错按不在)→ 现认,不读 `start_dirs`:
       - `root = findProjectRoot(cwd)`;没有根 → 三字段 null;
       - `identityOfRoot(root)`;`'git-error'` → 三字段 null,把结果记进 `ctx.classified` 后返回,**不写 `start_dirs`**;
       - 否则 `dirName = identity !== null ? findProjectDir(identity)?.name ?? null : null`、`name = identity?.name ?? null`;
    3. `cwd` 不在了 → 读 `start_dirs`:有行且 `project_dir !== null` 直接用;否则 `ctx.fallbackMatcher().match(cwd, { allowSelf: true })` 兜底(命中 → `dirName = ctx.currentDirName`、`root = hit.root`、`name = null`);
    4. 除 `git-error` 外把结果写一行 `start_dirs`(`saveStartDir` 传 `project_dir = dirName`),写失败吞掉;结果同时放进 `ctx.classified`;
    5. **不要**在目录还在时读 `start_dirs` 来决定归属(那正是要改掉的旧行为);也不要在目录不在时去 `identityOfRoot`(git 会在已删目录里跑)。
  - 在 `ingestIncremental` 构造 `ctx` 的地方加 `classified: new Map()`。
  - 文件头注释第 4 步改成:「开始目录还在就现认(同一趟按目录记住,git 按根只跑一次);不在了才用 `start_dirs` 缓存,再退到 `timeline_roots` 与副本登记」。
  - 保持 `processFile` / `writeFacts` / `saveRow` / `noteUnparsed` / `mapFacts` / `upsertRoot` 不动;`DirClassification` 的 origin 已在 T-1 去掉。

  **2. `src/core/timeline/ingest/rebuild.ts`**
  - 遍历文件的循环开头(拿到 `stat` 之后)先取一次 `const recorded = sessionIndex.getSessionFile(file)`:
    - 按 C-10 判断跳过:`recorded !== null && recorded.project_dir !== null && recorded.project_dir !== currentDirName && recorded.byte_offset > 0` → `continue`;
    - 被跳过的文件不读、不写临时库、不进 `parsedRows`(第 ⑥ 步因此不会推进它的偏移)。
  - `knownStartCwd` 改成接收已经取到的 `recorded`(或内联这段逻辑),不要再 `getSessionFile(file)` 第二次;`subagents/` 文件跟主会话的规则不变(先看本趟 `parsedStartCwd`,再查 sessions.db 里主文件的行)。
  - 其余全量流程(临时库、短事务清 + 写 + `rebuilt_at`、收尾推进偏移、删 `turns/` 与 `~/.cgraphx/sessions/`、VACUUM)不动。
  - `classifyCtx` 构造处加 `classified: new Map()`(每个重建一趟一个)。
  - 文件头注释第 4 步补一句跳过规则:已记到别的项目且偏移 > 0 的文件不从头读,交给增量。

- 风险/注意事项:
  - **性能**:`classifyStartDir` 每个文件都会调,`ctx.classified` 必须按 `cwd` 记住结果,否则每个文件都会 `findProjectRoot` + `findProjectDir`(扫 `projects/` + 读 `identity.json`)。键用传入的 `cwd` 原值,不要 resolve 后再存(同一个 start_cwd 才命中)。
  - **别给删掉的目录跑 git**:目录不在的分支只走缓存与根匹配,不调 `identityOfRoot`。
  - **缓存行还是要写**:目录还在时虽然不信缓存,但要把现认结果写回 `start_dirs` —— 将来目录被删了,靠它兜底。
  - **git 出错**:返回空归属、不写行、记进本趟记忆(避免同一趟反复跑失败的 git);下次运行再认。
  - **跳过规则只认「已记到别的项目且偏移 > 0」**:偏移 0、没记过、`project_dir` 为 null 的照旧从头读;别把「supposed 属于本项目」的文件也跳过。
  - **偏移不要动**:跳过的文件不进 `parsedRows`,第 ⑥ 步不推进它们的偏移;之后的增量从原偏移续读,新内容归新项目。
  - `ingest.ts` 已超过 600 行(存量),本任务不做整体拆分;新增的判定辅助放在本文件内即可。确实想拆时只把归类相关的纯函数抽到同目录新文件、由 `ingest.ts` 继续导出同名符号(不能改 `rebuild.ts` 的 import 面),不要顺手重构事件映射。
