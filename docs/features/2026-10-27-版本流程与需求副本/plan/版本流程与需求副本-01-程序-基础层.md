- 具体要求:
  1. `src/core/directory.ts`:按 C-1 加常量、类型和 `resolveDataDir`、`getDataDir`。realpath 失败时退回 `path.resolve` 的结果再比较;整个函数包在 try/catch 里,出错返回 own。不改已有函数的行为和签名。
  2. `src/core/db/index.ts`:`getDatabasePath` 按 C-1 改用 `getDataDir`;新增导出 `getLocalDatabasePath`。文件顶部注释里「共享 DB」的说明补一句:副本里共用库在数据目录,知识库在本地库。
  3. `src/core/markdown/schema-bootstrap.ts`:`openMarkdownDb` 里取库路径(含存在性检查)改用 `getLocalDatabasePath`;`ensureMarkdownSchema` 不动。
  4. `src/core/timeline/turn-state.ts`:轮次文件路径的拼法由 `path.join(projectRoot, '.cgraphx', TURNS_DIRNAME, …)` 改为 `path.join(getDataDir(projectRoot), TURNS_DIRNAME, …)`,读、写、删用同一个路径函数;写入(现在第 82 行 `mkdirSync` 之前)先看 `resolveDataDir(projectRoot).state`,是 `main-missing` 就直接返回,不建目录。`LEGACY_TURN_STATE_FILENAME` 不动(它由 timeline installer 清理旧文件时用,不在本任务范围)。
  5. `src/core/task/source.ts`:两处 `getCodeGraphDir(path.resolve(projectRoot))` 改为 `getDataDir(path.resolve(projectRoot))`;「`.cgraphx/` 不存在」的判断随之看数据目录(`main-missing` 时目录不在,照现有逻辑报错,不建目录)。
  6. `src/core/dbquery/config.ts`:项目级 `db-profiles.json` 的路径改为 `path.join(getDataDir(projectRoot), PROFILES_FILENAME)`;用户级 `~/.cgraphx/db-profiles.json` 不动;报错文案不动。
  7. `src/core/dbquery/logging.ts`:日志路径改为 `path.join(getDataDir(projectRoot), LOG_FILENAME)`;写日志(现在第 76 行 `mkdirSync` 之前)遇到 `main-missing` 直接返回,不建目录、不报错。
  8. `src/core/dbquery/init.ts`:`initDbProfiles` 的 `codegraphDir` 由 `path.join(resolved, '.cgraphx')` 改为 `getDataDir(resolved)`;`resolveDataDir(resolved).state` 是 `main-missing` → 抛错,message 用 C-12 的 D31 原文(主目录路径取 `mainRoot`);其余判断和文案不动。
  9. `src/core/git-hooks.ts`:按 C-2 实现。文件头注释说明:钩子目录取 `git rev-parse --git-path hooks`(已含 core.hooksPath),非 shell 钩子不写,片段紧跟 shebang 插入、每行带 marker,卸载按 marker 删行。shebang 判断:取第一行 `#!` 之后的解释器路径的文件名;是 `env` 时取它后面第一个不以 `-` 开头的参数;结果是 `sh`、`bash`、`zsh`、`dash`、`ksh` 之一才算 shell。
