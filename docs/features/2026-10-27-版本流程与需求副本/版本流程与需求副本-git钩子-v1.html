git 钩子是什么,cgraphx 拿它做什么

git 钩子是放在钩子目录里的普通脚本文件,文件名就是触发的时刻,比如 commit-msg、post-commit;git 到了这个时刻就自动执行它。cgraphx 往钩子文件里插几行,做两件事:每次提交后记一条提交记录,给日报、任务归属和平台上报用;在版本分支上提交时检查提交说明,挡住直接改代码的提交。默认的钩子目录是 .git/hooks,只属于你这台机器,插几行不影响任何人。麻烦在于钩子文件也可能在别处:在全机共用的目录里(第 1 条,已定),是仓库里跟着提交给全组的文件,或者是指向别处的链接(第 3 条)。这时候插几行,影响就超出了本项目、本机。

钩子是什么

记住四点就够了。

是一个文件,名字决定什么时候跑

钩子目录里放一个可执行脚本,git 到了和文件名同名的时刻就执行它。

例:.git/hooks/commit-msg 在每次提交、写完提交说明之后执行;.git/hooks/post-commit 在提交生成之后执行。

「提交前」的钩子能挡下提交

commit-msg 以非 0 退出,这次提交就不生效。post-commit 这类「提交后」的钩子挡不了,只能做记录。

例:commitlint 就是在 commit-msg 里检查提交说明的格式,不合格就挡下。

一个时刻只有一个文件

git 只认一个钩子目录,每个时刻只执行一个文件。别的工具也要用 commit-msg 时,大家挤在同一个文件里。

所以 cgraphx 只往文件里插几行,不整个覆盖,免得把 commitlint 那行冲掉。

默认在 .git 里,只属于这台机器

.git/ 里的东西不跟着仓库提交;别人 clone 下来,钩子目录是空的。

配置项 core.hooksPath 可以把钩子目录改到别处。husky 这类工具就是靠它,把钩子放进仓库、提交给全组共用。

一次提交经过哪些钩子

沿着一次提交走一遍,cgraphx 插的几行分别在第 2、4、5 步起作用。

插进去的几行长什么样

以 husky 项目的 .husky/commit-msg 为例:原来里面跑 commitlint;/release-start 装拦截后,第一行后面多了 3 行(高亮的部分,第 3 行的判断条件简化了写法)。

#!/usr/bin/env sh# cgraphx-release-guard — 版本分支只收合并提交和 chore(release): 开头的提交__cgx_rb=$(git symbolic-ref --short -q HEAD 2>/dev/null || true) # cgraphx-release-guardif <是版本分支> && <不是合并> && <说明不以 chore(release): 开头>; then echo "…" >&2; exit 1; fi # cgraphx-release-guard. "$(dirname -- "$0")/_/husky.sh" npx --no -- commitlint --edit ${1}

插在第一行后面

第一行(shebang)说明用什么程序执行这个文件。插在它后面,原钩子最后就算是 exec …,插的几行也照样会执行;插在文件末尾就可能永远跑不到。

每行带标记

每行末尾都有 # cgraphx-release-guard(提交记录是 # cgraphx-timeline-hook)。重装时先按标记删掉旧行再插,卸载时按标记删,不碰原有内容。

不是 shell 脚本就不插

插进去的是 shell 命令。钩子文件第一行是 #!/usr/bin/env node 这类时,插进去会让钩子报错、每次提交都失败,所以不插,只提示。

.git/info/exclude 是什么

它和 .gitignore 一样,写的是「哪些文件 git 当作没看见」;区别只在谁能看到这份清单。

.gitignore

放在仓库里,跟着提交,全组共用同一份。

.git/info/exclude

放在 .git/ 里,不提交,只在这台机器上生效。

例:新建两个钩子文件后,exclude 里多出两行

# .git/info/exclude/.husky/post-commit/.husky/post-merge

写进去以后

  • git status 里看不到它,git add -A 也不会把它加进去
  • 开副本时按被忽略的文件保留(副本本来就保留被忽略的文件,比如 node_modules),副本里照样记提交
  • 删副本前核对「有没有没提交的改动」时不算它
  • 卸载删掉这个钩子文件时,exclude 里对应的那一行一起删

副本已经在用这个机制:开副本时把 .claude/、.cgraphx/ 写进副本的 exclude(spec D21),第 4 条要讨论的就是它写多大范围。
