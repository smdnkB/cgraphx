  - 进程内记忆的结构与上限
- 具体要求:
  1. `project-identity.ts`(C-1)
     - git 调用一律 `execFileSync('git', args, { cwd, encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] })`;`identityOfRoot` 的那一次调用参数照 C-1 原文。`-z` 输出按 `\0` 分条,每条第一个 `\n` 前是键、后是值;`remote.origin.url` 有多条时取第一条
     - `workTreeRoot`:从根往上找第一个含 `.git`(目录或文件,`fs.lstatSync` 判断存在即可)的目录;`subdir` 用 `path.relative` 后转 POSIX,空串记 null
     - insteadOf:收集 `url.<base>.insteadof` 的值作前缀,origin 以哪个前缀开头取最长的那个,替换成 `<base>`(和 `git remote get-url origin` 的结果一致)
     - 进程内记忆:`Map<path.resolve(root), ProjectIdentity | null>`;`identityOfRoot` 每次现算 `workTreeRoot`、`subdir`、`needsName`、`nameSource` 这几个文件系统字段,只有 `identity` 走记忆
     - `writeProjectName` 写完调 `clearRootIdentity(root)`(内部函数),同进程后面的 `identityOfRoot` 重新读配置
  2. `repo-projects.ts`(C-2)
     - `listRepoProjects(T)`:base = `findProjectRoot(T)`(C-5);在 T 下跑一次配置读取;base 的标识按 C-1 规则算(有就放进结果第一项,subdir 为 null);再把配置里每个 `cgraphx.<子目录>.projectname` 键变成一项:`root = path.join(T, 子目录)`,`identity = { origin: 规整后的 origin 或 null, name: 值 }`,`subdir = 子目录`;每一项都调 `rememberRootIdentity`
     - `listSiblingRoots(root)`:根不在 git 里 → `[root]`;否则在根下跑 `git worktree list --porcelain`,取每个 `worktree <路径>` 行,拼上根相对工作区根的 `subdir`(没有就是工作区根本身),去重后返回(含 root 自己);git 出错 → `[root]`
     - `listOtherInstalledDirs(root)`:不在 git 里 → `[]`;取各工作区根,再加上每个工作区根拼配置里记了名字的子目录;留下 `isInitialized` 为真的;去掉 realpath 等于 root 的 realpath 的那个;git 出错 → `[]`
  3. `user-data-dir.ts`(C-3):按 C-3 原文实现。`identity.json` 写法:临时目录里 `fs.writeFileSync`,两空格缩进 + 末尾换行,字段顺序 `version, origin, name, createdAt`;`readIdentityFile` 只认 `version === 1` 且 `origin`、`name` 是字符串或 null 的
  4. `session-registry.ts`(C-4)
     - `safeSessionName`:`[A-Za-z0-9_-]+` 原样;否则 sha1 hex 前 16 位;null → `_nosession`(和现在 `timeline/turn-state.ts` 的逐字相同)
     - `sessionRootOf(sessionId, start)`:sessionId 非 null 时先 `readSessionRegistration`;读不到 → `root = findProjectRoot(start)`;`root` 为 null → 登记 `{ root: null, origin: null, name: null, project: null }`;否则 `identityOfRoot(root)`,`'git-error'` → 返回 null、不写;拿到标识后 `project = identity ? findProjectDir(identity)?.name ?? null : null`;写登记(sessionId 非 null 时);最后 `rememberRootIdentity(root, identity)`(root 非 null 时)。读到已有登记时同样 `rememberRootIdentity(reg.root, reg.origin 或 reg.name 有值 ? {origin, name} : null)`
     - `rewriteSessionRegistrations`:逐个读 `sessions/*.json`,`root` 的 realpath(失败用 path.resolve)等于 roots 里任一个的 realpath 的,改写 `origin`、`name`、`project`、`writtenAt`;返回改写份数
     - `cleanupSessionRegistrations`:`sessions/` 下 mtime 超过 7 天(`7 * 24 * 3600_000` 定成文件内常量)的 `.json` 删掉;目录不在什么都不做;任何异常吞掉
  5. `data-location.ts`(C-5)
     - `findProjectRoot`:从 `path.resolve(start)` 往上,第一个 `isInitialized` 的目录;没有就再从起点往上找第一个含 `.git` 的目录;都没有 → null;深度上限 128(同 `resolveProjectRoot`)
     - 判定逻辑写在 `locateDataAtRoot(root)`、`ensureDataDirAtRoot(root)` 里(把 `path.resolve(root)` 直接当根);`locateData(start)`、`ensureDataDir(start)` 只做「`findProjectRoot(start)` 为 null → `unavailable: 'no-root'` 的位置 / null;否则转调 AtRoot 版」
     - `locateData`、`ensureDataDir` 及两个 AtRoot 版、`hasLegacyTables`、`missingDataMessage` 照 C-5 原文;显示名用 `projectDisplayName`,`<root>`、`<start>` 原样写绝对路径
     - 本地库路径在本文件里写成 `path.join(getCodeGraphDir(root), 'cgraphx.db')`(文件名定成本文件常量,注明与 `db/index.ts` 的 `DATABASE_FILENAME` 同值;不 import `db/index.ts`)
     - `hasLegacyTables`:本地库不在 → false;用 `db/sqlite-adapter` 的 `createDatabase` 打开,跑 `SELECT 1 FROM sqlite_master WHERE type = 'table' AND (name LIKE 'timeline\_%' ESCAPE '\' OR name LIKE 'task\_%' ESCAPE '\' OR name LIKE 'sync\_%' ESCAPE '\') LIMIT 1`,用完关闭;异常 → true
     - `readLocalProjectJson`:读 `getCodeGraphDir(root)/project.json`;不在、不是对象 → null;字段类型不对的按 null
     - `updateLocalProjectJson`:读出原对象(不在为 `{}`)、合并 patch、写回(临时文件 + rename);`getCodeGraphDir(root)` 不在时抛错(只给装过的目录写)
  6. `root-match.ts`(C-6):算法照现在 `src/core/replica/roots.ts` 的 `realDir` 缓存 + `walkUp` 逐级往上查表 + `findRoot` 先原样后 realpath;缓存上限 4096,超过整个清掉
  7. `directory.ts`:删掉 C-5 接管的部分后,文件头注释改成只讲本地 `.cgraphx/`(知识库、我的需求、副本登记、shared 链接、`project.json`);`resolveProjectRoot` 的注释保留
  8. `db/index.ts`:`getDatabasePath` 从 `../data-location` import `getDataDir`;文件头注释改写成「库路径按数据位置:旧库模式是本地 `.cgraphx/cgraphx.db`,其余是用户目录里的项目目录;知识库固定本地」
  9. `__tests__/setup-home.ts`:文件顶层用 `fs.mkdtempSync(path.join(os.tmpdir(), 'cgx-home-'))` 建临时目录,`process.env.HOME`、`process.env.USERPROFILE` 指过去(先记下原值);`afterAll` 里还原并 `fs.rmSync(临时目录, { recursive: true, force: true })`。setupFiles 每个测试文件跑一次,各测试文件各用各的临时 HOME;自己改 HOME 的测试(如 `__tests__/core/dbquery/config.test.ts`)照旧覆盖
  10. 既有测试:`__tests__/core/db/migrate.test.ts` 因 `dropLegacyGraphTables` 改走本地库而红时,只改准备数据的方式,断言意图不变
