# 功能方案: 数据按项目放用户目录(讨论稿 v2)

> 讨论稿，不是契约：人终确认的那一版由 `/dev-spec` 原样收录为 spec 第一节，之后以 spec 为准，本文件不再维护。
> 图用支持 PlantUML 的 Markdown 预览打开(IDEA:设置 → 语言和框架 → Markdown → 启用 PlantUML)。

**一句话**:原来同一个项目在本机的每个目录各记一份数据，只有 `/dev-start` 开的副本靠链接记回主目录，换个目录干活，日报、task、统计里就少一块;这次把 timeline、task、sync 的数据按项目放到用户目录，在项目的哪个目录干活都记进同一份里。

**功能清单**

| 编号 | 功能点 | 类别 | 从哪进 → 到哪去 | 一句话 |
|---|---|---|---|---|
| F1 | 同一项目的各个目录记到一起 | 核心 | 在项目的任一目录里开会话、提交 → 记进这个项目的数据(F3)→ 日报、task show、统计、web、平台上报 | 不管在 clone、worktree、副本还是手动复制的目录里干活，会话和提交都记到这个项目下，一个会话从哪个目录开的就整个记到那个项目;读的时候看到的是同一份，挪过目录的旧记录也照样换算 |
| F2 | 认项目、改项目 | 支撑 | 项目的任一目录里查、改 → F1 按改过的项目记 | 能查当前目录属于哪个项目、数据在哪、本机出现过哪些目录;认错了可以手动指定项目名称，指定成已有的名字就并进那个项目 |

| F5 | 卸载和清理 | 支撑 | 目录里 `cgraphx uninstall`、清理命令 → 卸这个目录、删某个项目的数据 | 在一个目录卸载只卸这个目录，项目的数据留着，同一个仓库别的目录的提交照样记;另给列出、删除项目数据的命令 |
| — | 跨机器合并数据 | 建议新增 ✂️ | — | 不做：数据只在本机 |
| — | 平台按规整后的地址认项目 | 边界外 | — | 不做：平台现在按 origin 原样认项目;本机一个项目只按一个地址报(K5),别的机器用另一种写法接的平台，平台上还是两个;要改归平台 |
| — | 拆掉版本流程 | 边界外 | — | 另立需求，排在这个之后;这个需求只做到副本的数据不再靠链接 |
| — | Claude Code 自己按路径存的会话和记忆 | 边界外 | — | 不归 cgraphx 管:`/resume` 列表、自动记忆照旧按目录分 |

### F1 同一项目的各个目录记到一起(核心)

现在：一个目录一份数据，只有 `/dev-start` 开的副本经链接记回主目录;同一个项目的另一份 clone、worktree、手动复制的目录各记各的，目录里没有 `.cgraphx/` 的一条不记;每条事件按它当时所在的目录找项目，会话在附加的工作目录里干活，就被拆进两个项目。这次会话按开始的目录、提交按仓库认出项目(K17、K18),哪个目录记的都进这个项目的数据，放在哪见 F3;一个目录的旧数据并过去之前(F4),它照旧记在原来的库里(K8)。项目怎么认(K1、K2)和 F2 共用，认错了到 F2 改。

### F4 旧数据并过去(支撑)

以下供 spec 使用，可不细读

**必须在 spec 前解决的问题**:无

后续阶段的决策：拆掉版本流程另立需求，排在这个之后;平台按规整后的地址认项目，归平台。

**已锁定技术约束**:数据放用户目录、按项目隔离(你定的,11-05);没有 origin 的项目、一个仓库里装了几个项目，都按项目名称认，名字一样就是同一个项目(你定的,11-05);会话按开始的目录认项目，提交按仓库认(你定的,11-05);旧数据在安装时并(`cgraphx upgrade` 装完新版自动跑 `install -y`,也算);拆掉版本流程另立需求，排在这个之后;知识库索引、「我的需求」留在各目录;hook 一次 5ms 上下的耗时不能明显变慢。

**留给 spec 的细节决策**:

- origin 怎么规整(ssh、https、`.git`、末尾 `/`、端口);项目名称记在哪(git 本地配置、目录里的文件，还是提交进仓库的文件),worktree、复制出来的目录怎么读到;一个仓库里装了几个项目时，项目名称默认怎么取;装的时候怎么查本机已经有这个名字的数据(K2)。
- 会话开始时认出项目根和项目标识，后面的 hook 怎么拿到(K17):存进轮次记录(那边实测 Node 调一次 `git remote get-url` 约 7.5ms,比整个 hook 还慢),轮次记录缺了、坏了时怎么降级;git 钩子(提交、合并)怎么取项目，一个仓库装了几个项目时怎么按改到的文件分(K18)。
- hook 每条都要判断这个目录的旧数据并过没有(K8),「并过」的记号放哪才不拖慢 hook。
- 用户目录的布局和目录名(K7);一个项目一个库文件，不用一个大库加项目列(版本流程 spec D18 否掉过按工作目录分区，每条查询都得带条件，漏一处就串)。
- 项目根怎么记、换算时怎么用(K4,取代现在按「主目录 + 登记过的副本」换算):只记仓库根或项目目录，不记会话 cd 进去的子目录;并过来的旧记录按并的那个目录和它登记过的副本补哪些根;每个根的最近一次活动(K16)怎么取。
- 旧库怎么并：事件 id 重排后,sync、task 的进度怎么换算(K12);按什么认「同一个会话的同一条事件」(K10);项目级配置怎么比、不一样时怎么列;并的时候有会话在写，怎么不丢、不重。
- 上报用的 origin 记在哪、什么时候定(K5);副本会话、终端会话的 id 现在也按 origin 算，跟着用这个地址。
- 副本：数据不再看 `.cgraphx/shared` 链接和登记;数据目录的取法怎么改;版本流程拆掉之前 `/dev-start` 开的副本照常能用。
- uninstall、`timeline uninstall --purge` 的新含义;怎么知道共用 git 钩子的目录还有没有装着的(K13);清理命令叫什么、放在哪个子命令下。
- cgraphx web 读哪个库;`CGRAPHX_DIR` 以后还管什么(本地 `.cgraphx/` 的目录名)。

**影响半径与风险**:HIGH——timeline、task、sync 和 db-query 配置全部换存放位置;本机已有的数据(主目录 5.8 万条事件)要在安装时并过去，并错就丢记录(K11 先备份);uninstall 的含义从「连数据一起删」变成「只卸这个目录」;名字一样就算同一个项目，两个不相干、都没有 origin 又恰好同名的目录会记到一起(K2 装的时候提示已有数据,F2 能改);会话按开始的目录认，在附加的工作目录里做的事只记在开始的那个项目，那边的日报里看不到(提交照样记到那边);hook 每条多一次「并过没有」的判断，不能拖慢。
