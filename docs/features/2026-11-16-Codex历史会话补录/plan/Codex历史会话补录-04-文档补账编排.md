# T-4：文档补账编排

> 产物: plan
> 依据: spec@7e9527f

- **目标**：让现有 doc-backfill 在收口前自动触发通用补录并传递状态，沿用既有产物与确认流程。
- **对应 spec 编号**：F1、F3、K4、K9、K10、D4、D10、D11。
- **强制引用**：无（仅修改技能模板与需求文档）。
- **涉及范围**：`assets/claude-template/skills/doc-backfill/SKILL.md`、`assets/claude-template/skills/doc-backfill/filler-prompt.md`、`docs/features/2026-11-16-Codex历史会话补录/` 顶层本需求方案与 spec、`docs/features/2026-11-16-Codex历史会话补录/plan/` 本计划文件。
- **必须严格执行**：C-1、C-4；不新建补录命令、不启动 board、不执行实际补账或修改已有档案；保持原有用户决策门槛和提交规则。
- **允许局部适配**：可调整技能文字的章节和上下文格式；不得更改 doc-backfill 输出范围、确认和串行约束。
- **具体要求**：
  1. 在调用收口前从需求项目目录运行既有 timeline 查询触发统一补录，捕获 C-1 的 stderr 标记与原因；补录结果随需求上下文传给 filler。无状态或查询失败当作覆盖不足，允许已有成功数据按 K8 使用，不静默显示完整。
  2. 按 C-4 调用 `$dev-end` 并把需求标识、spec、提交范围、已知说明、补录结果传入；其他两种产物仍调用既有单测技能，不凭 spec 声称已执行测试。
  3. 保留 Git 作者候选、用户勾选范围、缺失清单确认、已有文件不覆盖、无主 spec 提示、逐需求串行、sanity check 及每需求独立提交；以未选范围不参与齐全判断为准。
  4. 将本需求全部方案版本、spec、index 和四个任务文件作为本任务文档落盘范围；实现提交时精确纳入 T-4 提交范围，不能夹带其他需求或用户改动。
- **完成条件**：模板与 C-1/C-4 一致，输出引用的 skill 名存在；`npm run build` 可复制资产；既有测试不因改动变红。
- **提交点**：1 笔 `feat(skills): 接通文档补账历史会话`，仅包含上述 T-4 文件与本需求方案/spec/plan。
- **风险/注意事项**：补录可能部分成功或被关闭；不得把 stderr 没有标记当作成功，亦不得因此跳过需要用户确认的既有流程。
