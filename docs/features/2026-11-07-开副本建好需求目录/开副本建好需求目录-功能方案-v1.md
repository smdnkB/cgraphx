# 功能方案: 开副本建好需求目录(讨论稿 v1)

> 讨论稿,不是契约:人终确认的那一版由 `/dev-spec` 原样收录为 spec 第一节,之后以 spec 为准,本文件不再维护。
> 图用支持 PlantUML 的 Markdown 预览打开(IDEA:设置 → 语言和框架 → Markdown → 启用 PlantUML)。

**一句话**:原来主目录没有这个需求目录时副本里也不建,副本里的 /dev-clarify 看不到就按描述另起一个名字;这次开副本时在副本里把登记的那个需求目录建好,澄清稿照旧写在里面。

### F1 开副本时建好需求目录(核心)

和 /dev-clarify、/dev-spec、features 共用同一个需求目录名:它们按 `docs/features/<需求目录名>/` 这个目录认需求,名字来自副本登记里的 feature-id;这次不另起一套判断,只保证副本里这个目录存在。

现在:主目录 `docs/features/<需求目录名>/` 有没提交的讨论稿,才把文件连目录一起拷进副本;没有这个目录(还没澄清、还没写讨论稿)时副本里也不建。副本里的 /dev-clarify 列出 `docs/features/` 找不到这个需求,就按描述另起一个名字——副本登记「安装流程完善」,讨论稿写进了「安装默认勾选已配置的agent」,还随合并提交进了主目录,以后按需求目录找产物、列需求都对不上。

改后:每次开副本都在副本里建好 `docs/features/<需求目录名>/`,名字就是登记里的 feature-id;已存在就不动。目录是空的,不写占位文件;讨论稿写进去之后,这个目录才随文件出现在 git 里。建不出来就整次开副本失败回滚,不留下「副本开好了、需求目录还是没有」的状态。副本里 `features` 列需求会看到这一条(还没有产物),澄清完就有讨论稿。`/dev-start` 调的也是这条命令,skill 不用改。

| 编号 | 哪一步 | 怎么判定 | 算 / 不算(例子) | 依据 |
|---|---|---|---|---|
| K1 | 建哪个目录 | 副本根下 `docs/features/<feature-id>/`;feature-id 就是 `cgraphx replica create` 的第一个参数(登记里的 `featureId`),不是文件前缀,也不是分支名 | 传 `2026-11-07-安装流程完善` → 副本里建 `docs/features/2026-11-07-安装流程完善/`;不建 `安装流程完善/`,也不建 `docs/features/feat-安装流程完善/` | 登记的 `featureId`;沿用(拷需求文件用的就是同一个路径前缀) |
| K2 | 什么时候建、已存在时 | 每次开副本都建(新建分支、接上删副本留下的分支都算),在写登记之前;主目录那份在不在、里面有没有文件都不影响;已存在就不动,不覆盖、不清空 | 主目录有讨论稿、文件先拷进副本 → 目录本来就在,不动;主目录没有这个目录 → 建空目录 | `src/core/replica/create.ts:391-412`(开 worktree 之后、写登记之前);新定 |
| K3 | 空目录在 git 里 | 不写占位文件。git 不跟踪空目录,讨论稿写进去之后目录才随文件出现在提交里;空着的目录不出现在 `git status` 里 | 刚开完副本:`ls docs/features/<需求目录名>` 有;`git status` 看不出;写完讨论稿提交,提交里有这个目录 | 新定 |
| K4 | ① 建不出来 | 整次开副本失败并回滚:删 worktree、删这次新建的分支、登记不写,主目录不动;报错原文带路径和原因 | `docs/features` 被一个文件占着、权限不够 → 停下来报错,不留下半开的副本 | 回滚(`src/core/replica/create.ts:277`);新定(沿用回滚路径) |

🎭 体验变体(待你定):建不出来时 整次开副本失败回滚(图里画的这种,副本不会半开、目录保证在)vs 照旧开副本、只提示一句(副本照开,目录还是没有,今天的问题还在)

---

以下供 spec 使用,可不细读。

**必须在 spec 前解决的问题**:无

**已锁定技术约束**

- 只改 replica 一侧(程序),不往 dev-clarify、dev-spec 等开发 skill 里加流程性规则(用户声明)。
- 主目录不建、不动(用户声明):主目录没有这个需求目录是正常的,副本里建好即可。

**留给 spec 的细节决策**

- 建目录放在 `createReplica` 流程的哪一步(开 worktree 之后、写登记之前):放 `prepareDataDir` 里还是单独一步。
- 建不出来的错误码(`invalid_args` / 新增码)与 `--json` 输出、CLI 提示原文;要不要在 `CreateReplicaResult` 加字段、`printCreate` 加一行(dev-start 只转告 `warnings`、`movedFiles`,加字段才有回执;目录是保证不是结果,倾向不加)。
- 新建的目录不能记进 `movedFiles`(那个字段的含义是「从主目录移进副本的文件」)。
- 测试覆盖:主目录没有需求目录时副本里有空目录;目录已存在(带文件)时不动;建不出来(如 `docs/features` 是文件)时回滚、主目录不动、分支不留下。
- 程序行为变了,`docs/knowledge/需求副本.md` 里 replica create 的契约要补一句。

**影响半径与风险**:LOW——只多建一个空目录,不动 worktree、分支、登记和移文件的逻辑。已知边界:空目录在 git 里不可见,`git clean -fd`、手工删目录、某些清理空目录的工具会把它带走,之后又回到今天的问题;本次不防护,spec 写明即可。另一种漏建情形也一并覆盖:主目录有这个目录、但里面只有被忽略的文件(没有可带的),今天同样不建。主目录里本来就有一个空的需求目录时,开完副本它还在(现有逻辑只在移走文件后才删空的目录),不影响副本。

**现实约束清单**

| 现有实现 | 事实 |
|---|---|
| `cgraphx replica create` | `src/core/replica/create.ts:376` 入口;`featureId`、`prefix`、`branch` 已校验为单段目录名(`assertArgs`) |
| 拷需求文件 | `copyFeatureFiles`(`create.ts:299`)按 `docs/features/<featureId>/` 前缀拷没被跟踪的文件,父目录按需建,但不保证目录本身存在 |
| 移出主目录 | `moveOutOfMain`(`create.ts:337`)全部成功后才删主目录那份,并删掉因此变空的目录(含需求目录) |
| 回滚 | `rollback`(`create.ts:277`)删 worktree、删这次新建的分支、删登记文件;接上的旧分支留着 |
| 登记 | 主目录 `.cgraphx/replicas/<副本目录名>.json`,`featureId` 就是需求目录名 |
| features | `docs/features/<feature-id>/` 的存在性即需求的存在性;空目录算需求在、只是还没有产物 |
| dev-spec 第 0 步 | 已经写着「目录已由 clarify 讨论稿、`/dev-start` 建立 → 直接复用」,程序侧没做到,这次补上 |
