## 1. 背景与目标

### 1.1 背景(根因)

`db` / `docs` / `features` / `web` 四个子系统把「当前工作目录」直接当项目根(缺省值取裸 `process.cwd()`),去该目录下找 `.cgraphx/` 配置与数据。Claude Code 会话工作目录随 agent `cd` 漂移之后:

- `db query / schema / profiles`:子目录下找不到项目本地 `db-profiles.json`——要么静默降级到用户全局配置(项目本地优先语义失效),要么直接报 `No db-profiles.json found`;
- `db init`:子目录下误报「未初始化,先跑 `cgraphx install`」;
- `docs` 各命令:对子目录做索引/查询,拿不到真根的 `docs/knowledge/` 与知识库数据;且 `DatabaseConnection.open` 对不存在的路径**现造目录与文件**——子目录下每跑一次(哪怕只读查询)就散落一个空的 `.cgraphx/cgraphx.db`(第二症状:不止找不到,还会丢垃圾);
- `features list / sync`:从子目录派生出空视图,`sync` 把个人索引写到错误位置;
- `web`:从子目录启动,服务的是错误目录,知识库/时间线数据缺失。

这是 2026-08-13「timeline项目根回溯修复」的挂账遗留项:该 spec §1.4 明确「docs / features 子系统的同类 cwd 默认值问题本次不动,已知相邻问题,后续另开」,web 读侧也仅记录未改。本次还账。

### 1.2 目标

把 2026-08-13 已实现、已验收的项目根解析规则拉齐到 `db` / `docs` / `features` / `web` 的缺省项目根解析:任意已初始化项目的子目录里运行这四个子系统的命令,读写都落到真根;并从修复之日起不再产生新的子目录散落。

### 1.3 范围(包含)

- `db`:query / schema / profiles / init 四个命令的缺省根解析;`init` 解析到真根后把 `db-profiles.json` 写入真根的 `.cgraphx/`;
- `docs`:全部命令的缺省根解析(未显式传 `[project-path]` 时);
- `features`:`list` / `sync` 的缺省根解析;
- `web`:未显式传 `[project-path]` 时的缺省根解析。

### 1.4 非目标(明确排除)

- 顶层 `cgraphx install` / `upgrade` 不动——保持「在哪个目录就安装/刷新到哪个目录」;
- `timeline` 不动(已修复);
- 显式传参路径一律不动:`[project-path]` / `--path` 位置参数、`CGRAPHX_DB_PROFILES_PATH` 环境变量、`~/.cgraphx/` 用户全局兜底,加载链与优先级语义原样;
- 不改三层配置加载链本身(env → project-local → user-global),只改「projectRoot 从哪来」;
- 不支持已初始化祖先下嵌套初始化(沿用 2026-08-13 已锁模型);
- **不清理存量散落**(见 3.7)。

## 2. 术语

沿用 2026-08-13 spec §2,补充两条:

- **解析起点**:本次四子系统命令未显式传路径时,取 `process.cwd()`;显式传参不经过本解析。
- **已初始化**:某目录下 `.cgraphx/cgraphx.db` 文件存在(裸 `.cgraphx/` 目录不算)。
- **项目根**:解析结果目录;一个 `.cgraphx/cgraphx.db` 即一个项目根。
- **就近优先**:从起点向上,第一个命中的已初始化目录即根;monorepo 子项目根不被仓库级根吞并。
- **散落空库**:修复前 `docs` 命令在子目录现造的空 `.cgraphx/cgraphx.db`(含 markdown schema、无数据)。

## 3. 已确认规格

### 3.1 根解析规则(核心,逐条继承 2026-08-13 §3.1)

1. 从解析起点所在目录开始,**逐级向上**;
2. 第一个满足「已初始化」的目录即项目根,**就近优先**;
3. 到文件系统根仍无命中 → **回退解析起点本身**,行为与现状一致(未初始化项目零变化);
4. 以 DB 文件存在(而非裸 `.cgraphx/` 目录)为标记;
5. 解析过程中任何 IO/异常按「未命中」处理,**绝不向上抛出**——最坏退化为旧版行为(把起点当根),修复本身不得使任何命令比现状更糟。

### 3.2 db 子系统

- `query` / `schema` / `profiles` / `init` 的缺省项目根 = 解析结果;
- 效果:子目录下运行读到真根的 `.cgraphx/db-profiles.json`,三层配置的**项目本地优先语义恢复**(同名 profile 项目本地覆盖用户全局);
- `db init` 跟随解析结果:子目录下运行不再误报未初始化,模板写入真根的 `.cgraphx/db-profiles.json`(幂等、`--force` 覆盖等既有语义不变);
- `CGRAPHX_DB_PROFILES_PATH` 设置时仍只读该文件,与根解析无关(既有优先级不变)。

### 3.3 docs 子系统

- 所有命令未传 `[project-path]` 时,缺省根 = 解析结果;显式传参 → `path.resolve` 原样使用,不解析;
- 效果:子目录下索引/查询作用于真根的 `docs/knowledge/` 与知识库数据;**子目录下不再现造 `.cgraphx/`**(解析到真根后,读写落在真根)。

### 3.4 features 子系统

- `list` / `sync` 未传 `[project-path]` 时,缺省根 = 解析结果;
- 效果:子目录下 `list` 派生真根的 `docs/features/` 视图;`sync` 把 `.cgraphx/my-features.md` 写入真根。

### 3.5 web 子系统

- 未传 `[project-path]` 时,缺省根 = 解析结果;显式传参原样;
- 效果:子目录下 `cgraphx web` 服务真根的知识库与时间线数据。

### 3.6 异常与降级

继承 3.1 第 5 条:解析失败(权限、坏目录等)→ 回退起点,命令按现状语义继续(该报错的照旧报错),解析环节自身不产生新的非零退出码、不产生新错误形态。

### 3.7 已知边界:存量散落空库(业务决策:不清理)

- 事实:修复前从子目录跑 `docs` 命令会在该子目录现造空 `.cgraphx/cgraphx.db`(代码路径确认,本环境排查**未发现实际个例**);
- 风险:回溯以「cgraphx.db 存在」为标记且就近优先——**若某项目祖先链上已存在这种散落空库,修复后会被解析为项目根**,命令读到空知识库(静默错指);
- 决策(已拍板):**本次不清理存量散落**。理由:无实际个例;修复后已初始化项目内不会再产生新散落;清理签名(区分空库与合法 monorepo 子项目根)需打开 DB 查表,成本高且有误删风险;
- 义务:该风险链在本节留档;日后若真实出现,另开需求处理(届时签名可参照「`.cgraphx/` 仅含 cgraphx.db 且库内仅 `markdown_*` 表、无 `timeline_*` 表」方向设计,届时再拍板)。

## 4. 关键约束

- **兼容性(零变化三场景)**:① 未初始化项目(祖先链无任何命中)、② 从项目根本目录运行、③ 显式传参(`[project-path]` / `CGRAPHX_DB_PROFILES_PATH` / 用户全局配置链)——三类场景行为与现状完全一致;
- 分层:共享解析能力落在 `src/core/`,`src/web` 可依赖之;`core` 不得反向依赖 `cli` / `web`;
- 解析必须是**纯目录存在性检查**——不得打开/读取 DB 内容、不得引入文件内容嗅探(性能,且与 3.7「不查表」决策一致);
- 不引入新的外部依赖;
- `timeline` 既有解析行为不得退化(其解析函数如被挪动/复用,既有测试必须继续通过)。

## 5. Plan 编写约束

- 根解析必须收敛为**单一共享实现**,四子系统接入复用,不得各自实现副本;与 `timeline` 现有 `resolveTimelineProjectRoot` 的关系(复用/提取/改名/放置)由 plan 定,但规则必须是 3.1 这一份,不允许出现第二套语义;
- 各子系统的接入点、错误信息是否展示解析后的根路径、测试组织,由 plan 定;
- 测试落在 `__tests__/core/<子系统>/`(与 `src/core/` 镜像),风格与现有测试一致。

## 6. 验收标准与测试关注点

1. 已初始化项目 `a/`(`a/.cgraphx/cgraphx.db` + `db-profiles.json`),cwd = `a/b/c` → `db query / schema / profiles` 读到 `a` 的项目本地配置;与 `~/.cgraphx/` 同名 profile 并存时项目本地覆盖全局(合并语义恢复);
2. cwd = `a/b/c` 运行 `cgraphx db init` → 模板写入 `a/.cgraphx/db-profiles.json`;`a/b`、`a/b/c` 下不新增任何 `.cgraphx/`;
3. cwd = `a/b/c` 运行 `docs` 各命令(不传路径)→ 作用于 `a` 的知识库与数据;子目录下不再新产生 `.cgraphx/`;
4. cwd = `a/b/c` 运行 `features list / sync` → 派生/写入均落在 `a`;
5. cwd = `a/b/c` 运行 `cgraphx web`(不传路径)→ 服务 `a`;
6. monorepo 就近优先:`a/b/.cgraphx/cgraphx.db` 与 `a/.cgraphx/cgraphx.db` 并存,cwd = `a/b/c` → 解析到 `a/b`;
7. 未初始化(祖先链无命中)→ 回退 cwd,各子系统行为与现状完全一致;
8. 显式传参(`[project-path]` / `CGRAPHX_DB_PROFILES_PATH`)→ 不经过解析,行为与现状完全一致;
9. 解析环节异常(如不可读目录)→ 回退起点,命令行为不劣于现状;
10. 四个子系统与 `timeline` 的既有测试全部保持通过(回归)。

## 7. 不可留到实现期的决策

业务决策已全部锁定:修复范围 = 四子系统;解析规则逐条继承 2026-08-13(标记 = DB 文件、就近优先、无命中回退起点、异常不抛出);`db init` 落真根;显式传参路径不动;顶层 `install` / `upgrade` 不纳入;不清理存量散落空库(3.7 留档)。实现手段(共享函数形态与放置、与 `resolveTimelineProjectRoot` 的整合方式、接入点、错误文案、测试组织)归 plan。
