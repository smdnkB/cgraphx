## 功能方案

> 小需求,没走讨论稿;方案在对话里给用户看过,用户 11-07 确认「发完版本自动退出」「一起挪」。

**一句话**:原来版本发完、回到 main 后「按版本走」的记号还在,`/dev-merge` 每次都停下问要不要开下个版本,tag 也要等下次 `/release-start` 才打在当时的 main 上;这次改成一个版本发完就退出版本流程,tag 在「发」的那一步打在发布的合并提交上,下个版本要按版本走由用户自己 `/release-start`。

**功能清单**

| 编号 | 功能点 | 类别 | 从哪进 → 到哪去 | 一句话 |
|---|---|---|---|---|
| F1 | 发版时打 tag、退出版本流程 | 核心 | `/release-review` 说「发」→ 合入主干 | 合入主干后在合并提交上打 `v<版本号>`,卸掉提交拦截、清掉「按版本走」的记号 |
| F2 | 开版本只开版本 | 支撑 | `/release-start` → 版本分支 | 不再打 tag,只拉版本分支、装提交拦截、记下「按版本走」 |
| F3 | 主干上合入不再追问 | 支撑 | 主目录 `/dev-merge <需求>` → 合入 | 版本都发完了就照默认流程合进 main;只有版本做到一半、主目录切回 main 时才问 |

### F1 发版时打 tag、退出版本流程(核心)

行为链:在版本分支上 `/release-review` → 说「发」→ 合入主干 → 合并提交上打 `v2.0.11`(已有就不重打,说出在哪个提交上)→ 卸掉版本分支的提交拦截、清掉记号 → 「版本流程已退出,main 上照默认流程开发」→ 问删不删已合入的副本 → 「下个版本还要按版本走就跑 /release-start」。

| 编号 | 哪一步 | 怎么判定 | 算 / 不算(例子) | 依据 |
|---|---|---|---|---|
| K1 | 打 tag · 版本号和位置 | 版本号取合入后 `package.json` 的 version,打在这次发版的合并提交上 | 算:dev/2.0.11 合入 main 的合并提交打 `v2.0.11`。不算:已有 `v2.0.11` 时不重打 | 报告「版本号」一节已核过版本号;沿用 release-start 原来的带说明 tag(`-a -m "发布 2.0.11"`) |

### F2 开版本只开版本(支撑)

行为链:在 main 上 `/release-start` → 核对上个版本都已发 → 定下个版本号 → 拉 `dev/2.0.11` → 装提交拦截、记下「按版本走」→ 「开始 2.0.11」。

### F3 主干上合入不再追问(支撑)

行为链:主目录在 main 上 `/dev-merge 订单导出` → 记号在,而且有没合进 main 的版本分支 → 停下问(切到版本分支再合 / 这次合进 main / 不再按版本走);记号在、但版本分支都已合进 main(旧版 cgraphx 发版后留下的)→ 清掉记号,说一句「上个版本已发完,版本流程已退出」,照常合进 main;记号不在 → 照常合进 main。

## 怎么实现

只改 skill 文字和说明文档,不改程序:`cgraphx release guard --remove` 已经能卸掉拦截、清掉两个记号。

| # | 决策 | 选择 | 没选的(为什么) | 理由(依据) | 影响面 |
|---|---|---|---|---|---|
| D1 | 退出放在哪 | `/release-review` 合入主干、打完 tag 后跑 `cgraphx release guard --remove --json` | 程序在合入时自动清——合入是 skill 里的 git 命令,程序看不到 | `src/core/release/guard.ts` 的 `removeReleaseGuard` | release-review 多两步 |
| D2 | 旧记号怎么办 | `/dev-merge` 在 main 上看到记号、但没有没发的版本分支 → 当成旧版留下的,清掉后照常合入,不问 | 一律停下问——升级前发过版的项目每次都要回答一遍 | 版本分支是否已合进主干:`git merge-base --is-ancestor` | dev-merge 第 2 步 |
| D3 | tag 的红线 | release-review 改成「tag 只打在本地,已有的不重打」;release-start 改成「不打 tag」 | 两边都能打——会打两次或打在不同提交上 | 原 release-start 第 5 步 | 两个 skill 的红线 |

### 全局约束

- 不推送 tag 和分支,不发布。
- 版本做到一半主动退出的说法照旧:切回主干,`/dev-merge` 停下问时回答「不再按版本走」。
