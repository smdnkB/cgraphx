# 规格说明: cgraphx web 开发时间线浏览

> feature-id: 2026-07-30-cgraphx-web时间线浏览
> 状态: 已确认
> 负责人: liulongfei
> 日期: 2026-07-30

> **拆分说明 / 依赖声明**:本需求与《cgraphx-web知识库浏览》(feature-id: 2026-07-30-cgraphx-web知识库浏览)原为同一需求「cgraphx web 本地浏览服务」,为独立演进与独立实现而拆分。**web 服务基座**(命令接口、启动行为、localhost 安全边界、应用壳与全局错误态、分层约束、时区显示总口径)由知识库 spec 定义,本 spec 直接引用、不重复;**若单独实现本 spec,须先按知识库 spec §3.1 / §3.2 / §5.1 / §6 落地服务基座**。

## 1. 目标与范围

### 1.1 目标

在 `cgraphx web` 本地服务中提供**开发时间线页面**:让团队成员在浏览器里浏览目标项目的 Claude Code 开发事件流(timeline 子系统经五个隐藏 hook 记录的 `timeline_*` 事件),支持多维过滤、按天分组、单事件 payload 原文查看,以及一行式当日概况。体验定位为内部产品级,设计基线见已确认的交互设计稿。

### 1.2 包含范围

- 开发时间线页面:概况数据条、过滤器(时间范围/事件类型/工具/文件/会话)、按天分组的事件流、单事件 payload 展开;
- 时间线相关的全部只读查询,经 timeline 子系统**现有**公共门面(`src/core/timeline/index.ts` 已导出 `queryEvents` / `getEventById` / `getEventStats` / `getSessionStats` 等)。

### 1.3 明确非目标

| 非目标 | 说明 |
|---|---|
| 聚合统计视图 | 不做独立的统计页、不做按维度 groupBy 的聚合浏览。页面顶部的**一行概况数据条**(今日事件数/活跃会话数/最常用工具/近 7 日事件量柱图)在范围内,独立统计页不在 |
| 会话列表视图 | 不做以会话为主角的列表/详情页;会话仅作为过滤维度存在 |
| 叙事报告 | 日报/周报/月报/阶段总结仍归 developer-timeline skill(AI 生成),web 只呈现原始事件数据 |
| 任何写操作 | 不触发 timeline install/uninstall、不写 hook、不删改事件;只读口径与基座一致(不写 DB、不写文件) |

## 2. 术语与业务对象

| 对象 | 定义 |
|---|---|
| timeline 事件 | Claude Code hook 记录的开发事件,5 种类型:`user_prompt`(用户输入)/ `pre_tool_use`(工具调用前)/ `post_tool_use`(工具调用后)/ `stop`(会话轮次结束)/ `git_commit`(提交) |
| payload 原文 | 事件附带的结构化数据:prompt 文本(`prompt_text`)、工具名与参数(`tool_name` / `tool_args`)、工具结果摘要、提交信息(`commit_hash` / `commit_message` / `commit_files`)、耗时等。**入库时已按 timeline 记录层契约序列化并截断**(见 `src/core/timeline/` 记录侧实现),web 原样展示,不还原、不补全 |
| 会话(session) | 一次 Claude Code 会话,由 `session_id` 标识;同一会话的事件经 `turn_id` 组织为轮次 |

## 3. 系统行为:开发时间线页

### 3.1 概况数据条

页面顶部一行概况,口径全部基于**浏览器本地时区**(基座 §4.2 全站时区口径):

- **今日事件数**:本地当天 0 点起的事件总数;
- **今日活跃会话数**:本地当天出现事件的 session 去重数;
- **今日最常用工具**:当天 `tool_name` 出现次数最多者(含次数);当天无工具事件时优雅降级(呈现占位而非报错);
- **近 7 日事件量柱图**:按本地日期分组的最近 7 天每天事件数;柱可悬停查看具体数值。

### 3.2 过滤器

| 维度 | 行为 |
|---|---|
| 时间范围 | 「今天」(默认)/「近 7 天」两个快速切换;自定义时间范围本次不做 |
| 事件类型 | **多选**,5 种类型可任意组合,显示标签:Prompt(user_prompt)/ 工具调用(pre_tool_use)/ 工具完成(post_tool_use)/ Stop(stop)/ Git 提交(git_commit);全不选 = 不过滤(等价全选) |
| 工具 | 按工具名过滤(对应现有查询 `tool` 维度的**精确匹配**口径);入口形态(独立输入/下拉/并入搜索)由 plan 定 |
| 文件 | 按文件路径片段过滤(对应现有 `file` 维度的**子串匹配**口径,匹配 tool_args + commit_files);入口形态由 plan 定 |
| 会话 | 按 session 定位该会话全部事件(对应 `session` 维度);入口形态由 plan 定 |

各维度可组合;激活条件的呈现与清除机制沿用基座应用壳的筛选交互约定(知识库 spec §3.3 的 pill 模式)。

### 3.3 事件流

- **按本地日期分组**:今天 / 昨天 / 具体日期(如"7月28日 周二"),各组标题带该组条数;
- **事件行**:时间(本地时区,精确到秒)、类型标记(5 种类型各有视觉区分)、工具名(工具类事件)、关联路径、一行摘要(如"exit 0 · 42 passed"、提交 message、prompt 截断预览);
- **排序**:组内按时间倒序(最新在上);
- **单事件详情**:带 payload 的事件行可展开,查看 **payload 原文**——JSON 原样呈现(语法着色即可),不做结构化二次解读、不翻译字段名;无 payload 细节的事件(如 stop)不呈现展开入口;
- **截断提示**:事件入库时 `tool_args` 等字段可能已被记录层截断(§2),展开内容即最终内容,web 不暗示"有更多内容可加载";
- 单次查询上限沿用现有 `queryEvents` 契约(默认 100、最大 10000);时间线事件量大时的浏览全量手段(分页/加载更多/收窄时间窗提示)由 plan 定,约束与知识库一致:**不静默截断,用户必须能感知还有更多**。

### 3.4 空状态

- 今天 0 事件:空状态文案区分于"筛选无匹配";
- 全库 0 事件(从未安装/使用 hooks):引导运行 `cgraphx timeline install`,说明事件由 timeline hooks 自动记录;
- 筛选组合 0 匹配:空状态 + 重置筛选入口。

## 4. 数据与口径

- **数据来源**:只读 `timeline_*` 表,经 timeline 子系统现有公共门面;不新建查询层、不复刻查询逻辑;
- **时区**:事件时间 DB 存 UTC ISO 8601(不变),界面按本地时区呈现;"今天"判定、按天分组均按**本地日期**计算(与基座 §4.2 一致);
- **新鲜度**:无 SLA;hook 持续写入,web 查询拿到的是查询时刻的快照;用户刷新即见新事件,不做实时推送(实时推送属手段,若有也仅为体验优化,不产生新的业务义务);
- **幂等**:读请求天然幂等。

## 5. 安全:payload 不脱敏

事件 payload 含用户 prompt 原文、工具参数、提交内容等,可能包含敏感信息(凭据片段、内部路径等)。**web 层不做二次脱敏**——脱敏会破坏"事件流原样可审"的核心价值;安全模型完全依赖基座的 localhost 访问边界(知识库 spec §5.1)。此决策与"仅 localhost、不做 LAN 暴露"绑定:若未来放开访问边界,脱敏须重新评审。

## 6. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 全库 0 事件 | 空状态 + 引导 `cgraphx timeline install`(§3.4) |
| 筛选 0 匹配 | 空状态 + 重置入口,文案与"0 事件"区分 |
| DB 读取失败 / 库损坏 | 页面级错误态(沿用基座 §3.2 全局错误态) |
| 单事件不存在(按 ID 找不到) | "未找到"状态 + 返回事件流入口 |
| 事件量超单次查询上限 | 感知"还有更多" + 浏览全量手段(§3.3) |
| payload 字段缺失/畸形 JSON | 优雅降级:原文展示失败时呈现可读的占位提示,不崩溃(记录层已保证序列化,此为兜底) |

## 7. 验收标准与测试关注点

**验收**(业务可观察):

1. 时间线页概况数据条四项数值(今日事件/活跃会话/最常用工具/近 7 日柱图)与 DB 可核对,时间按浏览器本地时区计算;
2. 今天/近 7 天切换、5 类型多选组合、工具/文件/会话过滤均可用,组合过滤结果正确;
3. 事件流按本地日期分组、组内倒序;带 payload 事件可展开看 JSON 原文,与库中存储一致(含已截断字段原样呈现);
4. §6 全部异常场景行为符合描述;
5. CLI 回归:`__tests__/core/timeline/` 全绿,`cgraphx timeline` 命令行为零变化;
6. 只读契约:任何 web 请求不产生 DB 写入、不产生文件写入。

**测试关注点**:跨时区行为通过派生带显式 `TZ` 的子进程验证(仓库既有约定,见 `__tests__/core/timeline/store.timezone.test.ts`;不为本地时区改 TZ 处理逻辑);"今天"边界(本地 0 点前后事件的归属);类型多选的全集/空集等价性;payload 畸形 JSON 兜底。

## 8. Plan 编写约束

- **复用现有门面**:timeline 读侧必须经 `src/core/timeline/index.ts` 已导出的查询能力(`queryEvents` / `getEventById` / `getEventStats` / `getSessionStats` / `resolveTimeBound`),不新建查询层、不改记录侧(hook / recorder / store 写入路径不在本需求范围);
- **分层铁律**(2.0-spec §3.1):页面逻辑在 `src/web/`,只依赖 core;
- **类型多选与单值过滤维度的桥接**:现有 `TimelineQueryFilter.type` 为单值,多选组合如何在 web 层实现(多次查询合并 / 门面扩展 / 其他)由 plan 论证;若扩展门面,不得破坏 CLI `timeline query` 现有行为,以 `__tests__/core/timeline/` 为基线;
- **不引入 chalk**;前端技术形态随基座 spec 的 plan 决策(若两个需求同一轮实现,共用同一套前端基建)。

## 9. 不可留到实现期的决策

1. **能力面**:事件流(时间/类型/工具/文件/会话过滤)+ 单事件 payload 详情 + 概况数据条;不做独立统计页、不做会话视图、不做叙事报告;
2. **payload 原样展示、不脱敏**(与 localhost 边界绑定,§5);
3. **时区口径**:本地时区显示、按本地日期分组、按本地日期判定"今天";
4. **5 种事件类型的显示标签**(§3.2)与组内倒序排列;
5. **截断即最终内容**:不暗示 payload 有更多内容可加载;
6. **不静默截断**:超查询上限时用户必须能感知还有更多;
7. **CLI 兼容契约**:`cgraphx timeline` 现有命令行为零变化,既有测试为基线。

## 10. 待确认项

无阻塞项。plan 范畴:工具/文件/会话过滤的入口形态、事件量过大的浏览手段(分页/加载更多/收窄时间窗)、概况数据条的刷新时机、与知识库需求同轮实现时的前端基建共用方案。
