# 规格说明: cgraphx web 数据库入口激活为模型知识库预览

> feature-id: 2026-09-16-cgraphx-web数据库预览
> 负责人: liulongfei
> 日期: 2026-09-16

> **依赖声明**:本需求依赖《cgraphx-web知识库浏览》(feature-id: 2026-07-30-cgraphx-web知识库浏览)定义的**服务基座**——命令接口、启动预检、localhost 安全边界、应用壳与全局错误态、分层约束、时区显示总口径、路径边界与只读契约的总口径。本 spec 直接引用、不重复基座条款;若单独实现,须先按知识库 spec §3.1 / §3.2 / §5.1 / §5.2 / §6 落地基座。本需求**不改动基座机制**,仅激活基座应用壳中预留的第三个导航入口。

> **与基座非目标的关系**:知识库 spec §1.3 将「db(dbquery)子系统对接——涉及凭据与只读安全模型」列为非目标,导航中第三入口以"后续"灰置占位。本需求**不是**该非目标的实现——本需求预览的是 `docs/schema-knowledge/` 下的**本地 DDL 知识文件**,纯文件系统读取,不连接数据库、不涉及凭据与只读安全模型。连库查询仍是未决项,另议。

## 1. 目标与范围

### 1.1 目标

激活 cgraphx web 应用壳侧栏第三个导航入口(现"数据库",灰置占位),提供目标项目 `docs/schema-knowledge/` 模型知识库的**本地、只读、面向浏览器**的预览:浏览各工程的表清单、单表 DDL 全文(含团队沉淀的 DISCOVERED 块),以及跨表聚合的「经验沉淀」统一视图。让团队成员在浏览器里直接看到 export-table-ddl 导出的 DDL 与 db-query 探索回写经验,而不必逐文件打开编辑器。

体验定位为内部产品级,与知识库/时间线页同档:空态、错误态齐全,视觉整洁。

### 1.2 包含范围

- 第三导航入口激活(从灰置占位变为可点击链接);
- schema 模块下三个视图:
  1. **工程列表页**:列出 `docs/schema-knowledge/` 下所有工程目录;
  2. **表清单页**:渲染某工程的 `INDEX.md` 表清单(过滤后);
  3. **单表 DDL 详情页**:渲染该表 `ddl/<table>.sql` 全文,DDL 本体与 DISCOVERED 块分区呈现;
  4. **经验沉淀页**:扫描当前工程所有 `ddl/*.sql`,提取 DISCOVERED 块,按标签跨表聚合呈现。
- schema 模块相关的一切只读查询,纯文件系统派生,**不经 DB、不连库**。

### 1.3 明确非目标

| 非目标 | 说明 |
|---|---|
| 连接数据库 | 不连接任何 MySQL/PostgreSQL,不读 `.cgraphx/db-profiles.json`,不调 core/dbquery 门面。连库查询属未决项,另议 |
| DDL 结构化解析 | 不解析 DDL 语句为字段表/索引表/约束表。不写跨 MySQL/PG 方言的 SQL DDL tokenizer。DDL 本体原文直出 |
| SQL 语法高亮 | 不引入语法高亮(会引入前端依赖/构建链,与包"无原生依赖、无 wasm、随单包 npm 分发"现状冲突) |
| 跨工程全局搜表 | 不提供跨工程的表名搜索。表在工程内定位,同名表跨工程由工程前缀区分 |
| 跨工程经验聚合 | 经验沉淀页仅扫描当前工程内的 DISCOVERED 块,不跨工程聚合 |
| pending-comments.sql 呈现 | 根级 `_pending-comments.sql` 与工程级 `pending-comments.sql` 均不在 web 呈现(不在 agent 读路径上,与 db-query skill 口径一致) |
| 写操作 | 不触发 export、不重建 DDL、不写 DB、不写源文件、不应用 schema。只读口径与基座一致 |
| 对外 HTTP API 契约 | 服务对象是人(浏览器),不为程序/agent 消费设计稳定 API,不承诺接口兼容性 |
| LAN 暴露与多用户 | 仅 localhost,无鉴权、无会话、无用户概念(基座 §5.1) |

## 2. 术语与业务对象

| 对象 | 定义 |
|---|---|
| 工程目录 | `docs/schema-knowledge/<工程名>/`,一个数据库 profile 对应一个目录(如 `zqassis-service/`、`flowable-zqassis-service/`)。工程名 = 目录名 |
| INDEX.md | 工程目录下的表清单文件:表名 + 表注释 + 状态(✓ / missing)。是表清单页的元数据事实源 |
| DDL 文件 | 工程目录下 `ddl/<table>.sql`,内容为 `CREATE TABLE ...` + `COMMENT ON ...` 语句 + 末尾可选的 DISCOVERED 块 |
| DISCOVERED 块 | DDL 文件末尾 `-- === DISCOVERED (db-query 探索补充,非 DB 原生) ===` 与 `-- === END DISCOVERED ===` 之间的内容,团队沉淀的隐式知识。行以 `-- [标签]` 前缀组织(标签见下) |
| 经验标签 | DISCOVERED 块内 `-- [标签]` 前缀的类别:`[定位]` / `[关系]` / `[陷阱]` / `[样本]` / `[索引]` / `[性能]`。经验沉淀页按此聚合 |
| missing 表 | INDEX.md 中状态为 missing(表中不存在)的表项——export 时从信息_schema误采的噪声,无对应 ddl 文件 |

**易混辨析**:「DDL 本体」指 CREATE TABLE / COMMENT ON 语句(数据库原生结构);「DISCOVERED 块」是 db-query 探索补充的非原生内容,二者在同一 .sql 文件内但语义不同,web 分区呈现。「schema-knowledge 模型知识库」是本地文件产物,「数据库」是远端库——web 预览前者不连后者。

## 3. 系统行为

### 3.1 第三导航入口激活【基座应用壳改动,仅此一处】

- 应用壳侧栏第三个入口从灰置占位(`href: null`,"后续"不可点)变为可点击链接,指向 schema 模块首页(工程列表页;单工程时直达表清单页,见 §3.2);
- 导航文案、图标、路由路径命名由 plan 定(基座 layout.ts 的 navItem 已支持 `href` 非空即渲染为可点击链接,本需求仅改第三入口的 `href` 与文案,不动 navItem 机制);
- 基座其他机制(预检、回环绑定、错误态、静态资产、时区口径)一律不动。

### 3.2 工程列表页

| 场景 | 行为 |
|---|---|
| 多工程 | 列出 `docs/schema-knowledge/` 下所有工程目录,每项展示工程名 + 表数量(从 INDEX.md 统计 ✓ 状态表数) + 注释摘要(可选);点击进入该工程表清单页 |
| 单工程 | 自动折叠,跳过工程列表页直达该工程的表清单页(避免单项列表空转) |
| 零工程 | `docs/schema-knowledge/` 目录存在但无工程子目录 → 空状态,引导运行 export-table-ddl skill 建基线(见 §3.6) |
| 目录不存在 | 目标项目无 `docs/schema-knowledge/` 目录 → 空状态(同上口径),第三入口仍可点 |

### 3.3 表清单页

- 渲染当前工程的 `INDEX.md`:表名 + 表注释 + 状态;
- **过滤 missing 表**:只呈现 ✓ 状态(有 ddl 文件)的表;missing 表(表中不存在)不呈现(§1.3 / §11);
- 表项按 INDEX.md 原序或按表名排列(由 plan 定);
- 点击表项进入该表 DDL 详情页;
- 工程内是否提供表名搜索/分页(131 张表)由 plan 定,但**不跨工程**(§1.3);
- 页面提供进入「经验沉淀页」的入口(同工程作用域)。

### 3.4 单表 DDL 详情页

- **数据源**:该工程 `ddl/<table>.sql` 文件当前内容;
- **DDL 本体**:`CREATE TABLE` + `COMMENT ON` 等语句,**原文转义直出**于 `<pre>` 区块,不解析、不高亮、不重排;
- **DISCOVERED 块分区**:若文件含 DISCOVERED 块,以视觉分区(背景色/左边框等,plan 定)与 DDL 本体隔开,块内原文呈现;无 DISCOVERED 块则不渲染该分区;
- **文件缺失**:ddl 文件不存在(INDEX.md 标 ✓ 但文件被删)→ 详情页呈现"DDL 文件缺失"提示 + 返回表清单入口,HTTP 200,不报错退出(与基座 §8 源文件缺失口径同构);
- **路径边界(硬契约,§5.2)**:ddl 文件路径**只从工程目录扫描结果解析**(工程名 + 表名 → `docs/schema-knowledge/<工程>/ddl/<表>.sql`),路由不接受任意文件路径参数;
- 详情页不存在的操作:编辑、重跑 export、写 DB 等一切写入口。

### 3.5 经验沉淀页

- **扫描范围**:当前工程目录下所有 `ddl/*.sql`;
- **提取**:解析每个 DDL 文件的 DISCOVERED 块(边界:`-- === DISCOVERED ... ===` 至 `-- === END DISCOVERED ===`),提取块内 `-- [标签]` 前缀行;
- **聚合维度**:按标签 `[定位]` / `[关系]` / `[陷阱]` / `[样本]` / `[索引]` / `[性能]` 分区,每条经验附**归属表名**(可点击跳转该表 DDL 详情页);
- **标签解析边界(§5.3)**:仅识别 DISCOVERED 块内行首的 `-- [标签]` 前缀,用于聚合索引;**不解析 DDL 语句**,不还原标签结构;
- **容错**:无标签前缀的行 / DISCOVERED 块格式异常 / 标签非上述六类 → 优雅降级(归入"其他"或原样保留,plan 定),不崩、不报错;
- **无经验**:当前工程所有 ddl 文件均无 DISCOVERED 块 → 空状态,提示"暂无探索沉淀的经验"(与"全库为空"文案区分);
- 工程内聚合,**不跨工程**(§1.3)。

### 3.6 空状态与引导

- `docs/schema-knowledge/` 目录不存在 / 无工程子目录 → 空状态页,提示"未导出 schema-knowledge" + 引导运行 export-table-ddl skill 建基线(与知识库空态引导 `docs index` 同构);
- 工程存在但 INDEX.md 缺失/损坏 → 该工程项呈现降级提示(不崩;具体降级形态 plan 定);
- 空状态与"筛选 0 命中"等其它空态文案严格区分。

## 4. 数据、状态与口径

### 4.1 读写的数据

| 数据 | 访问方式 |
|---|---|
| `docs/schema-knowledge/<工程>/INDEX.md` | 只读文件,表清单元数据事实源 |
| `docs/schema-knowledge/<工程>/ddl/*.sql` | 只读文件,DDL 全文 + DISCOVERED 块数据源 |
| `.cgraphx/cgraphx.db` | **不访问**。schema 模块不进 SQLite、无索引、纯目录树实时派生(形态同 features 子系统,非 docs 子系统) |

### 4.2 新鲜度与时区口径

- **无新鲜度 SLA**:本地工具,读到什么是什么。INDEX.md 为元数据事实源,DDL 全文以 ddl 文件当前内容为准;用户改 ddl 文件未重 export,web 直读文件即最新,不调和、不提示、不阻塞(与基座 §4.2 元数据 vs 全文口径同构);
- **时区**:schema-knowledge 产物无时间字段(无 created/updated/indexed_at),不涉基座全站时区口径;
- 读请求天然幂等,重复请求返回相同结果(除非期间文件被外部改动)。

## 5. 权限、安全与边界

### 5.1 访问边界(基座)

继承基座 §5.1:仅 localhost,无鉴权、无角色、无审计日志、无用户概念。

### 5.2 路径边界(文件读取)

- DDL 文件路径**只从工程目录扫描结果解析**:工程名 + 表名 → `docs/schema-knowledge/<工程>/ddl/<表>.sql`,路由不接受任意文件路径参数;
- 不存在"给个路径就渲染"的端点(与基座 §5.2 全文渲染路径边界同构);
- **纵深防御**:`path.resolve` 后校验结果仍在 `docs/schema-knowledge/` 根内,否则视为文件缺失/404,绝不越界读取(`/schema/../package.json` 类穿越在此拦截);
- 工程名、表名仅用作目录/文件名解析,出现 `..` / `/` 等路径分隔符的输入一律拒绝。

### 5.3 DISCOVERED 解析边界

- 仅解析 DISCOVERED 块内行首 `-- [标签]` 前缀,用于经验沉淀页的聚合索引;
- **不解析 DDL 语句**(CREATE TABLE / COMMENT ON),DDL 本体原文直出(§3.4);
- 解析器为纯字符串处理,容错优先:格式异常/标签缺失不崩,降级呈现(§3.5)。

## 6. 接口、页面与系统边界

- **页面**(本 spec):工程列表、表清单、单表 DDL 详情、经验沉淀,共 4 个视图;无登录页、无设置页;
- **路由**:路径命名由 plan 定(如 `/schema`、`/schema/<工程>`、`/schema/<工程>/<表>`、`/schema/<工程>/insights`),经基座 `createRequestHandler` 分发,复用基座 404/500 兜底;
- **依赖边界**:web 仅依赖 `src/core/`(基座分层铁律);本需求**不引入 core 新依赖**——schema-knowledge 文件读取用 `node:fs` + `node:path`,不经 core/dbquery 门面;core 不因本需求产生对 cli/web 的反向依赖;
- **与 CLI 的关系**:web 与 CLI 平行消费方;web 不调 CLI 进程,CLI 不感知 web 运行;
- **与 export-table-ddl / db-query skill 的关系**:web 只读消费这两个 skill 的产物(`docs/schema-knowledge/`),不调用 skill、不触发 export、不写 DISCOVERED 块。

## 7. 兼容性、迁移与存量

- **零存量调用方**:schema 模块全新,无旧接口/旧页面需兼容;
- **CLI 行为不许变**(硬契约):本需求不改 core/markdown、core/dbquery、core/timeline,`cgraphx docs` / `cgraphx db` / `cgraphx timeline` 现有命令行为零变化,既有测试为回归基线;
- **基座机制不许变**(硬契约):启动预检、回环绑定、错误态、静态资产服务、时区口径不变;本需求仅改 `layout.ts` 第三入口的 `href` 与文案,不动 navItem 机制与其余基座;
- **资产分发**:新增静态资产(若有)必须纳入 `scripts/copy-assets.cjs` 构建期清单并镜像到 `dist/`,否则不随包发布(基座既有约定)。预计复用现有 `app.css`,可能新增少量样式;
- **版本号**:沿用基座 `cli/index.ts` 运行时从 `package.json` 读取的版本号机制。

## 8. 异常与边界场景

| 场景 | 期望行为 |

| ddl 文件无 DISCOVERED 块 | 详情页不渲染 DISCOVERED 分区;经验页无该表条目 |
| DISCOVERED 块格式异常/标签缺失 | 优雅降级,归入"其他"或原样保留,不崩(§3.5) |

| 文件系统读取失败(权限/IO) | 页面级错误态 + 可读原因,不白屏(基座 §3.2 全局错误态兜底) |

## 9. 验收标准与测试关注点

**验收**(业务可观察):

1. 第三导航入口从灰置变为可点击,进入 schema 模块;基座其余机制(预检/回环/错误态/其它两入口)行为不变;
2. 工程列表页:多工程列出全部、单工程自动折叠直达表清单、零工程/无目录空态引导 export-table-ddl;

5. 经验沉淀页:按 6 类标签聚合当前工程全部 DISCOVERED 块,每条附归属表名可跳转;无 DISCOVERED 时空态;格式异常不崩;
6. §8 全部异常场景行为符合描述;
7. 只读契约可断言:任何 schema 模块请求不产生 DB 写入、不产生文件写入、不连库;
8. CLI 回归:`__tests__/core/markdown/`、`__tests__/core/dbquery/`(若存在)、`__tests__/core/timeline/` 全绿,CLI 手工抽查行为不变。

**测试关注点**:路径穿越拦截(工程名/表名含 `..` / `/`);DISCOVERED 块边界解析(有块/无块/块未闭合/标签缺失/非六类标签);missing 表过滤;单工程自动折叠判定;空态文案区分(目录不存在 vs 无工程 vs 无 DISCOVERED)。

## 10. Plan 编写约束

- **分层铁律**:web 仅依赖 core;本需求不引 core 新依赖(node:fs + node:path),不经 dbquery 门面;
- **基座机制不动**:预检、回环、错误态、静态资产、时区口径不变;仅改 layout.ts 第三入口 href 与文案;
- **DDL 不解析**:不写 SQL DDL tokenizer(跨 MySQL/PG),DDL 本体原文 `<pre>` 直出;
- **DISCOVERED 仅标签解析**:只识别 `-- [标签]` 行首前缀,不解析 DDL 语句;解析器纯字符串、容错优先;
- **零前端构建链**:SSR HTML + 极少 JS(URL 即状态),不引语法高亮库/前端框架,随单包 npm 分发;markdown-it 不复用于 SQL(DDL 非 markdown);
- **不引入 chalk**(基座既有约定);
- **plan 自定项**:导航文案与图标、路由路径命名、表清单页工程内搜索/分页形态、DDL 与 DISCOVERED 视觉分区样式、文件扫描策略(每请求扫 vs 进程级缓存)、单工程自动折叠判定时机、经验页标签缺失行归并策略、INDEX.md 损坏降级形态。

## 11. 不可留到实现期的决策

以下已定,实现期不得自行调整:

1. **数据源性质**:纯文件系统派生,不连库、不读 DB、不调 dbquery 门面;
2. **页面层级**:三级(工程列表 → 表清单 → 单表 DDL)+ 经验沉淀视图;单工程自动折叠;
3. **DDL 呈现**:原文直出 + 视觉分区,不解析字段表/索引、不做 SQL 语法高亮;
4. **DISCOVERED 统一视图**:经验沉淀页按 6 类标签跨表聚合,当前工程内,每条附归属表名;
5. **DISCOVERED 解析边界**:仅标签行解析,不解析 DDL 语句;
6. **missing 表过滤**:表清单只呈现 ✓ 状态表;
7. **pending-comments.sql 不呈现**:根级与工程级均不呈现;
8. **第三入口语义**:激活为模型知识库预览,连库另议(不本次实现);
