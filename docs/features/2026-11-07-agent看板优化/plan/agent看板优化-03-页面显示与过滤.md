# T-3: 页面显示与过滤

> 产物: plan
> 依据: spec@67abbc8

- 目标:看板页面在任务行和摘要卡显示版本;页头加版本下拉,带任务数,按版本过滤左栏,记住选择;没挂会话的任务右栏显示空态。
- 对应 spec 编号:F6、F7、D22、D23、D24(K21–K25)
- 强制引用:`docs/guides/coding-standards.md`
- 涉及范围:
  - `src/core/board/page.html`
- 必须严格执行:
  - 数据形状按 C-2(`BoardTask.versions`、`BoardProject.noSession`);文案与存储按 C-4;版本号比较按 C-5。
  - 版本标签(D22):左栏任务行放在阶段色块后,样式和阶段色块同一尺寸(新 class,沿用 `.stage` 的写法),无版本不放;摘要卡在「阶段」格后加「版本」格,内容同左栏文案,空数组显示「无版本」。
  - 下拉(D23、K21、K22):`<select id="ver-filter">` 放在页头 `.actions` 里「全部」按钮左边;选项按 C-4,顺序「全部版本」→ 各版本(C-5 倒序)→「无版本」;只列个数大于 0 的版本;「无版本」个数为 0 时也不列。每次拿到数据(首屏、刷新)重建选项。
  - 过滤(K23):
    - 全部版本:和现在完全一样(`tasks`,点「全部」再加 `older`,未归类照旧),不显示 `noSession`。
    - 具体版本:各项目 `tasks` + `older` + `noSession` 里 `versions` 含这个版本号的;有会话的按 `lastActiveAt` 倒序,`noSession` 的排在后面、保持数据里的顺序(已按标题排好)。
    - 无版本:各项目 `tasks` + `older` 里 `versions` 为空的,按 `lastActiveAt` 倒序。
    - 具体版本或无版本时:不画未归类行;一个匹配任务都没有的项目整组不画;项目头的任务数用过滤后的个数;「全部」按钮 `disabled`。
    - 下拉里的个数用同一套过滤数出来(各项目相加)。
  - 选中(K24),「选中还有效」按当前过滤值分开判:
    - 全部版本:沿用现有 `selectionExists`——在 `tasks` + `older` 里找任务、`unsorted` 非空认未归类,不认 `noSession`;无效时沿用现有 `defaultSelection`(全局最近活动的任务,没有再回落到未归类)。「全部」收起时选中的 `older` 任务照旧保持选中,行为和现在一样。
    - 具体版本或无版本:只在当前过滤结果里找(具体版本含 `noSession`),未归类一律算无效;无效时选过滤结果里第一个显示的项目的第一个任务(K24 的「最近活动」由排序保证),不回落到未归类;过滤结果为空时 `sel = null`,右栏显示现有空态。
    - 首屏、刷新、切换下拉三个入口都先定过滤值,再走同一套「选中还有效?→ 否则默认」(`applyData` 那一路)。
  - 记住选择(K25、D24):`localStorage` 键 `cgraphx-board-version`,读写包 try/catch(写法同 `cgraphx-board-folded`);切换下拉时写入。首屏和刷新重建选项后,当前过滤值不在选项里(版本已没有任务)→ 改成全部版本并写回。
  - 项目折叠的默认值(`isFolded` 里「第一个项目展开」)按过滤后实际显示的序号判,不按数据下标。
  - 右栏(F7 ②):选中 `noSession` 里的任务时,摘要卡照常(最近活动显示「-」,会话格「定挂 0」),会话区只显示一个空态框「本机没有挂上的会话」,不画「定挂(0)」那组标题。
  - 已有的项目折叠、左右栏各自滚动、摘要卡、复制、刷新行为不变。
  - `page.html` 总行数不超过 600(规范硬线);超了按 index 的 PLAN_CONFLICT 上报,不拆文件。
- 允许局部适配:
  - 下拉和版本标签的 CSS 细节(颜色沿用现有色块:未发 / 计划可用蓝色系,没赶上可用红色系,已发灰色系)、JS 内部函数拆分与命名。
- 具体要求:
  1. 加版本相关 CSS(标签、`select`)。
  2. 页头加 `<select>`;状态里加当前过滤值,首屏从 `localStorage` 读。
  3. 加:版本号比较(C-5)、版本标签文案(C-4)、按过滤值取一个项目的任务列表、数下拉个数、重建下拉选项。
  4. `renderLeft`、`taskRow`、`renderRight`、`defaultSelection`、`selectionExists`、「全部」按钮状态按上面改。
  5. 页面头注释补一句:版本下拉与过滤,对应 spec D22–D24。
- 完成条件:
  - 用 index「统一验证」第 5 条手工看:切版本、切「无版本」、切回「全部版本」与改前一致;刷新后选择保留;选中没会话的任务看到空态。
  - 浏览器控制台无报错;`wc -l src/core/board/page.html` 不超过 600。
  - `npm test` 通过(`server.test.ts` 读页面的断言不变红)。
- 提交点:
  1. `feat(board): 看板显示版本、按版本过滤——下拉带任务数`:`src/core/board/page.html`
- 风险/注意事项:
  - 页面里所有数据都要过 `esc()` 再拼进 HTML,版本号也一样。
  - 本机有两个项目组指向同一目录,同一个任务会出现在两组里,下拉的数会翻倍;这是数据现状,不在页面去重。
