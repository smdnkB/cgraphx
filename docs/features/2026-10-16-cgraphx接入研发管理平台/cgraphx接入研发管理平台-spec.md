## 一图看懂

员工用平台账号给本仓库接入一次，本地 cgraphx 就成为研发管理平台的客户端：本地采集的会话、事件、绑定段、commit、产出、参考按白名单自动同步到平台，1 小时内可见。离线时数据积压，联网后补传，一条不丢；重复上报不重复计数。hook 照常只写本地库，自己不发网络请求，同步由 hook 拉起的脱离进程完成。接入前的本地历史全部回传。本地 web 与本地既有业务规则不变。

协议以需求①（`docs/features/2026-10-15-研发管理服务端/研发管理服务端-spec.md` §7）和已发布的契约包 `@cgraphx-server/contract`（`client.ts`、`enums.ts`）为准。

```mermaid
flowchart TD
  conn[员工：接入平台<br/>平台地址 + 账号 + 密码] --> chk{已有可用凭据?}
  chk -- 是，且未加 --force --> already[提示已接入 + 同步状态]
  chk -- 否 / --force --> plat{平台校验}
  plat -- 拒绝：未登记 / 停用 / 非成员 / 密码错 --> reject[显示原因，不上报任何数据]
  plat -- 通过 --> saved[凭据存本地<br/>任务源配置自动写好]
  saved --> hist[回传本仓库全部历史]
  hist --> daily[日常开发：hook 写本地库<br/>并拉起后台同步，不等它]
  daily --> res{同步结果}
  res -- 成功 --> ok[平台 1 小时内可见]
  res -- 断网 / 服务端异常 / 请求过大 --> retry[静默重试<br/>连续失败超 1 小时：会话开始时提示]
  res -- 凭据失效 / 账号停用 / 移出项目 / 仓库停用 --> pause[暂停自动上报，本地照常记录<br/>会话开始时提示原因 → 恢复后补传全部]
  res -- 某会话格式被拒 --> iso[隔离该会话，其余照常<br/>升级 cgraphx 后自动重试]
  manual[员工：立即同步 / 查看同步状态 / 断开] --> daily
```

| 员工动作 / 场景 | 看到什么 | 异常时 |
|---|---|---|
| 接入 | 接入成功：项目名、账号、开始回传历史 | 按平台拒绝原因分别提示（§3.3）；已接入且未加 `--force`：提示已接入，不重新签发凭据 |
| 日常开发 | 无感知；hook 耗时不变 | 被暂停或连续失败超 1 小时：下次会话开始时提示一行 |
| 立即同步 | 本次上报结果：成功 / 失败原因 / 被隔离会话数 | 未接入：提示先接入 |
| 同步状态 | 接入信息、最后成功同步时间、积压条数、暂停原因、被隔离会话、最近一次错误 | 未接入：提示先接入 |
| 断开 | 本地凭据与任务源配置删除，停止上报 | 未接入：空操作 |
| 平台任务详情 / 我的工作量 | 本仓库的会话、时长、commit、产出、参考 | 本地手动任务、终端 commit：显示为未归属，可在平台补绑 |

## 1. 目标与范围

### 1.1 目标

让员工本地的 cgraphx 开发数据进入研发管理平台，平台就能按任务和人统计投入与交付，员工不需要手动录入。

### 1.2 包含范围

| 模块 | 内容 |
|---|---|
| 接入 | 用平台账号接入本仓库；重复接入保护；`--force` 换账号或换凭据；自动写好任务源配置；断开 |
| 同步 | 自动同步（hook 拉起脱离进程）、立即同步、首次接入回传全部历史、离线补传、失败分级处理 |
| 上报内容映射 | 会话、事件、绑定段、commit（含终端 commit）、产出（产物类型映射）、参考，全部从本地数据按白名单构造 |
| 参考的精确记录 | `cgraphx docs` 执行时记录召回命中的概念和读过正文的文档；对四个沉淀目录做命令文本推断作为补充 |
| skill 调整 | knowledge-recall（skill 与子 agent）、knowledge-api 读取知识库正文时改走 `cgraphx docs` 命令 |
| 同步状态与提示 | 本地同步状态查询；会话开始时提示异常；向平台报告积压条数 |

### 1.3 非目标

- 修改服务端或契约。服务端遗留问题 P1（旧凭据不作废）、P4（回执计数口径不统一）由服务端处理。
- 修改本地 web（包括「任务参考」的口径）、`cgraphx task show`、`cgraphx features` 阶段口径，以及本地既有的绑定和归属规则。「本地 web 对齐新参考口径」另立需求。
- 把平台补绑的结果回写到本地。
- 排除某个会话不上报、临时暂停上报（关闭全部采集用现有的 `CGRAPHX_NO_TIMELINE`）。
- 断开时删除平台上的数据。
- 从 `git log` 回填本地 timeline 没有记录的 commit（如安装 cgraphx 之前的提交、合并提交）。
- squash 或 rebase 合并、删除分支导致的平台链接 404。
- 安装系统级定时任务（launchd / cron / Windows 计划任务）。
- 新增通用的"读沉淀文件"命令；把 db-query、code-map-recall、design-map 改为经 cgraphx 命令读取。
- 平台上标注哪些参考是推断出来的（契约没有该字段）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 平台 | 研发管理服务端（需求①） |
| 接入 | 用平台账号密码，按本仓库 git 远程地址换取长期上报凭据。一个仓库的 `.cgraphx/` 同一时刻只保存一份凭据（一个账号） |
| 凭据 | 平台签发的长期上报凭据。只存一份，就是 `.cgraphx/task-source.json` 里的认证头；拉任务和上报共用 |
| 同步 | 把本地尚未上报或上报后发生变化的数据发给平台，并得到平台成功确认 |
| 积压 | 本地尚未得到平台成功确认的数据条数 |
| 终端会话 | 本仓库一个固定的虚拟会话，承载不在任何 agent 会话里产生的 commit。只有 commit，没有事件 |
| 暂停 | 遇到不可重试的拒绝后，自动同步停止向平台提交数据；本地照常记录 |
| 隔离 | 被平台判为格式不合法的会话单独留在本地并标记，不阻挡其他数据 |
| 沉淀目录 | `docs/knowledge/`、`docs/schema-knowledge/`、`docs/code-map/`、`docs/design-map/` |

## 3. 接入、凭据与断开

### 3.1 接入

| 项 | 规则 |
|---|---|
| 输入 | 平台地址、账号、密码。平台地址只在接入时给一次，之后的同步不需要再给 |
| 密码 | 只在本次接入请求里使用，**不落盘**：不写任何文件或库；不得出现在命令行参数里（否则会进入 shell 历史和本地 timeline 的命令记录）。密码输入时不回显 |
| 远程地址 | 取本仓库 `origin` 的 git 远程地址上报给平台匹配；没有 `origin` 时接入失败并提示原因 |
| 成功 | 保存凭据；写好任务源配置（指向平台「我的任务列表」，带凭据认证头）；显示项目名和账号；随即开始回传全部历史（§4.3） |
| 拒绝 | 不保存凭据，不上报任何数据，不改动已有的任务源配置；按 §3.3 提示原因 |
| 已接入 | 本地已有凭据且平台认为它可用时，不重新接入：提示"已接入"并显示同步状态 |
| `--force` | 不管有没有凭据都重新接入（换账号、换凭据），新凭据覆盖本地旧凭据。旧凭据在平台上仍有效（服务端 P1），接入输出里说明这一点 |
| 存量配置 | 本仓库已有手工写好的任务源配置和凭据，视为已接入，直接沿用，不要求重新接入 |
| 客户端标识 | 客户端名固定为 `cgraphx`，版本取本地 cgraphx 版本号 |

### 3.2 断开

- 删除本地凭据，也就是删除平台写入的任务源配置。之后停止一切上报，`cgraphx task list` 也不再从平台拉任务。已拉到本地的接口任务保留（沿用"外部接口不再返回的任务保留不删"）。
- 本地数据和平台数据都保留。
- 重新接入后按 §4.3 回传全部历史；按幂等规则不会重复计数。

### 3.3 平台拒绝原因与提示

| 平台错误 | 发生于 | 提示（意思） | 后续 |
|---|---|---|---|
| `invalid_credentials` | 接入 | 账号或密码错误 | 重新接入 |
| `account_disabled` | 接入 / 同步 | 平台账号已停用，联系平台管理员 | 同步：暂停 |
| `repo_not_registered` | 接入 / 同步 | 本仓库未在平台登记，联系项目管理员 | 同步：暂停 |
| `repo_disabled` | 接入 / 同步 | 本仓库的平台登记已停用 | 同步：暂停 |
| `not_project_member` | 接入 / 同步 | 你不是该仓库所属项目的成员 | 同步：暂停 |
| `invalid_token` | 同步 | 上报凭据已失效，请重新接入 | 同步：暂停，直到重新接入 |
| `validation_failed` | 同步 | 部分数据被平台拒收 | 隔离（§4.5） |
| `internal_error`、`payload_too_large`、网络失败、超时 | 同步 | 无（连续失败超 1 小时才提示） | 重试；请求过大时拆小后重试 |
| （本地）后台同步正在进行 | 接入 / 立即同步 | 后台同步正在进行，稍后再试（最多等待 30 秒后提示） | 稍后重试；接入在签发凭据前放弃，不留下任何改动 |

## 4. 同步

### 4.1 触发

| 触发 | 规则 |
|---|---|
| 自动 | 由 hook 拉起脱离的后台同步进程，hook 立即返回、不等待。有节流，不是每个事件都拉起一次。本仓库未接入时 hook 不拉起任何进程；`CGRAPHX_NO_TIMELINE` 打开时也不拉起 |
| 立即同步 | 员工手动执行，前台运行并显示结果 |
| 接入成功 | 接入后开始回传全部历史 |

多个触发同时发生（多个会话并行、手动同步与自动同步同时）时，不能产生重复或错乱的数据。

### 4.2 时效

- 只要本机在线、本仓库有 agent 活动，本地产生的数据 1 小时内在平台可见。
- 已上报的数据在本地发生变化，同样要在 1 小时内反映到平台。变化包括：绑定段结束或切换；产出的文件被提交、被推送，得到了 commit hash；会话里又有新事件、新产出、新参考。
- 本机离线，或者最后一次活动后再没有 agent 活动，数据留在本地，直到下次有活动或员工手动同步。此时平台「接入状态」里的最后同步时间会停在旧值。这种情况可以接受。

### 4.3 历史回传

- 首次接入（含断开后重新接入）回传本仓库本地库里的**全部**历史数据，不设时间下限。
- 历史数据和新数据的上报规则相同（§5）。精确参考记录（§5.6）只从本需求上线后才有，历史会话的参考只来自命令文本推断。

### 4.4 失败处理

| 类别 | 行为 | 员工感知 |
|---|---|---|
| 可重试（断网、超时、`internal_error`） | 下次触发时重试 | 连续失败超过 1 小时：下次会话开始时提示一行；同步状态里显示最近一次错误 |
| 请求过大（`payload_too_large`） | 拆成更小的请求重试，直到成功或拆到单个会话 | 同上 |
| 不可重试（§3.3 中标"暂停"的） | 暂停自动同步；本地照常记录，积压保留。`invalid_token` 等员工重新接入后恢复；其余原因自动定期探测，平台恢复后自动继续，并补传暂停期间的全部积压 | 每次会话开始时提示一行原因；同步状态里显示暂停原因 |

- 会话开始时的提示只在会话开始时出现，会话中途不插话，与本地"不打扰"原则一致。提示和现有的会话开始上下文（会话 id、已绑定任务）一起输出，不能删掉现有内容。
- 任何同步失败都不能影响 hook、本地记录和本地命令。

### 4.5 隔离

- 平台返回 `validation_failed` 时，要定位到被拒的会话（最细到单个会话），只隔离这些会话；其余数据照常上报并得到确认。
- 被隔离的数据不删除、不丢弃，留在本地并标记；同步状态里列出"有 N 个会话被平台拒收"。
- 本地 cgraphx 版本变化（升级）后，被隔离的会话自动重新尝试上报。
- 被隔离的会话不在会话开始时提示。

### 4.6 确认与积压

- 一个请求得到平台成功响应，才算其中的数据已上报（平台整批一个事务）。**不用**回执里的 `accepted` 条数判断上报进度（服务端 P4 口径不统一）。
- 每次上报都携带本地积压条数（`backlog`），在平台「接入状态」里显示。
- 平台回执里的 `warnings`（`binding_ineffective`、`path_dropped`）不算失败，不重试，不提示，可在同步状态的最近一次结果里看到。

## 5. 上报内容

所有上报记录一律**从本地数据中只取白名单字段正向构造**，不能把本地记录整条透传后再删字段（§6）。所有路径一律为仓库内的相对 POSIX 路径。

### 5.1 会话

| 本地 | 平台 | 规则 |
|---|---|---|
| agent 会话（timeline 事件的 `session_id`，包括子 agent 的事件，它们和主会话同一个会话 id） | `clientSessionId` = 本地会话 id | 每个本地会话对应一个平台会话 |
| 终端 commit（`session_id` 为空的 git_commit） | 本仓库固定的终端会话 | 只带 commits，events / bindings / artifacts / references 为空；平台时长计为 0 |

### 5.2 事件

| 字段 | 来源 |
|---|---|
| `eventId` | 本地事件的稳定标识。同一条本地事件无论上报多少次，标识都不变 |
| `ts` | 事件时间，带时区偏移 |
| `type` | 本地事件类型原样上报（`user_prompt` / `pre_tool_use` / `post_tool_use` / `stop` / `git_commit` / `session_start` / `session_end`） |
| `toolName` | 工具名；没有就不带 |
| `skillName` | 调用 Skill 工具时的 skill 名；用户以斜杠命令（如 `/write-spec`）触发的 skill，从本地记录里识别出命令名作为 skill 名（只取命令名，prompt 原文不出本机） |

只上报 agent 会话的事件；终端 commit 不生成事件。

### 5.3 绑定段

| 本地 | 平台 |
|---|---|
| 一条会话绑定记录 | 一个绑定段，`bindingId` 为该绑定记录的稳定标识 |
| 绑定到接口任务 | `taskId` = 该任务的外部编号（平台任务形如 `T-<n>`），原样上报 |
| 绑定到手动任务 | `taskId = null`（平台算未归属，员工可在平台补绑） |
| 开始 / 结束 | `start` / `end`；仍生效的为 `null`。绑定结束或切换后要重新上报，带上结束时间 |

平台判定绑定段无效（非本人负责、任务已终态、任务不存在）时只给 warning，客户端不需要处理。

### 5.4 commit

- 上报本地 timeline 记录的全部 commit：agent 会话里的挂在该会话下，终端 commit 挂在终端会话下（§5.1）。
- 字段：hash、message、分支、文件（仓库内相对路径）、增加行数、删除行数、时间（本地记录的时间）。

### 5.5 产出

**哪些文件算本会话的产出**：本会话里用编辑工具（Edit / Write / MultiEdit / NotebookEdit）改过的文件，加上本会话 commit 里的文件，再按下表映射，**没有命中的不作为产出上报**（代码由 commit 承载）。终端会话的产出就是终端 commit 里命中下表的文件。Bash 生成、还没提交的文件不算产出，提交后在提交所在的会话里出现。

**产物类型映射**（`<需求>` = `docs/features/<feature-id>/`；只看路径和文件名，不看内容；先命中先用）：

| 平台类型 | 本地文件 |
|---|---|
| `ui_test_spec` | `<需求>/ui功能测试/*-ui功能测试-spec.md` |
| `ui_test_report` | `<需求>/ui功能测试/` 下的 `*-ui功能测试报告.xlsx`、`*-ui功能测试报告.md`（旧）、`*-ui功能测试结果.json`、`*.png` |
| `api_test_spec` | `<需求>/*-接口测试-spec.md` |
| `api_test_report` | `<需求>/*-接口测试报告.md`、`<需求>/*-测试报告.md`（旧名）、`<需求>/*-接口测试验证.jsonl` |
| `unit_test_spec` | `<需求>/*-单元测试-spec.md` |
| `unit_test_report` | `<需求>/*-单元测试报告.md` |
| `spec` | `<需求>/<前缀>-spec.md`（需求目录顶层，排除上面三种测试 spec） |
| `plan` | `<需求>/plan/` 下的全部文件 |
| `wireframe` | `<需求>/*-线框-v<N>.html` |
| `knowledge` | `docs/knowledge/` 下的全部文件 |
| `code_map` | `docs/code-map/` 下的全部文件 |
| `design_map` | `docs/design-map/` 下的全部文件 |
| `schema_knowledge` | `docs/schema-knowledge/` 下的全部文件 |

不作为产出：`docs/bruno/`、`docs/guides/`、需求目录里不符合上表的文件（如 `验收记录.md`、旧的 `*-mockup.html`、PRD、设计文档、交付讲解）、代码和其他一切文件。

**产出记录字段**：

| 字段 | 规则 |
|---|---|
| `type` / `path` | 按上表映射；仓库内相对路径 |
| `action` | 本会话之前文件不存在、由本会话新建 → `create`；否则 `modify` |
| `commitHash` | 本会话最后一次改动该文件之后，第一个包含该文件的 commit（不限哪个会话或终端提交），并且它**已在远程任意分支上**；否则为 `null`（平台显示「未推送」）。"已在远程"以本机最近一次和远程同步（push / fetch）后的状态为准，不额外访问远程 |
| `branch` | 有 commit 时为该 commit 提交时所在的本地分支；没有时为空 |
| `ts` | 本会话最后一次改动该文件的时间 |

文件后来被推送、拿到 commit hash 后，按 §4.2 重新上报。本地已不存在、且从未进入任何 commit 的文件（改过又删掉）不作为产出上报——平台上没有可查看的版本。

### 5.6 参考

**口径**：

| 种类 | 什么算 | 不算 |
|---|---|---|
| 概念（`kind = concept`） | 召回命中的概念：按概念检索知识库并命中至少一篇文档的概念，记索引里的规范概念名 | 只列出全部概念（如 `docs concepts`）；按关键词 / 领域 / 标签检索 |
| 文件（`kind = file`） | 本会话**读过正文**的沉淀目录文件（§2），仓库内相对路径 | 召回只返回了路径、没有打开正文的文档；只看了元数据和摘要；代码文件、设计文档、需求目录里的文件、散落在仓库里的 `.sql` |

本会话的产出文件（§5.5 映射前的集合中属于沉淀目录的）不再算参考。

**识别**：

| 来源 | 规则 |
|---|---|
| 精确记录（主） | `cgraphx docs` 在执行时，自己往本地记下本会话命中的概念和输出了正文的文档。会话 id 按现有规则取（`--session` 或宿主注入的环境变量）；拿不到就不记，不报错，不改变命令的输出和退出码 |
| 命令文本推断（辅） | 从本会话的命令记录里推断读取的文件，**只认四个沉淀目录**，且须是仓库内存在的文件。命令以 `cd <目录> && …` 或 `cd <目录>; …` 开头时，后面的相对路径按切换后的目录解析。仍然跳过含 `$` 的片段 |
| 合并 | 两路结果合并去重后上报；平台不区分来源 |

**知识库正文的读取方式**：`cgraphx docs` 需要提供输出文档正文的能力（现在的 `docs show` 只输出元数据和摘要）。knowledge-recall（skill 和子 agent 定义）、knowledge-api 两个 skill 读知识库正文时，改为通过这个能力读取，不再用 `cat` / `sed` 等直接读文件。

## 6. 白名单与隐私

| 项 | 规则 |
|---|---|
| 只传白名单 | §5 列出的字段之外，一律不出本机 |
| 绝不上传 | prompt 原文、命令原文（`tool_args`）、工具结果摘要、代码和文件内容、命令输出、绝对路径（包括 `cwd`）、commit 文件以外的本地元数据 |
| 路径 | 一律转成仓库内相对 POSIX 路径；转换不了（在仓库之外）的不上报 |
| 推断产生的数据 | 参考的路径和概念名可以上报，但用来推断的命令原文不出本机 |
| 本地凭据 | 只存在 `.cgraphx/`（git 忽略）里；同步状态、日志、错误提示里不得输出凭据明文 |

## 7. 同步状态与平台可见

- **本地同步状态显示**：是否已接入（项目、账号能拿到就显示）、平台地址、最后一次成功同步的时间、积压条数、是否暂停及原因、被隔离的会话数、最近一次同步的结果或错误。
- **平台侧**：「接入状态」显示最后同步时间和积压；任务详情、「我的工作量」显示本仓库的会话、时长、commit、产出、参考（口径由平台按需求① 计算，客户端不报时长）。

## 8. 兼容性

| 对象 | 要求 |
|---|---|
| 契约 | 按已发布的 v1 契约对接，不依赖平台未发布的字段 |
| hook 预算 | hook 不发网络请求、不等待同步进程；单次 hook 耗时不明显增加（现约 5ms） |
| 旧版 cgraphx 共存 | agent 的 Bash 里，PATH 优先命中全局安装的 cgraphx。新版 hook 配置遇到不认识新入口的旧版二进制时，不能报错阻塞 Claude Code，也不能写出错误数据（沿用"给 hook 加输入优先用环境变量"的经验） |
| 已安装项目 | `cgraphx install` 重新执行时，能把已安装项目升级到带自动同步的 hook 配置 |
| 本地数据结构 | 新增的本地状态（上报进度、隔离标记、暂停原因、精确参考记录等）不能改变现有表的语义和现有读取方的结果。动表时按 `docs/guides/data-standards.md`「Schema 变更约定」执行 |
| 本地 web / 本地命令 | `cgraphx web`、`cgraphx task`、`cgraphx features`、`cgraphx timeline` 的现有输出不变（参考的新口径和精确记录只用于上报） |
| 多 agent | Claude Code 和 CodeBuddy 的会话都按同样规则上报（会话 id 来源沿用 agents 门面） |
| 卸载 | `cgraphx uninstall` 删除 `.cgraphx/` 时凭据一并删除；`--keep-data` 时保留 |

## 9. 异常与边界场景

| 场景 | 行为 |
|---|---|
| 本仓库没有 git 远程地址 | 接入失败，提示原因，不保存任何东西 |
| 接入时平台地址不可达 | 接入失败，提示检查平台地址；不保存任何东西 |
| 已接入，任务源配置被手工改坏或删除 | 视为未接入；同步状态提示重新接入 |
| 多个会话同时拉起同步 | 不重复上报出不同结果，不产生错乱的积压计数（§4.1） |
| 同步进程运行时 Claude Code 退出 | 同步照常完成或中断；中断的数据下次重传，平台按幂等不重复计数 |
| 同一条数据上报两次 | 平台不产生重复记录、不重复计时 |
| 离线一周后联网 | 下次触发时补传全部积压，按原时间计入对应日期 |
| 绑定段指向平台上不存在 / 非本人 / 已终态的任务 | 照常上报；平台算未归属，只给 warning |
| 本地手动任务 | `taskId = null`，平台算未归属 |
| 终端 commit | 挂在终端会话，时长 0，平台算未归属 |
| 被移出项目后又加回 | 暂停期间本地照常记录，恢复后补传全部 |
| 文件已提交但只在本地分支上 | `commitHash = null`，推送后（本机看到远程状态后）的下一次同步补上 |
| 推送后被 squash 合并并删除了分支 | 不处理（非目标） |
| 会话 id 拿不到时执行 `cgraphx docs` | 不记精确参考，命令照常 |
| 换账号后用 `--force` 重新接入 | 之后的上报都属于新账号；已上报给旧账号的数据留在平台旧账号下 |

## 10. 验收标准

- **完成标准**：本仓库接入平台并同步后，在平台任务详情（如 T-24）和「我的工作量」里能看到本仓库的会话、时长、commit、产出与参考；接入前的历史（如 T-23）同样可见。
- **接入**：账号密码错误、仓库未登记、非成员、账号停用分别给出对应提示，并且不保存凭据、不上报任何数据；已接入时重复接入不在平台上新增凭据；`--force` 可以换账号；接入成功后 `cgraphx task list` 能从平台拉到任务；密码不出现在任何文件、本地库和命令记录里。
- **时效**：有 agent 活动时，新数据 1 小时内在平台可见；hook 耗时与改动前相比没有明显变化；hook 进程里没有网络请求。
- **补传**：断网期间正常开发，联网后（下一次活动或手动同步）平台数据完整，条数与本地一致。
- **幂等**：同一批数据重复上报、并发同步之后，平台上的会话数、事件数、commit 数和时长都不增加。
- **暂停与恢复**：在平台上把本人移出项目，同步暂停，会话开始时提示原因；加回后自动恢复，暂停期间的数据全部补齐。凭据失效时提示重新接入，重新接入后恢复。
- **隔离**：构造一个平台会拒收的会话，只有它被隔离，其余数据照常可见；同步状态里显示被隔离的会话数。
- **白名单**：抓取实际请求体，里面没有 prompt 原文、命令原文、工具结果、文件内容、绝对路径；所有路径都是仓库内相对路径。
- **产物映射**：上表 13 种类型各至少一个样例映射正确；`docs/bruno/`、`docs/guides/`、`验收记录.md`、代码文件不出现在产出里；commit 只在本地时 `commitHash` 为空，推送后补上。
- **参考**：用 knowledge-recall 召回若干概念并读取其中一篇正文，平台参考里有这些概念和那一篇文件，没有只返回了路径的文档；`cd docs/knowledge && cat <文件>` 能被识别；读代码文件、需求 spec 不出现在参考里；本地 web 的「任务参考」输出与改动前一致。
- **终端 commit**：在终端提交一次，平台「我的工作量」里出现该 commit，归在未归属，不增加时长。
- **断开**：断开后不再上报，`task list` 不再访问平台；本地数据和平台数据都还在；重新接入后不重复计数。

## 11. Plan 编写约束

- 不修改服务端仓库和契约包；按已发布的 v1 契约对接。
- hook 里不发网络请求、不等待子进程；不能因为同步失败而影响 hook 的退出码、stdout 约定（timeline hook 的 stdout 必须为空）和本地记录。
- 依赖方向：只经门面读 timeline / task / features / markdown；core 不依赖 cli / web；不能让 timeline、task、features 反向依赖新的同步代码。
- 上报数据只能从白名单字段正向构造；必须有能证明请求体不含禁止内容的测试。
- 本地 web 和现有本地命令的输出不变；参考的新口径（四个沉淀目录、`cd` 解析）不能改变本地 web 现有的 `collectReferences` 结果。
- 产物类型映射和参考的沉淀目录范围各自只定义在一处；改命名约定时只改这一处。
- 改 skill 的入口是 `assets/claude-template/`（skill 与 agent 定义），不是仓库根目录的 `.claude/`。
- 新增运行时资产（如新的 `schema.sql`）要加进 `scripts/copy-assets.cjs`。
- 动本地表时按 `docs/guides/data-standards.md`「Schema 变更约定」执行。
- 不引入 chalk；不引入原生依赖。

## 12. 不可留到实现期的决策

以下已在本 spec 锁定，plan / implementation 不得自行调整：

- 接入时的拒绝语义和"不保存、不上报"
- 重复接入保护与 `--force`
- 密码不落盘、不进命令行参数
- 只保存一份凭据，存在任务源配置里
- 回传全部历史
- 终端 commit 挂在终端会话、没有事件
- 手动任务算未归属
- hook 拉起脱离进程、hook 不等待
- 1 小时时效，以及变化也要在 1 小时内反映
- 失败分三级：可重试、暂停、隔离，以及各自的提示方式
- 只在会话开始时提示
- 不用回执条数判断进度
- 产物类型映射表和"会话产出"的口径
- `commitHash` 只在 commit 已在远程时才带
- 参考的口径（命中的概念 + 读过正文的四类沉淀文件）和识别方式（精确为主、推断为辅）
- 上报白名单
- 本地 web 不变
- 断开的范围
