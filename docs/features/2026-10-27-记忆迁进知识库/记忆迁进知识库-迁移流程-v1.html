记忆迁进知识库

原来 Claude Code 的自动记忆存在项目外的 ~/.claude/projects/<编码>/memory/,只有你本人、只有这一个目录读得到:换个副本、换个队友就没了,知识库也召回不到。现在敲一次 /knowledge-migrate:读出主目录和各副本的记忆,按讲的内容分去三处——知识库、项目根目录 CLAUDE.md、你自己的 ~/.claude/CLAUDE.md;你看过清单、说「迁」才写;写完关掉你在这个项目里的自动记忆。之后你说「以后都这样做」,agent 先问记到哪。

3 处记忆的去向:知识库、项目 CLAUDE.md、个人 CLAUDE.md
3 条本项目的记忆:2 条进知识库,1 条进个人 CLAUDE.md
每人 1 次每个项目跑一次,主目录、副本里都行
0 个新增的 cgraphx 命令:全用现成工具
全局· 从哪读记忆· 每条去哪· 迁移清单· 说「迁」以后· 关自动记忆· 什么时候提交· 之后怎么记· 跟着改的地方

全局:敲一次 /knowledge-migrate

整条链都是这次新增的。蓝色的关口停下来等你;写入时任何一步失败,就停在关记忆之前。

怎么读

等你确认停下来等你拍板 停下出了问题,不往下走 程序拦程序检查挡住,改对才能过 看情况只在某些情况下发生
去知识库 去项目根目录 CLAUDE.md(随仓库共享) 去你自己的 ~/.claude/CLAUDE.md
一次迁移以本项目为例
  1. 1

    列目录:主目录 + 全部副本

    cgraphx replica list --all --json 列出副本;在副本里跑时,经 .cgraphx/shared 链接认出主目录;还没有 replica 命令就只读主目录

  2. 2

    算记忆目录、读记忆

    按 Claude Code 的规则把目录路径编码,读 memory/ 下的条目文件,跳过索引 MEMORY.md;本项目读到 3 条

  3. 3

    出迁移清单 等你确认

    每条定好去向,标出已迁过、可能过期、同一件事、说法矛盾;你可以改去向、划掉,说「迁」才往下走

  4. 4

    写入三处

    知识库按 /knowledge-write 写条目
    项目根目录 CLAUDE.md加进「## 项目约定」节
    ~/.claude/CLAUDE.md追加到文件末尾

    程序拦知识库条目过了 cgraphx docs validate 才算写完

    停下任何一步失败就停在这里,自动记忆保持开着

  5. 5

    关自动记忆

    主目录和还在的副本:在本人的 .claude/settings.local.json 写 "autoMemoryEnabled": false

  6. 6

    提交 看情况

    只在主目录、而且在版本分支(如 dev/2.0.11)上,以 chore(release): 提交;其余情况不提交

  7. 7

    回报

    迁了几条、各去哪,自动记忆已关,原来的记忆文件留在原处

之后每个会话会话开始多一行提示 → 你说「以后都这样做」→ agent 先问记到哪:知识库 / 项目约定 / 你个人的设置

局部:从哪读记忆(第 1、2 步)

要读的目录 = 主目录 + replica list 里的全部副本,删了的也算:副本目录删了,Claude Code 那边的记忆目录还在。每个目录的记忆目录,是把它的 git 根路径里每个不是字母数字的字符换成 -。

目录编码后的项目目录说明
/Users/smdnk/objects/ai/cgraphx-Users-smdnk-objects-ai-cgraphx本项目的主目录:3 条记忆 + MEMORY.md(实测)
…/cgraphx@订单导出-Users-smdnk-objects-ai-cgraphx-----@ 和 4 个汉字各变一个 -
…/cgraphx@积分发放-Users-smdnk-objects-ai-cgraphx-----和上一行字数相同,撞到同一个目录 → 只读一次,「在哪」两个都写
…/cgraphx-server-Users-smdnk-objects-ai-cgraphx-server本机另一个项目,所以不按 cgraphx-* 通配找副本,只认 replica 登记

skill 里的算法(一个目录)

root=$(git -C "$d" rev-parse --path-format=absolute --git-common-dir) && root=$(dirname "$root") || root=$d
enc=$(node -e 'console.log(process.argv[1].replace(/[^a-zA-Z0-9]/g, "-"))' "$root")
ls ~/.claude/projects/$enc/memory/

和 Claude Code 2.1.204 同一算法。编码超过 200 个字符时 Claude Code 会截断再接哈希,改按前 200 个字符的前缀找;配了 autoMemoryDirectory 的读那个目录。

每条记忆读什么

  • name、description、metadata.type本项目 1 条 project 类、2 条 feedback 类
  • 正文的结论 + Why: + How to apply:分别写进知识条目的 Summary、Context、Reuse Guidance
  • originSessionId、modified 不迁协作元信息,不是知识
  • 记忆文件只读不删、不改、不挪,MEMORY.md 也不动

局部:每条记忆去哪(第 3 步的去向)

按记忆讲的内容分三处。知识库是开工时按需召回的,每轮都要守的规则放进去会时灵时不灵;.claude/CLAUDE.md 里的 cgraphx 托管块升级时整块重写,所以不往那里写。

这条记忆讲的是什么?
项目里的决策、规则、教训→ 知识库 docs/knowledge/「code-subsystem 分支不并入 main」→ 决策

每轮都要守的项目约定→ 项目根目录 CLAUDE.md,随仓库给队友「提交前先跑 npm test」
只关于你本人的偏好→ 你的 ~/.claude/CLAUDE.md「回复用中文」

「备注」里的标记

  • 已迁过,默认不迁知识库里找得到「迁自 Claude Code 自动记忆 code-subsystem-branch-kept-unmerged」这一行
  • 可能过期,默认不迁记忆提到的分支、文件已经不在了;按意思认,「code-subsystem 分支」指的是 feat/code-subsystem
  • 合进已有条目知识库里已有讲同一件事的条目:「怎么写」填「合进 <已有条目>」,不新建
  • 说法矛盾,待你定和已有条目说的相反:清单下面摆出两段原文,问以哪个为准
  • 已有同义一条,不重复写两处 CLAUDE.md 里已经写过同一个意思

局部:说「迁」以后(第 4 步)

顺序固定。知识库先写、先校验、先建索引,两处 CLAUDE.md 后写;全部成功才进第 5 步关记忆。

1

写知识库条目

一条记忆一个条目,按 /knowledge-write 的 frontmatter、Summary、合并规则写;source_type 一律 work_context,owners 取 git 用户名。Summary 写结论和什么时候该召回,带上召回时的口语词。

  • 程序拦每个文件跑 cgraphx docs validate,不合法就改到合法
2

建索引

cgraphx docs index;你说的「迁」已经算确认,不再问。

3

写项目约定

项目根目录 CLAUDE.md:有「## 项目约定」节就加在节末,没有就在文件末尾新建这一节。一条一行:- 提交前先跑 npm test——CI 只跑构建,测试挂了合进去才发现。

4

写个人设置

追加到 ~/.claude/CLAUDE.md 末尾,文件没有就新建:- 回复用中文,长任务中途也不漂成英文——连续工具调用后回复漂成过英文。

  • 停下上面任何一步失败:回报写了哪些、没写哪些,自动记忆保持开着;修好再跑一次,已写的会标「已迁过」

局部:关自动记忆(第 5 步)

只写你本人的 .claude/settings.local.json(不签入),主目录和每个还在的副本各写一份;之后开的副本会把这个被忽略的文件一起复制过去,不用再关。已经开着的会话不撤回已加载的记忆,新开的会话起不再加载。

情况结果(临时仓库实测)
没有设置文件,也没被 git 忽略新建 { "autoMemoryEnabled": false },把它加进 .git/info/exclude,git status 干净
已有 env、permissions 等字段原样保留,只加一个字段;再跑一次不改文件
JSON 坏了报错,不动文件,回报写明是哪个文件
被仓库跟踪不写:写进去一提交,队友的记忆也关了;提示先 git rm --cached 它再跑
已经被项目 .gitignore 忽略只写设置,不重复加忽略

为什么只写这一个文件

  • 不写签入的 .claude/settings.json会把队友的记忆也关掉;只关本人的,队友各迁各关
  • 不写 ~/.claude/settings.json会关掉你所有项目的自动记忆
  • 不改项目 .gitignore那是被跟踪的改动,会拦下开副本、合入需求

局部:什么时候提交(第 6 步)

在主目录,而且当前分支形如 dev/2.0.11?
是只提交本次写的知识库文件和项目根目录 CLAUDE.md,说明 chore(release): Claude Code 记忆迁进知识库。版本分支上只放行这种开头的整版改动
不是(在 main 上,或在副本里)不提交,回报列出改了哪些文件。副本里的改动随需求自己的提交合入

个人 ~/.claude/CLAUDE.md 和本地设置不在仓库里,不进任何提交。
