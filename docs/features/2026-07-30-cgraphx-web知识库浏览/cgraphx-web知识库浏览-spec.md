# 规格说明: cgraphx web 本地知识库浏览(服务基座 + 知识库)

> feature-id: 2026-07-30-cgraphx-web知识库浏览
> 状态: 已确认
> 负责人: liulongfei
> 日期: 2026-07-30

> **拆分说明**:本需求与《cgraphx-web时间线浏览》(feature-id: 2026-07-30-cgraphx-web时间线浏览)原为同一需求「cgraphx web 本地浏览服务」,为独立演进与独立实现而拆分。**本 spec 承载 web 服务基座**(命令、启动行为、应用壳、安全边界、分层与兼容契约)+ 知识库页面,是时间线 spec 的前置依赖;时间线 spec 只定义时间线页面,不重复基座契约。

## 1. 目标与范围

### 1.1 目标

实装 cgraphx 2.0 刻意预留的 `src/web/` 层(见《cgraphx2.0重构-spec》§3.1:`src/web/` = Web 本地服务,后续阶段),新增 `cgraphx web` 顶层命令,启动一个**本地、只读、面向浏览器**的服务,让团队成员在浏览器里浏览目标项目 `docs/knowledge/` 的 markdown 知识库:多维筛选、文档列表、文档详情(markdown 全文渲染)、文档间双向引用导航。

体验定位为**内部产品级**:导航、搜索、空态、加载态、错误态齐全,视觉整洁。设计基线见已确认的交互设计稿(两版迭代,知识库 v2 布局定稿)。

### 1.2 包含范围

- `cgraphx web` 命令:启动本地服务、指定目标项目与端口的命令接口(**服务基座,两个子需求共用**);
- 应用壳:左侧导航、顶栏只读状态标识、全局错误态/加载态(**基座**);
- 两个页面:知识库总览、文档详情;
- markdown 子系统公共门面的补齐(web 与 CLI 共享读侧能力的接入点,见 §7 兼容性契约)。

### 1.3 明确非目标

| 非目标 | 说明 |
|---|---|
| db(dbquery)子系统对接 | 涉及凭据与只读安全模型,另议;UI 导航中以"后续"灰置占位,不可点开 |
| 对外 HTTP API 契约 | 服务对象是人(浏览器),不为程序/agent 消费设计稳定 API,不承诺接口兼容性;**不是** 1.x 被移除的 MCP server 的复活 |
| 任何写操作 | web 不触发:索引重建、validate、dedup、seen-names 管理、timeline install/uninstall、hook 写入。"只读"口径:不写 DB、不写源文件、不接受任何会改变目标项目状态的请求 |
| LAN 暴露与多用户 | 仅 localhost 访问,无鉴权、无会话、无用户概念 |
| 全文检索升级 | 沿用现有 LIKE 查询(CJK 兼容,不用 FTS5),不引入搜索引擎 |
| 时间线页面 | 属平行需求《cgraphx-web时间线浏览》;本 spec 仅在应用壳导航中为其保留入口 |

## 2. 术语与业务对象

| 对象 | 定义 |
|---|---|
| 知识文档 | `docs/knowledge/` 下带 frontmatter 的 markdown 文件,经 `cgraphx docs index` 索引后成为 `markdown_documents` 行。web 的一切文档数据来自索引 DB + 源文件,不解析未索引文件 |
| 概念 / 领域 / 标签 | 文档 frontmatter 中的 `concepts` / `domains` / `tags`,索引为 `markdown_concepts` / `markdown_domains` / `markdown_tags`,是三个并列的词汇维度 |
| 文档类型(document_type) | frontmatter 必填枚举,**共 17 种**(见 §3.3 类型标签表);`concept` 是知识库索引层的枢纽(实体概念主条目,如"商品"、"礼包") |
| 文档状态(status) | frontmatter 必填枚举,共 4 种:`draft`(草稿)/ `active`(现行)/ `superseded`(已被替代)/ `deprecated`(已废弃) |
| 文档 ID | 索引层分配的 64 位十六进制 ID;文档同时可按项目相对路径定位(与 CLI `docs show <doc-id-or-path>` 口径一致) |

**易混辨析**:「知识文档」是索引对象,「源文件」是磁盘上的 .md/.mdx 文件——索引可能滞后于源文件(用户改了文件没重建索引),web 的**元数据以索引为准、全文以源文件为准**,二者不一致时不试图调和(见 §4.2 新鲜度口径)。

## 3. 系统行为

### 3.1 服务启动与访问(`cgraphx web`)【基座】

| 场景 | 行为 |
|---|---|
| 正常启动 | 命令接口与现有子系统命令同构:`cgraphx web [project-path]`(默认当前目录,语义与 `docs` / `timeline` 各命令的 `[project-path]` 一致),另提供端口指定选项(选项名与默认端口值由 plan 定)。启动成功后在终端打印可点击的本地访问地址,进程常驻直到用户终止 |
| 绑定地址 | **仅本机回环地址**,任何情况下不绑定可被局域网/外网访问的地址。这是安全契约,plan 不得以"方便调试"为由放开 |
| 目标项目未初始化 | 目标项目不存在 `.cgraphx/cgraphx.db`,或库中缺少 markdown / timeline 任一套 schema 表 → **启动失败并退出**,错误信息明确指出缺什么、引导运行 `cgraphx install`(2.0 中 `.cgraphx/` 创建与两套 schema 的应用由 `cgraphx install` 完成,无独立 `init` 命令)。不启动一个"半空"的服务 |
| 默认端口被占用 | 启动失败并退出,错误信息告知被占用的端口值,并提示用端口选项指定其他端口。**不**自动换端口(行为可预测优先) |
| 服务运行中 DB 被外部重建 | CLI 侧并发跑 `cgraphx docs index`(全量重建)时,web 的读请求**不报错**,可能读到重建前或重建后的快照(事务一致性由 SQLite 保证);不向用户呈现锁等待 |

### 3.2 应用壳与全局【基座】

- 左侧导航:**知识库**(本 spec)/ **开发时间线**(平行 spec 实现;基座先落导航入口)/**数据库**("后续"灰置占位,不可点击,明示 roadmap);
- 顶栏常驻状态标识:本地访问地址 + **只读**性质提示;
- 全站错误态:DB 读取失败(如库文件损坏)→ 页面级错误态 + 可读的错误原因,不允许白屏或抛原始堆栈给用户;
- 加载态:数据请求期间有明确的加载中呈现,不闪烁、不留空白假象。

### 3.3 知识库总览页

**页面结构**:左侧固定筛选面板 + 右侧主区(统计条 → 文档列表)。

**统计条**:文档总数、概念总数、领域总数、标签总数,取自索引 DB 实时计数;页面顶部展示最近索引时间(全库最新 `indexed_at`)。

**筛选面板**(各组均为多选/可组合,激活条件以可删除 pill 悬挂于列表上方,条件 ≥2 个时出现「清除全部」):

1. **关键词搜索**:匹配标题、摘要、概念名、标签名、领域名(即现有 `find` 的 `q` 维度,匹配范围为 title + summary_text;概念/标签/领域名命中与否以现有查询实现为准)。提供键盘快捷键 `/` 聚焦搜索框;
2. **文档类型过滤**:列出**全部 17 种**类型,各带当前计数(计数随其他筛选条件联动与否由 plan 定,但类型全集必须完整可见),**按使用频率降序**排列。显示标签采用「中文名 + 英文原值」,映射表如下(英文原值为 frontmatter 契约,不可改):

   | 英文原值 | 显示标签 | 英文原值 | 显示标签 |
   |---|---|---|---|
   | concept | 实体概念 | runbook | 运维手册 |
   | decision | 决策 | installation | 安装部署 |
   | rule | 规则 | api | API |
   | lesson | 教训 | faq | FAQ |
   | warning | 警示 | architecture | 架构 |
   | finding | 发现 | guide | 指南 |
   | analysis | 分析 | tutorial | 教程 |
   | exploration | 探索 | conversation | 对话 |
   | note | 笔记 | | |

   类型徽标的色系分组(17 种不可能各一色)属 UI 实现细节,约束仅为:同页内同类型徽标颜色一致、可肉眼区分出"这不是文字而是类型标记";
3. **状态过滤**:列出全部 4 种状态(draft/active/superseded/deprecated),显示标签:草稿 / 现行 / 已被替代 / 已废弃;
4. **领域过滤**:列出全部领域及计数;
5. **热门概念**:概念排行列表(名称 + 篇数 + 占比条),按篇数降序;概念总量大时的"查看更多/搜索概念"入口由 plan 定,但首页必须能呈现最常用的那一批。

**文档列表**:
- 每张文档卡展示:类型徽标(中文 + 英文小标)、标题(+ alias)、摘要(最多三行,超出截断)、概念标签行(可点击,点击即追加为概念筛选条件)、负责人、状态、领域、引用数(出向 + 入向合计)、更新时间;
- 排序:提供「最近更新」(默认,按 updated 降序)与「名称」两种切换;
- **不允许静默截断**:现有 `find` 单次返回上限为 100 条。匹配结果超过一屏/单次上限时,必须提供浏览全量匹配结果的手段(分页或"加载更多",形态由 plan 定),并在界面上呈现匹配总数,用户必须能感知"还有更多";
- 点击卡片进入文档详情;
- 空结果:空状态提示 + 一键重置全部筛选。

### 3.4 文档详情页

- **头部**:类型徽标、大标题、alias / 领域 / 状态辅助行;
- **元数据网格**(来自索引):负责人、领域、创建时间、更新时间、概念、标签、相关代码(related_code)、索引时间(该文档的 `indexed_at`);
- **摘要块**:frontmatter 的 Summary 段落(索引中的 summary_text);
- **全文渲染**:渲染源文件 markdown 正文,至少正确呈现:标题层级、段落、列表、行内代码与代码块、表格、引用块。**渲染数据源是索引中记录的文档路径对应的源文件**(见 §5.2 路径边界);
- **双向引用栏**:出向引用(本文档 → 其他)与入向引用(其他 → 本文档)分区列出,每项可点击跳转对应文档详情(与 CLI `docs refs` 数据同源,`getReferences`);
- **文档标识**:展示文档 ID 与项目相对路径,便于用户回到 CLI/编辑器定位;
- 详情页不存在的操作:编辑、删除、重建索引等一切写入口。

## 4. 数据、状态与口径

### 4.1 读写的数据

| 数据 | 访问方式 |
|---|---|
| `markdown_*` 表 | 只读查询,经 markdown 子系统公共门面(§7) |
| `docs/knowledge/` 源文件 | 只读,且仅限全文渲染场景、仅限索引记录过的路径(§5.2) |
| `.cgraphx/cgraphx.db` 文件本身 | 服务不创建、不迁移、不写入;schema 应用是 `cgraphx init` 的职责 |

(timeline 表的访问见平行 spec。)

### 4.2 新鲜度与时区口径

- **无新鲜度 SLA**:本地工具,查到什么就是 DB 里什么。索引滞后由用户在 CLI 跑 `cgraphx docs index` 解决,web 的职责是**让滞后可见**:知识库总览显示全库最近索引时间,文档详情显示该文档索引时间;
- **元数据 vs 全文**:元数据以索引为准,全文以源文件当前内容为准。源文件被改但未重建索引时,详情页全文与元数据(如摘要)可能不一致——不提示、不调和、不阻塞(用户看到全文即最新,元数据滞后是可接受的);
- **时间显示(全站口径,两个子需求共用)**:所有时间字段在界面上呈现为**浏览器本地时区**;DB 存储口径不变(沿用现有 UTC ISO 8601);
- 读请求天然幂等,重复请求返回相同结果(除非期间有 CLI 侧重建)。

## 5. 权限、安全与边界【基座 + 知识库】

### 5.1 访问边界(基座)

- **仅 localhost**:服务只接受本机回环连接,无鉴权机制(也不需要——localhost 即信任边界);
- 无角色、无审计日志、无用户概念。

### 5.2 路径边界(全文渲染)

- 全文渲染**只接受从索引 DB 中取得的文档路径**(`markdown_documents.path`),不接受请求侧传入的任意文件路径;
- 即:不存在"给个路径就渲染"的端点,只有"给文档 ID/索引路径 → 服务自行从 DB 解析出源文件路径 → 渲染";
- 源文件读取失败(被删/无权限)→ 详情页元数据正常展示,全文区域呈现"源文件缺失或不可读"+ 路径,不报错退出。

## 6. 接口、页面与系统边界

- **命令接口**:`cgraphx web [project-path]` + 端口选项。选项命名、默认端口值由 plan 定;错误输出风格沿用 CLI 现有约定(手写 ANSI,不引 chalk);
- **页面**(本 spec):知识库总览、文档详情,共 2 个;无登录页、无设置页;导航中的开发时间线页面属平行 spec;
- **依赖边界**:web 仅依赖 `src/core/`(markdown 门面 + DB 基础层 + directory;timeline 门面由平行 spec 接入);不依赖 `src/cli/`;core 不因本需求产生对 cli/web 的反向依赖;
- **与 CLI 的关系**:web 与 CLI 是 core 的两个平行消费方,共享同一 DB 文件;web 不调用 CLI 进程,CLI 不感知 web 运行。

## 7. 兼容性、迁移与存量

- **零存量调用方**:web 层全新,无任何需要兼容的旧接口/旧页面;
- **CLI 行为不许变**(硬契约):本次为补齐 markdown 子系统公共门面所做的任何调整,必须保证 `cgraphx docs` 全部 10 个子命令(index / concepts / domains / tags / find / refs / dedup / seen-names / show / validate)的行为与输出不变,以 `__tests__/core/markdown/` 现有测试为回归基线;
- **资产分发**:web 的前端资产(若有静态资源)必须纳入 `scripts/copy-assets.cjs` 构建期清单并镜像到 `dist/`,否则不随包发布(CLAUDE.md 既有约定);
- **版本号**:沿用 `cli/index.ts` 运行时从 `package.json` 读取的版本号机制,web 页面展示的 cgraphx 版本取自同一来源。

## 8. 异常与边界场景

| 场景 | 期望行为 |
|---|---|
| 目标项目未初始化 / schema 缺失 | 启动失败,错误引导 `cgraphx install`(§3.1) |
| 端口被占用 | 启动失败,报错 + 提示换端口(§3.1) |
| 知识库已初始化但 0 篇文档 | 服务正常启动;知识库页空状态,引导运行 `cgraphx docs index`;统计条计数为 0 而非报错 |
| 文档 ID/路径不存在 | 详情页"未找到"状态 + 返回列表入口(对应 `DocumentNotFoundError` 语义) |
| 源文件缺失/不可读 | 详情页元数据正常 + 全文区缺失提示(§5.2) |
| DB 文件损坏/不可读 | 页面级错误态 + 可读原因,不白屏(§3.2) |
| 筛选组合命中 0 结果 | 空状态 + 重置筛选入口,与"全库为空"的空状态文案区分 |
| 匹配结果超单次上限 | 呈现匹配总数 + 浏览全量手段,不静默截断(§3.3) |
| frontmatter 异常值(脏枚举) | 索引层已保证入库枚举合法(`validator` 前置),web 按枚举信任处理;个别展示字段缺失时优雅降级(显示占位而非崩溃) |

## 9. 验收标准与测试关注点

**验收**(业务可观察):

1. 在已初始化项目执行 `cgraphx web`,浏览器打开打印的地址,应用壳(导航三入口、数据库灰置、顶栏只读标识)符合设计稿,知识库两个页面可用;
2. 筛选面板的类型(17 种全集,按频率降序)、状态(4 种)、领域、概念、关键词五维可任意组合,激活条件以 pill 呈现且可单独移除/一键清除,结果计数正确;
3. 文档详情正确渲染 markdown 全文(含代码块、表格、CJK),元数据网格、双向引用跳转、文档 ID/路径展示齐全;
4. §8 全部异常场景行为符合描述(未初始化 / 端口占用 / 空库 / 源文件缺失 / 文档不存在);
5. CLI 回归:`__tests__/core/markdown/` 全绿,`cgraphx docs` 手工抽查行为不变;
6. 只读契约可断言:任何 web 请求不产生 DB 写入、不产生文件写入。

**测试关注点**:多维筛选组合的边界(空组合 = 全量、互斥维度组合 = 空集);17 种类型计数与实际索引一致;本地时区换算(沿用仓库既有手法:派生带显式 `TZ` 的子进程验证,不为本地时区改 TZ 处理逻辑)。

## 10. Plan 编写约束

- **分层铁律**(2.0-spec §3.1):web 只依赖 core;core 不得因本需求产生对 cli/web 的反向依赖;
- **markdown 门面补齐方式**:现有 markdown 子系统无 `index.ts` 公共门面(CLI 直接引用内部模块),本需求需要补门面供 web 消费;门面补齐必须与 CLI 现有调用路径兼容(CLI 可同步切门面,也可暂不切,由 plan 论证,但任何方案不得破坏 CLI 行为);
- **不重写读侧逻辑**:`MarkdownQuery` 的查询实现直接复用,不为 web 另起一套查询;
- **不引入 chalk**(CLI 既有约定,手写 ANSI);
- **前端技术形态由 plan 论证后拍板**:HTTP 服务实现、是否引入前端框架/构建链、markdown 渲染方案、前端资产组织与分发——均在 plan 阶段决定;约束仅为:最终产物必须能随单包 `npm` 分发(不要求用户额外安装/构建)、保持包"无原生依赖、无 wasm"的现状;
- **plan 自定项**:端口默认值与选项名、DB 连接生命周期(进程内单连接 vs 按请求)、概念列表"查看更多"形态、列表分页 vs 加载更多、筛选计数联动策略、类型徽标色系分组。

## 11. 不可留到实现期的决策

以下已定,实现期不得自行调整:

1. **服务性质**:本地、只读、面向浏览器;仅 localhost 绑定;无鉴权;
2. **能力面**:词汇列表(概念/领域/标签)+ 多维 find + 双向引用 + 文档详情 + 全文渲染;
3. **只读口径**:不写 DB、不写源文件、无写操作端点;
4. **类型与状态枚举全集**:类型 17 种全列出(含 §3.3 显示标签映射表),状态 4 种全列出;
5. **新鲜度呈现**:全库最近索引时间 + 单文档索引时间必须可见;
6. **时区口径(全站)**:界面按浏览器本地时区呈现;
