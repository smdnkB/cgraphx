## T-1: 程序:日期段统一识别

- 目标:按 C-1 新增 `parseFeatureId`,features 扫描和 task 命名都改用它——目录名里第一段日期不论在哪都能识别;以 `YYYY-MM-DD-` 开头的目录名,日期、标题、目录任务名与现在逐字相同。
- 对应 spec 编号:F3(①②③)、D4 🔒、D5;全局约束「默认格式零变化」
- 强制引用:`docs/guides/coding-standards.md`
- 依赖:无;与 T-2、T-3 同时跑。
- 涉及范围:
  - 新建 `src/core/features/feature-id.ts`
  - `src/core/features/index.ts`:门面导出 `parseFeatureId` 与类型 `ParsedFeatureId`
  - `src/core/features/scanner.ts`:删掉 `FEATURE_ID_PATTERN`(第 41–42 行);`scanFeatures` 里取 `dateFromName`、`title` 的两行(第 284–286 行)改用 `parseFeatureId`
  - `src/core/features/types.ts`:`FeatureEntry.title` 的注释(第 20 行)「目录名去掉日期前缀」改成「目录名去掉日期段」
  - `src/core/task/feature-name.ts`:删掉 `DATE_PREFIX_PATTERN`;`featureDatePrefix` 返回 `parseFeatureId(featureId).date`,`featureTaskName` 返回 `parseFeatureId(featureId).title`;从 `'../features'` 导入;文件头和两个函数的注释改成「日期段」
  - 只改注释:
    - `src/core/task/auto-binding.ts` 第 208 行(`isLaterFeature` 上方)与第 221 行(`deriveSessionAutoBinding` 上方「只有日期前缀更新的目录」):「日期前缀」→「日期段」
    - `src/core/task/resolve.ts` 第 83 行:「去掉日期前缀的任务名称」→「去掉日期段的任务名称」
    - `src/core/features/types.ts` 第 16 行 `featureId` 的注释:「格式 YYYY-MM-DD-[业务ID-]<标题>」→「默认格式 YYYY-MM-DD-[业务ID-]<标题>,项目可在 docs/guides/feature-standards.md 自定义」
- 必须严格执行:
  - 按 C-1:文件路径、导出名、类型、规则、门面导出都照 index 原文
  - `featureDatePrefix`、`featureTaskName` 的导出名与签名不变;`auto-binding.ts`、`store.ts`、`resolve.ts`、`feature-task.ts` 的调用代码不改(`feature-task.ts` 第 19 行的再导出保留)

  - `scanFeatures` 的其余逻辑不动:日期仍先取主 spec 头部 `> 日期:`、再 plan/index 头部、最后目录名;排序不变
  - 不动 `src/core/artifact-registry/`、`src/core/sync/`、`src/web/`、`src/cli/`
- 允许局部适配:
  - `feature-id.ts` 的内部实现(正则或逐段扫描都行)、内部辅助函数及其命名
  - 注释措辞
