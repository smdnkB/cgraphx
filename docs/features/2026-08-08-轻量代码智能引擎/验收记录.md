## 7. DEFECT-1 修复复验(2026-08-09)

### 7.1 根因(实际,非候选)

**根因不在 rpc-edges.ts,而在 `src/core/lbug/csv-generator.ts` 的节点 emit。**

排查路径:
1. rpc-edges.ts 与 fork 逐字节一致(diff 零差异)—— 单边创建逻辑(Phase 5a/5b、`ensureExternalServiceNode`、orphan consumer/provider)完整存在,**排除候选 C(移植缺陷)**
2. pruneLocalSymbols 仅剪枝 `Const|Variable|Static` + `scope==='block'` 的本地值符号,**从不触碰 ExternalService** —— **排除候选 A/B**
3. 临时埋点重跑 hx analyze,Phase 5 实际产出:`orphan consumer edges=526 + provider edges=1142,externalServiceNodes=35,extInGraph=35` —— 节点在 `ctx.graph` 内确实被创建(35 个)
4. 持久化层定位:`streamAllCSVsToDisk` 的 `switch (node.label)` 仅显式覆盖 File/Folder/Community/Process/Method/Section/Route/Tool/BasicBlock + `codeWriterMap`(Function/Class/Interface/CodeElement)+ `multiLangWriters`(19 种多语言类型)。**ExternalService 不在其中**,落入 `default` 分支的"未知标签:无 CSV 表,故意不持久化"路径被**静默丢弃**

即:T-9 把 ExternalService 写进了 `EXTERNAL_SERVICE_SCHEMA`(CREATE NODE TABLE,通用 code-element 列形)+ `NODE_TABLES`,但 csv-generator 的 emit 接线漏改。schema 注释本已写明"列形态通用,故 getCopyQuery 默认分支与 deleteNodesForFile 过滤均无需改动"——只差 emit 这一步。

级联效应:ExternalService 节点未持久化 → rel COPY 时 Method→ExternalService / ExternalService→Method 的 orphan RCALLS 边因 FK 端点缺失而一并丢失 → matched RCALLS(Method→Method,1447)正常持久化。

### 7.2 修法

`src/core/lbug/csv-generator.ts` 单文件 +30 行,四处接线(参照 Route/Tool/BasicBlock 同为合成特化节点的显式 case 模式):
1. 新建 `externalServiceWriter`(`externalservice.csv`,复用 `multiLangHeader`,列序与 `EXTERNAL_SERVICE_SCHEMA` 严格对齐)
2. `switch` 增 `case 'ExternalService'`(extractContent 对 `filePath=''` 短路返回空,行/列 -1)
3. 加入 `allWriters`(flush)+ `tableMap`(COPY 注册,走 `getCopyQuery` 默认分支)

rpc-edges.ts **零改动**(已与 fork 重新 diff 确认一致);埋点全部清除。
