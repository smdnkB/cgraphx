## 问题

问题 1–5 都已在 ce42ab9 修复,复验见每条最后一项。

### 1. 同一个仓库第二次 `install` 后,所有提交都失败(严重,已修)

- **现象:** 在一个仓库里 `install` 两次(升级时重跑、在 worktree 里再装一次),之后每次提交都报 `.git/hooks/commit-msg: line 5: unexpected EOF while looking for matching '`,提交失败;人手动提交也一样。只装一次的仓库正常。
- **原因(已复现):** 门禁片段里的 `printf '%s\n'` 写在 JS 模板字符串里,`\n` 成了真的换行(`src/core/commit-gate/gate.ts:247`),一行片段被拆成两行,只有后一行带 marker。重装时按 marker 删旧行,前一行删不掉,留下半句 shell。
- **影响:** 每次升级都要重跑 `install`,装过 2.0.14 的仓库升级一次就提不了交。违背「git 钩子片段不得让提交失败」。
- **修法:** 写成 `\\n`。
- **复验:** 同一仓库装两次后,人手动提交成功,钩子文件只有 3 行;worktree 和主目录都装、再卸载的整组 33 项全过。

### 2. 没装 cgraphx 的目录、没装的 agent 也提示「skill 是 2.0.11 之前装的」(中,已修)

- **现象:** 在没装 cgraphx 的目录跑任何命令(包括设计成任意目录可跑的 `cgraphx board`),每天第一条都在终端打出「cgraphx 提示(请在你的第一句回复里告诉用户):这个项目的 cgraphx skill 是 2.0.11 之前装的…」;项目只给 Claude Code 装过,在 CodeBuddy 会话里跑命令也会提示。
- **原因:** 版本提示在没有任何已装 agent 时退回按 Claude Code 判(`selectInstalledAgents`,`src/core/session-notices.ts:52`),会话是 CodeBuddy 时直接看 CodeBuddy;这家没有版本记录,就当成「2.0.11 之前装的」。原来的会话开始 hook 只在装过的项目里触发,碰不到这种情况;改成命令输出后,命令在哪都能跑。
- **影响:** 提示是写给 agent 的,agent 会叫人重装一个根本没装的项目;直接看终端的人看到的措辞也不对。
- **修法:** 只看在这个项目里装过 cgraphx 的 agent。2.0.11 之前装、没有版本记录的项目照旧提示。
- **复验:** 会话提示整组 21 项全过;从没装 cgraphx 的目录启动看板,不再打出这条提示。

### 3. 升级时没删掉已下掉的 task-history 子 agent(小,已修)

- **现象:** 装过 2.0.13 的项目重跑 `install` 后,`.claude/agents/task-history.md` 还在;同一次清理里 `/dev-handoff` 删掉了。本机主目录的 `.claude/agents/` 里就有这个文件。
- **原因:** 2.0.13 部署的是 `agents/task-history.md`,废弃清单登记的是 `agents/task-history`(`assets/claude-template/deprecated-assets.json:45`),路径对不上。
- **影响:** agent 还能调起这个子 agent,它用的 `cgraphx task` 命令已经没有了。
- **复验:** 种下旧的 `task-history.md` 和 `/dev-handoff` 后 install,两样都删掉了。本机已装项目要在新版 install 时才会清。

### 4. `DSH_HOME` 多拼了一层目录(小,已修)

DeepSeek 自己的 `DSH_HOME` 就是 `~/.dsh` 这一层(`deepseek-harness/packages/util/home-paths/src/index.ts`),cgraphx 却拼成 `$DSH_HOME/.dsh/sessions`(`src/core/agents/sources.ts:133`)。设了这个变量的人读不到 DeepSeek 会话,不报错。默认不设时正常。改成读 `$DSH_HOME/sessions`,spec D13 同步改了说法。复验:用户目录里没有 `.dsh`、只设 `DSH_HOME=~/.dsh` 时读到了 2841 条 DeepSeek 事件。

### 5. 刷新接口不带 `Origin` 也放行(小,已修)

带错的 `Origin` 会返回 403,但不带 `Origin` 会放行,比 spec D2「校验 Origin」宽松。改成必须带看板自己的地址(127.0.0.1 或 localhost,同一端口)。复验:不带 403、带对 200;在浏览器里点「刷新」照常 200。

### 首轮已修复(1e5d6b6)

- **在 worktree 副本里提交,会把别的项目的会话记进当前项目(严重)。** 提交记录的后台进程继承了钩子带的绝对路径 `GIT_DIR`,识别别的仓库时读到的都是当前仓库。改成后台进程一启动就清掉 git 只对当前仓库有效的环境变量。复验:旧构建把另一个仓库的会话和目录记进了 cgraphx,修复后没有。
- **`--no-verify` 跳过门禁的 agent 提交没标「跳过门禁」(中)。** 代码把「没有门禁记号」当成走过门禁,和 spec D14 不符。改成没有记号也算对不上。复验:跳过门禁的标了,走过门禁的、人手动的没标。
