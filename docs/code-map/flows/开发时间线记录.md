# 开发时间线记录 · 代码地图

> 派生视图:从代码生成,不手工修改。相关文件在 `source_commit` 之后有改动即视为过期,用 `/code-map-write` 重新生成。

## 一句话

两类事件会触发 hook,把一条记录写进 `timeline_events` 表:

- **agent 宿主的事件**:Claude Code 或 CodeBuddy 的会话开始 / 结束、提问、工具调用、一轮结束。
- **git 提交**:由项目的 post-commit 钩子触发。

每次触发都是一个短命的 hook 进程。几条关键规则:

- **来源 agent**:每条事件都记下自己来自哪个 agent。hook 命令带 `--agent` 时取该值,不带时视为 Claude Code。git 提交的来源,由读到的会话环境变量属于哪个 agent 推出。
- **turn_id 传递**:同一轮对话的多个 hook 进程,靠「每个会话一个」的状态文件共享 `turn_id`。
- **读方只读**:日报 / 周报、web 时间线页、`cgraphx task show` 与 web 开发任务页(后两者经 task 子系统)都只读这张表,读取输出不包含来源列。

## 代码链路:一轮对话中的 user_prompt 事件

看什么:

- `--agent` 在 cli 层被解析成 agentId,随事件写进库。
- turn_id 在 user_prompt hook 生成,经本会话自己的状态文件传给同一轮的其他 hook。
- 每次打开库都会补旧库缺的 agent 列。
- 任何失败都不阻塞宿主。

## 代码链路:会话起止与 git 提交

看什么:

- session_end 写完事件后,删掉本会话的 turn 文件。
- git 提交的 hash 与分支由钩子脚本在提交当下固定,经环境变量交给后台进程。
- git 提交的 session_id 和来源 agent 都来自继承的会话环境变量,不来自 stdin。

```mermaid

  participant G as git post-commit<br/>钩子脚本
  participant H as hooks.ts
  participant AP as agents 门面
  participant TS as turn-state.ts
  participant RC as recorder.ts

  AG->>H: sessionStartHook(agentId)(stdin 带 source)
  H->>RC: session_start 事件,metadata.source
  AG->>H: sessionEndHook(agentId)(stdin 带 reason)
  H->>RC: session_end 事件,metadata.reason
  H->>TS: removeTurnState(session_id)
  Note over G: 前台:git rev-parse HEAD / git symbolic-ref → hash、分支
  G->>H: gitCommitHook()(后台运行,不带 --agent)<br/>环境变量 CGRAPHX_COMMIT_SHA / CGRAPHX_COMMIT_BRANCH
  H->>AP: resolveSessionIdFromEnv()<br/>按登记顺序读 CLAUDE_CODE_SESSION_ID / CODEBUDDY_SESSION_ID
  Note over H: 读到 → session_id + 该变量所属 agent,<br/>终端手动 commit 读不到 → 两者都为空(未归属)

  H->>RC: git_commit 事件,metadata.branch
```

## 数据流转

看什么:

- 只有 hook 写表,读方都只读,读取输出不含 agent 列。
- turn 文件按会话隔离,只在同一会话同一轮的 hook 之间传值。
- 安装按 agent 写进各自的 settings,git 钩子每个项目只有一份。

```mermaid

  up[user_prompt hook] -- 写 turn_id --> tf[(.cgraphx/turns/会话id.json)]
  tf -- 读 turn_id --> rest[pre / post / stop hook]
  se[session_end hook] -- 删除 --> tf
  up -- INSERT 含 agent --> ev[(timeline_events<br/>schema v2 · agent 列)]
  rest -- INSERT --> ev
  ss[session_start hook] -- INSERT --> ev
  se -- INSERT --> ev
  git[git_commit hook] -- INSERT --> ev
  ev -- 查询 --> cli[cgraphx timeline 命令<br/>developer-timeline skill 使用]
  ev -- queryEvents / getEventStats --> web[web 时间线页]
  ev -- queryEvents / getSessionStats --> task[task 子系统<br/>task show · web 开发任务页<br/>见「开发任务绑定」「开发任务浏览」视图]
  inst[installTimelineHooks agent] -- 按 agent 写 hook 命令 --> settings[(.claude/settings.json<br/>.codebuddy/settings.json)]
  inst -- 每项目一份 --> pc[(.git/hooks/post-commit)]
```

## 已知盲区

- pre_tool_use 只记录写类工具(白名单过滤),图中没有展开过滤分支。
- git_commit 钩子由 `cgraphx timeline install` / `cgraphx install` 接入 git 侧,接入路径没有画。完整安装链路见 `flows/多agent安装.md`。
- git_commit 事件的 `ts` 是记录进程写库的时间,不是提交时间;连续提交时,写库顺序可能与提交顺序不同。
- 合并提交不触发 post-commit,不产生 git_commit 事件。
- 会话没有正常结束时(崩溃、强杀),`.cgraphx/turns/` 下的文件不会被删除,目前没有清理机制。
- 在 CodeBuddy 的 `-p` 非交互模式里实测,只看到 session_start 和 stop,没看到 session_end。交互模式下的 SessionEnd 还没有实测。
- task 子系统读 `timeline_events` 的具体方式见 `flows/开发任务绑定.md`,本图只画到门面。
