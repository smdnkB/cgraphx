# 开发任务绑定 · 代码地图

> 派生视图:从代码生成,不手工修改。相关文件在 `source_commit` 之后有改动即视为过期,用 `/code-map-write` 重新生成。

## 一句话

一个 Claude Code 会话在某个时间区间内绑定一个开发任务。绑定有两种来源:agent 执行 `cgraphx task use`,或会话改动了 spec 头部声明 `> 任务:` 的需求目录而自动绑定。事件归属哪个任务,不存在事件上,而是查询时用「会话 + 时间区间」去 join `timeline_events` 得出。task 只经门面读 timeline 和 features,反方向没有依赖。

## 代码链路:会话开始提醒与显式绑定

看什么:会话 id 的两个来源(hook 的 stdin、CLI 的环境变量 / `--session`);首次绑定把起点回溯到会话的第一条 timeline 事件。

```mermaid
sequenceDiagram
  participant CC as Claude Code
  participant HK as task/hooks.ts
  participant CLI as task/cli.ts
  participant RS as resolve.ts
  participant SRC as source.ts
  participant BD as binding.ts
  participant TL as timeline 门面
  participant ST as store.ts<br/>TaskStore

  CC->>HK: task-session-start-hook(stdin 含 session_id)
  HK->>BD: getCurrentBinding(session_id)
  HK-->>CC: stdout hookSpecificOutput.additionalContext<br/>已绑定任务 / 未绑定提示 + 当前会话 id
  CC->>CLI: agent 执行 cgraphx task use 值
  Note over CLI: 会话 = --session ?? 环境变量 CLAUDE_CODE_SESSION_ID,都没有 → 退出码 3
  CLI->>RS: resolveTaskForUse(值, manual)
  RS->>ST: 本地 id → 接口任务编号
  RS->>SRC: 已配置接口:fetchRemoteTasks → upsertApiTask
  RS->>ST: 手动任务名 → 新建手动任务 / 报错
  CLI->>BD: bindSession(session, task, 'cli')
  BD->>TL: 首次绑定:getSessionStats(session).first_ts
  BD->>ST: IMMEDIATE 事务:closeOpenBinding + insertBinding
  BD-->>CLI: bound / already / switched
```

## 代码链路:改动需求目录时自动绑定

看什么:「检查是否已绑定」和「写入绑定」在同一个事务里('ifUnbound' 模式),所以并发时也不会切走别的进程刚绑上的任务;同一对任务的提醒只出现一次。

```mermaid
sequenceDiagram
  participant CC as Claude Code
  participant HK as task/hooks.ts
  participant FL as feature-link.ts
  participant FT as features 门面
  participant RS as resolve.ts
  participant BD as binding.ts
  participant ST as store.ts

  CC->>HK: task-post-tool-use-hook<br/>(matcher Edit/Write/MultiEdit/NotebookEdit)
  HK->>FL: autoBindFromFeatureDir(session, file_path 或 notebook_path)
  Note over FL: 路径不在 docs/features/目录名/ 下 → 结束
  FL->>FT: readFeatureTask(目录) → 主 spec 头部 > 任务:
  FL->>RS: resolveDeclaredTask(声明值)<br/>未命中:有接口配置建占位,否则建手动任务
  FL->>BD: bindSessionCore(…, 'feature_dir', 'ifUnbound')
  alt 会话未绑定
    BD->>ST: insertBinding → bound
  else 已绑定其它任务 A
    FL->>ST: recordReminder(会话, A, B)
    FL-->>HK: 首次 → remind 文案
    HK-->>CC: stdout hookSpecificOutput.additionalContext
  end
```

## 数据流转

看什么:task 只写自己的 `task_*` 表;读 `timeline_events` 和 spec 头部都经门面,只读。

```mermaid
flowchart LR
  api[(外部任务接口<br/>GET url)] -- tasks JSON --> src[source.ts]
  cfg[(.cgraphx/task-source.json)] -- url / headers --> src
  src --> items[(task_items)]
  manual[task use 手动名称] --> items
  bind[binding.ts] -- 写 --> sess[(task_sessions<br/>一个会话最多一条生效)]
  fl[feature-link.ts] -- 写 --> rem[(task_reminders)]
  specs[(docs/features/*/<br/>*-spec.md 头部)] -- readFeatureTask / scanFeatureTasks --> fl
  ev[(timeline_events)] -- getSessionStats<br/>首次绑定起点 --> bind
  sess -- 会话 + 时间区间 --> show[getTaskDetail<br/>task show]
  ev -- queryEvents 按区间 --> show
  inst[cgraphx install] -- ensureTaskSchema + installTaskHooks --> settings[(.claude/settings.json)]
```

## 已知盲区

- 外部任务接口的地址来自目标项目的 `.cgraphx/task-source.json`,属运行时配置,图中不列实例。
- `getTaskDetail` 每条绑定区间最多取 10000 条事件,图中未画截断。
