# 开发任务绑定 · 代码地图

> 派生视图:从代码生成,不手工修改。相关文件在 `source_commit` 之后有改动即视为过期,用 `/code-map-write` 重新生成。

## 一句话

一个 agent 会话(Claude Code 或 CodeBuddy)在一段时间区间内绑定一个开发任务。绑定有两种来源:

- agent 执行 `cgraphx task use`;
- 会话改动了某个需求目录里的文件,而该目录的 spec 头部声明了 `> 任务:`,于是自动绑定。

事件不直接记录自己属于哪个任务。查询时用「会话 + 时间区间」去 join `timeline_events`,得出归属。

各 agent 的差异只从 agents 门面取:hook 命令带不带 `--agent`、写类工具有哪些、会话 id 读哪个环境变量。task 只经门面读 timeline、features、agents,反方向没有依赖。

## 代码链路:会话开始提醒与显式绑定

看什么:

- hook 带 `--agent` 时按对应 agent 处理;不带或无法识别时,按 Claude Code 处理。
- CLI 进程拿会话 id 的顺序:先看 `--session`,再按 agent 登记顺序读各 agent 的会话环境变量。
- 首次绑定会把起点回溯到会话的第一条 timeline 事件,所以事后补绑不丢数据。

## 代码链路:改动需求目录时自动绑定

看什么:

- 哪些工具算「写类工具」由 agent 描述的 `writeTools` 决定,安装时写成 settings 的 matcher,hook 里再判断一次。
- 「检查是否已绑定」和「写入绑定」在同一个事务里('ifUnbound' 模式),所以并发时也不会切走别的进程刚绑上的任务。

```mermaid
sequenceDiagram
  participant AG as agent 宿主
  participant HK as task/hooks.ts
  participant FL as feature-link.ts
  participant FT as features 门面
  participant RS as resolve.ts
  participant BD as binding.ts
  participant ST as store.ts

  AG->>HK: task-post-tool-use-hook [--agent id]<br/>(matcher = profile.writeTools)
  Note over HK: tool_name 不在 profile.writeTools → 结束
  HK->>FL: autoBindFromFeatureDir(session, file_path 或 notebook_path)
  Note over FL: 路径不在 docs/features/目录名/ 下 → 结束
  FL->>FT: readFeatureTask(目录) → 主 spec 头部 > 任务:
  FL->>RS: resolveDeclaredTask(声明值)
  FL->>BD: bindSessionCore(…, 'feature_dir', 'ifUnbound')
  alt 会话未绑定
    BD->>ST: insertBinding → bound
  else 已绑定其它任务 A
    FL->>ST: recordReminder(会话, A, B)
    FL-->>HK: 首次 → remind 文案
    HK-->>AG: stdout hookSpecificOutput.additionalContext
  end
```

## 数据流转

看什么:

- task 只写自己的 `task_*` 表;读 `timeline_events` 和 spec 头部都经门面,只读。
- hook 安装是按 agent 写进各自的 settings 文件。

```mermaid
flowchart LR
  api[(外部任务接口<br/>GET url)] -- tasks JSON --> src[source.ts]
  cfg[(.cgraphx/task-source.json)] -- url / headers --> src
  src --> items[(task_items)]
  manual[task use 手动名称] --> items
  bind[binding.ts] -- 写 --> sess[(task_sessions<br/>一个会话最多一条生效)]
  fl[feature-link.ts] -- 写 --> rem[(task_reminders)]
  specs[(docs/features/*/<br/>*-spec.md 头部)] -- readFeatureTask / scanFeatureTasks --> fl
  ev[(timeline_events)] -- getSessionStats<br/>首次绑定起点 --> bind
  sess -- 会话 + 时间区间 --> attr[attribution.ts<br/>queryBindingEvents 左闭右开]
  ev -- queryEvents 按绑定段 --> attr
  attr --> show[getTaskDetail<br/>task show]
  attr --> rep[report.ts<br/>web 开发任务页,见「开发任务浏览」视图]
  inst[cgraphx install<br/>agent-steps.ts] -- 每个选中 agent:installTaskHooks --> settings[(.claude/settings.json<br/>.codebuddy/settings.json)]
```

## 已知盲区

- 会话 id 环境变量是宿主注入的,没有官方文档保证。
  - Claude Code 的 `--resume` 恢复会话后 session_id 是否沿用,还没有实测;CodeBuddy 同样没有实测。
  - 两个 agent 嵌套启动时,会按登记顺序取 Claude Code 的变量,见知识库「会话 id 来源约束」。
- 外部任务接口的地址来自目标项目的 `.cgraphx/task-source.json`,属于运行时配置,图中不列具体实例。
- 每条绑定区间最多取 10000 条事件(`EVENTS_PER_BINDING_LIMIT`)。`task show` 截断时不提示,web 开发任务页会标注。
- web 开发任务页的只读链路(`openTaskDbReadOnly` → `report.ts`)见 `flows/开发任务浏览.md`,本图不展开。
