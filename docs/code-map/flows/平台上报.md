# 平台上报 · 代码地图

> 派生视图:从代码生成,不手工修改。相关文件在 `source_commit` 之后有改动即视为过期,用 `/code-map-write` 重新生成。

## 一句话

- **hook 只拉起进程**:agent 的 Stop / SessionEnd / SessionStart hook 只检查几个文件,然后拉起一个脱离的 `sync-worker`;所有网络请求都在 worker 里。
- **worker 怎么跑**:
  - 每轮持同步锁运行 `runSync`。
  - 从 timeline / task 门面只读取数,按白名单构造每个会话的上报内容,分批 POST 到平台的 `/ingest`。
  - 只有收到 200 才推进 `sync_sessions` 的进度。
  - 跑完睡 10 分钟,期间有新活动就再跑一轮。
- **接入**:`cgraphx sync connect` 用账号换凭据,写进任务源配置 `.cgraphx/task-source.json`;`docs` 命令在执行时写入精确参考记录。

## 代码链路:hook 拉起 worker

看什么:

- hook 不打开数据库(SessionStart 只读一次状态用于提示),不发网络请求。
- 「已有存活 worker」和「节流 1 分钟」两道检查,保证同一个仓库最多一个 worker。

```mermaid
  participant CLI as sync/cli.ts<br/>隐藏 hook 命令
  participant H as sync/hooks.ts
  participant CN as sync/connection.ts
  participant LK as sync/lock.ts
  participant SP as sync/spawn.ts
  participant W as sync-worker 进程

  AG->>CLI: sync-stop-hook / sync-session-start-hook(命令带 2>/dev/null || true)
  CLI->>H: syncStopHook / syncSessionStartHook(profile)
  Note over H: kill-switch 开启 → 直接返回,不读 stdin
  H->>H: runSyncHook:读 stdin → resolveProjectRoot → isInitialized
  H->>CN: readConnection(projectRoot)
  Note over H,CN: 任务源配置不是平台形态 → 视为未接入,直接返回
  opt SessionStart
    H->>H: readStatus → sessionStartNotice
    H-->>AG: stdout 一行 hookSpecificOutput(暂停 / 连续失败超 1 小时)
  end

  H-->>AG: 退出码 0
```

## 代码链路:worker 的一轮同步

看什么:

- 三类失败在 `sendBatch` 里分流:暂停、连续失败、隔离。
- 进度只在 `ackChunks` 里推进。

```mermaid
sequenceDiagram
  participant W as runner.ts<br/>runWorker / runSync
  participant LK as lock.ts
  participant ST as store.ts<br/>sync_* 表
  participant PL as payload.ts
  participant AR as artifacts.ts / references.ts
  participant TL as timeline / task 门面
  participant CL as client.ts
  participant P as 研发管理平台

  W->>LK: claimWorker(sync-worker.pid),失败 → 退出
  loop 每轮
    W->>LK: acquireLock(sync.lock),后台不等待,占用 → busy
    W->>ST: getStatus
    alt 已暂停
      W->>CL: getStatus(/status) 探测(后台 30 分钟一次,前台每次)
      CL-->>W: 成功 → 解除暂停 / 仍被拒 → 本轮结束
    end
    W->>PL: createSyncContext(一次性取齐 commit、绑定、参考记录、git 缓存)
    PL->>TL: listCommitEvents / listBindingsWithTask
    W->>TL: listSessionEventMaxIds
    W->>ST: listSessions → 候选判定(isAgentCandidate / terminalNeedsSend)
    W->>PL: buildSessionPayload × 候选 / buildTerminalPayload
    PL->>TL: listSessionEventsAfter(会话, 0)
    PL->>AR: collectSessionArtifacts / collectSessionReferences
    W->>W: dropUnsafePaths → chunkSession → packBatches
    W->>CL: postIngest(批)
    CL->>P: POST /api/client/v1/ingest
    alt 200
      W->>ST: ackChunks(推进 last_event_id / extras_hash / pending_push)
    else 413
      W->>W: sendHalves 对半拆批,单块再切事件
    else validation_failed
      W->>ST: 二分到单会话 → isolateSession
    else 不可重试拒绝
      W->>ST: pausedReason,本轮结束
    else 网络 / 5xx
      W->>ST: failingSince / lastError,本轮结束
    end
    W->>ST: setStatus(lastResult)
    W->>LK: releaseLock
    W->>W: sleep 10 分钟,activityMark(含 connectedAt)未变 → 退出循环
  end
  W->>LK: releaseWorker
```

## 数据流转

看什么:

- 平台上报只读 timeline / task 的数据。
- 只写 `sync_*` 四张表、两个标记文件和任务源配置。
- 出本机的只有 `/connect` / `/status` / `/ingest` 三个请求。

```mermaid
flowchart LR
  ev[(timeline_events)] -- listSessionEventMaxIds / listSessionEventsAfter / listCommitEvents --> pl[payload.ts]
  ts[(task_sessions + task_items)] -- listBindingsWithTask --> pl
  rr[(sync_reference_records)] -- 预载 --> pl
  docs[docs find / show --body] -- recordReferenceHit --> rr
  git[(本地 git<br/>远程跟踪引用)] -- branch -r --contains / show / ls-files --> pl
  pl -- IngestSession 批 --> plat[研发管理平台<br/>/ingest]
  plat -- 200 --> ss[(sync_sessions<br/>水位 / 哈希 / 隔离)]
  run[runner.ts] -- lastResult / 暂停 / 失败 --> st[(sync_state)]
  conn[connect] -- token --> tsj[(task-source.json)]
  conn -- connection --> st
  tsj -- readConnection --> run
  lock[(sync.lock<br/>sync-worker.pid<br/>sync-trigger)] --- run
  hook[sync hooks] -- 只读 --> lock
  hook -- SessionStart 读 --> st
```
