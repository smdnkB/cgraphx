# 系统交互 · 代码地图

> 派生视图:从代码生成,不手工修改。相关文件在 `source_commit` 之后有改动即视为过期,用 `/code-map-write` 重新生成。

## 一句话

cgraphx 由本地 CLI 和本地 web 组成。

**谁调用它**:

- agent 宿主,目前是 Claude Code 和 CodeBuddy。宿主通过 hook 调用:timeline 记录事件,task 回传上下文,sync 拉起后台同步进程。agent 也会直接调用 CLI。
- git 的 post-commit 钩子。

**它读写什么**:

- 项目内的 SQLite 和 markdown 文件;
- 各 agent 自己的配置目录;
- 本机 git,只读调用。

**对外有六类连接**:

1. 只读查业务库;
2. 经 HTTP 只读查询接口查库;
3. 研发管理平台:接入、上报,以及「我的任务」(就是任务源配置指向的任务接口);
4. 其他外部任务接口(没接平台时);
5. npm 自更新;
6. 浏览器从公网加载字体和画图组件。

## 交互图

看什么:

- 实线是本仓库代码发起的调用,虚线是外部系统调用 cgraphx。
- 两个 agent 宿主走同一套 hook 子命令。CodeBuddy 的命令带 `--agent codebuddy`。
- 所有网络请求都不在 hook 进程里发:sync hook 只拉起脱离的 `sync-worker`,由它去请求平台。
- 业务库、研发管理平台、npm、CDN 在本机之外,其余全部在本机。

## 已知盲区

- 业务库、HTTP 查询服务、任务源接口和研发管理平台的地址都是运行时配置,分别来自 `.cgraphx/db-profiles.json` 和 `.cgraphx/task-source.json`。图中不列具体实例。
- hook 进程内不发网络请求。外部任务接口只在 `cgraphx task` 命令里调用;平台请求只在 `cgraphx sync` 命令和 `sync-worker` 里发。
- `cgraphx report` 命令组只读写本地文件,没有对外连接,所以图中没画。
- 平台侧怎么处理这些请求,见 cgraphx-server 仓库 `docs/code-map/flows/客户端接入与上报.md`。上报链路见 `flows/平台上报.md`,安装链路见 `flows/多agent安装.md`。
- `cgraphx` 有两种调用方式,解析到的可执行文件不同,版本可能不一致:
  - agent 在 Bash 工具里调用 CLI 时,用的是加载 shell 配置之后 PATH 上的 `cgraphx`。
  - hook 进程直接继承宿主进程的 PATH。
  - sync hook 命令带 `2>/dev/null || true`,即使命中旧版二进制,也不会出现错误输出。
