# 项目

## Summary

项目是 cgraphx 记数据的单位:同一个项目在本机的各个目录(主目录、另一份 clone、worktree、需求副本、复制出来的目录)都记进同一份数据,放在用户目录的项目目录 `~/.cgraphx/projects/<目录名>/`(又称项目数据目录;目录名就是项目名称)——timeline 的表和 db-query 的项目级配置、日志都在这里;知识库索引和「我的需求」留在各目录本地的 `.cgraphx/`。项目只按名称认:项目名称是唯一身份,一字不差才算同一个项目(大小写算不同)。名字依次取记下的名字、工作区根有 origin 时地址最后一段的仓库名、装过的目录取目录名(子目录项目取子目录名),都没有就没有标识。地址只用于取默认名字和重名提示,不参与「是不是同一个项目」的比较。项目根是项目在本机出现过的目录;数据目录(数据位置)是一个目录此刻读写数据的地方,还没在新版 install 过、本地库里还有旧表的目录走旧库模式,照旧用本地 `.cgraphx/cgraphx.db`。用 `cgraphx project show / name / list / remove` 查看、改名、列出、删除。

补录的进度**跟着会话文件走,不跟项目数据**:用户级 `~/.cgraphx/sessions.db`(基础层 `session-index.ts`,0600)存每个会话文件解析到哪了(`session_files`)、开始目录认到的归属(`start_dirs`)、删过的项目(`removed_projects`,键是项目名称)、提示记录(`notices_shown`)、判断过重名的目录(`dirs_checked`)。`project remove` 只在 `removed_projects` 记一笔,偏移不动——重装后补录只收删除之后的事实,旧会话不补回;改名只清受影响根的 `start_dirs`(偏移不动),下次补录重新认。

## 命名与边界

- 规范名「项目」;代码里的项目标识是 `ProjectIdentity`(只有 `name`),命令组 `cgraphx project`。
- 项目、项目根、数据目录的区分:
  - 项目是一份数据,一个项目目录。
  - 项目根是这个项目在本机出现过的某个目录。一般是工作区根;一个仓库装了几个项目的,是各项目所在的子目录。主目录和需求副本都是项目根。
  - 数据目录是某个目录此刻读写数据的位置:并过旧数据的在项目目录,旧库模式在本地 `.cgraphx/`。
- 「是不是副本、主目录在哪」只给版本流程、features 与 project 的重名判断用(见「需求副本」),和数据放哪无关。
- 口径(定于 2026-11-05-数据按项目放用户目录;补录侧补充定于 2026-11-06-会话文件解析替代hooks):
  - K1 认项目:只比项目名称,一字不差才算同一个项目(大小写算不同)。名字依次取:记下的名字(工作区根读 `cgraphx.projectName`,子目录项目读 `cgraphx.<子目录>.projectName`,不在 git 里读本地 `.cgraphx/project.json` 的 `name`)、工作区根有 origin 时地址最后一段的仓库名、装过的目录取目录名。地址不参与比较。算:同一个地址的不同 clone(地址相同、目录不同);同名但地址不同的仓库(fork 与上游);改了地址、换了 URL 重新 clone 的老目录。不算:地址相同但名字不同(`cgraphx project name` 改成过别的名字)。
  - K6 install 时记下名字:所有项目 install 时都问一次名字(默认名打底,回车即用);`-y` 与 `cgraphx upgrade` 不问,用默认名字并写回。名字存本地 git 配置——工作区根写 `cgraphx.projectName`,子目录项目写 `[cgraphx "<子目录>"] projectName`;不在 git 里的目录写本地 `.cgraphx/project.json` 的 `name`。worktree 共用这份配置,之后开的副本、带过去的复制目录读到同一个名字。
  - K18 提交记到哪:在哪个仓库提交,就记到那个仓库的项目,不看是哪个会话里提交的。一个仓库装了几个项目的,改了哪个子目录下的文件就记到哪个项目,几个都改了各记一条,只改仓库根目录文件的不记。
  - K7 项目目录名:目录名就是名字。不能做文件名的字符(`/ \ : * ? " < > |` 与控制字符)换成 `-`,去掉首尾的 `.` 和空格,超过 120 个字截断(截断后再去一次首尾);清空后什么都不剩就用 `-`。撞名时加 `-2`、`-3`(同名,或文件系统不分大小写时 `api` 与 `API` 撞到同一路径),哪个目录是哪个项目以目录里 `identity.json` 的 `name` 为准。
  - K14、K15 列出与删除:`project list` 列用户目录里的每个项目,目录已经不在了的也列。`project remove <目录名>` 删整个项目:事件、会话、任务绑定、上报进度、项目级配置、备份。删之前先列出会删的内容,确认后才删;非交互终端要加 `--yes`。删过之后在用户级 sessions.db 的 `removed_projects` 记一笔(项目名称加时间),补录偏移不动,重装后只收删除之后的事实。
  - 重名提示(定于 2026-11-06-项目按名称认):新目录第一次跑非隐藏的 cgraphx 命令或 install 时判断一次。项目库里已经有别的根记过这个项目、又不属于同一个项目(同一仓库的其他 worktree、登记过的副本、项目还没记过地址、这个目录的地址已在项目的 `origins` 里)时提示一次:项目名、最近活动的那个根,和「这个目录也记进去、数据库连接配置也共用」;不是同一个项目就 `cgraphx project name <名称>` 改名。判过的目录记进 sessions.db 的 `dirs_checked`,不再判断。提示只写 stderr(install 里用 clack 输出),数据照样记进去,不影响命令结果与退出码,`--json` 的 stdout 不混提示。
  - K13 卸载:只删这个目录的 git 钩子片段和本地 `.cgraphx/`;项目的数据不删,哪怕这是这个项目在本机的最后一个目录。
- 补录侧的归属口径(会话文件按开始目录认):start_cwd 还在就现认(同一趟按目录记住、git 按根只跑一次),目录不在了才用 `start_dirs` 缓存,再按本项目库的 `timeline_roots` 和副本登记匹配;认出哪个项目就记进哪个项目的库;别的项目的文件不代推进偏移,它的项目自己补。

## 关键约束与陷阱

- **项目目录只经 `ensureProjectDir` 建,读的地方不建**:
  - 写数据的入口才建目录:补录写事件、提交记录、`db init`、install。
  - 读的地方一律不建目录、不写并过记号:timeline 查询用只读路径打开;补录在项目目录不在(没装过也从没记过数据)时静默不补,查询报自己的错。
  - `ensureDataDir` 在装过的目录里会建出项目目录、写上并过记号;只读的调用方用了它,就会「读」出一个项目目录来。
- **没装过的目录,项目目录已经在才记进去**:另一份 clone、没装过的 worktree,只要项目目录已经在就照记;项目一次都没装过的,不建目录、不记。
- **会话按开始目录认归属,目录还在就现认**:
  - 补录按会话文件的 start_cwd 认:目录还在就现认(改名、换过项目目录之后才对得上),同一趟按开始目录记住、git 按根只跑一次;目录不在了才用 sessions.db 的 `start_dirs` 缓存,再退到本项目库的 `timeline_roots` 和副本登记兜底。
  - 缓存行仍然写,给目录被删之后兜底;git 跑不起来的那一趟不写,下次再认。
  - 所以会话 cd 到别的项目里调用的工具,也记在会话开始的那个项目。
  - 旧登记目录 `~/.cgraphx/sessions/` 在时间线重建时删掉(和 sessions.db 是两回事)。
- **提交事件的 cwd 记的是工作区根,不是项目根**:子目录项目的根是「工作区根/子目录」。按 cwd 给提交找根时,要拼上项目根在仓库里的相对位置;timeline 给提交归根时会碰到这一点。
- **`timeline_roots` 是项目的根清单**:每写一批事件在同一事务里 upsert 一次,根按 realpath 存。hook 退役后写入方是补录管线(`timeline/ingest/ingest.ts`,不然删掉目录的会话再认不回来);`project show`、改名提示从这张表来。
- **项目名称存在本地 git 配置里**:工作区根的项目是 `cgraphx.projectName`,子目录项目是 `[cgraphx "<子目录>"] projectName`;不在 git 里的目录存 `.cgraphx/project.json` 的 `name`。worktree 共用这份配置,`cp -R` 和副本带着走,新 clone 没有;uninstall 不删它。
- **`identity.json` 版本 2,只按 `name` 认**:项目目录里的 `identity.json` 是 `version`、`name`、`origins`、`createdAt`;`origins` 存项目记下的地址(规整后,只给重名判断用,不参与项目比较)。版本 1 带 name 的照认,只有 origin 的算标识缺失(`project list` 标「标识缺失」),不写迁移。
- **改名只影响之后**:之前记的留在原来的项目目录,`project name` 会提示「之前记的 N 条还在 <旧名> 下」;同时清掉受影响根的 `start_dirs` 行(偏移不动),下次补录重新认。旧库模式的目录不能改名(退出码 2),先 install 并过去。
- `~/.cgraphx/` 根下不放 `cgraphx.db`。`~/.cgraphx/db-profiles.json` 是用户级的 db-query 配置,和数据目录里的项目级配置两层合并。
- sessions.db 是 cgraphx 自身基础设施,不走 data-standards 的版本表机制;里面有项目根路径,权限 0600。`dirs_checked` 记判断过重名的目录(按 realpath 的根),不过期;只有走完判断才写(没根、旧库模式、项目目录还没建、没有标识、git 出错、项目库读不出都不写,留给下次)。

## 代码入口

- 基础层 `src/core/`:
  - `project-identity.ts`:认名字(记下的名字 → 仓库名 → 目录名)、规整 origin、读写项目名称。
  - `repo-projects.ts`:一个仓库里装着的几个项目,同仓库还装着的其他目录。
  - `user-data-dir.ts`:项目目录的查找与建立、`identity.json`(版本 2,带 `origins`)。
  - `session-index.ts`:用户级 sessions.db(五表:补录进度、开始目录、删除记录、提示记录、判断过的目录)。
  - `data-location.ts`:数据位置、旧库模式判定、`.cgraphx/project.json`。
  - `root-match.ts`:按根匹配路径。
- `src/core/project/`:`cgraphx project` 子系统(show / name / list / remove),以及 install 用的问名字、并旧数据;重名提示在 `duplicate.ts`。
- `src/core/timeline/git-commit.ts`:提交按工作区根认项目,一个仓库几个项目时按文件分;`src/core/timeline/roots.ts`:读 `timeline_roots`。
- `src/core/timeline/ingest/ingest.ts`:会话文件按开始目录认归属、写事件与根。

## 相关表

- 项目库 `~/.cgraphx/projects/<目录名>/cgraphx.db`:`timeline_*`(含 `timeline_roots`、`timeline_meta` 的重建记号)。本地 `.cgraphx/cgraphx.db` 只留知识库的 `markdown_*`,旧库模式的目录除外。
- 用户级 `~/.cgraphx/sessions.db`(`session-index.ts` 建表,幂等):
  - `session_files`(path 主键):每个会话文件的进度——agent、session_id、start_cwd、project_dir、byte_offset、size、mtime_ms。
  - `start_dirs`(cwd 主键):开始目录认到的归属(root、name、project_dir;`origin` 是旧列,不再读写)。
  - `removed_projects`(identity_key 主键):删过的项目与时间,键是项目名称。
  - `notices_shown`(scope 主键):提示的频控记录,打开时删 30 天前的行。
  - `dirs_checked`(root 主键、checked_at):判断过重名的目录,不过期。
- 文件:
  - 项目目录里的 `identity.json`(`version`、`name`、`origins`、`createdAt`)和 `backups/`。
  - 本地的 `.cgraphx/project.json`(`mergedAt`、`mergedInto`、`name`)。
