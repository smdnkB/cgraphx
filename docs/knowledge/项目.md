# 项目

## Summary

项目是 cgraphx 记数据的单位:同一个项目在本机的各个目录(主目录、另一份 clone、worktree、需求副本、复制出来的目录)都记进同一份数据,放在用户目录的项目目录 `~/.cgraphx/projects/<目录名>/`(又称项目数据目录)——timeline、task、sync 共用的 `cgraphx.db`、轮次文件、task 接口配置、sync 的锁、db-query 的项目级配置和日志都在这里;知识库索引和「我的需求」留在各目录本地的 `.cgraphx/`。项目按项目标识认:有 origin 的按规整后的 origin,没有 origin 的按项目名称;一个仓库装了几个项目时,按 origin 加子目录的项目名称认。项目根是项目在本机出现过的目录;数据目录(数据位置)是一个目录此刻读写数据的地方,还没在新版 install 过、本地库里还有旧表的目录走旧库模式,照旧用本地 `.cgraphx/cgraphx.db`。用 `cgraphx project show / name / list / remove` 查看、改名、列出、删除。

## 命名与边界

- 规范名「项目」;代码里的项目标识是 `ProjectIdentity`(`origin`、`name` 两项),命令组 `cgraphx project`。
- 项目、项目根、数据目录的区分:
  - 项目是一份数据,一个项目目录。
  - 项目根是这个项目在本机出现过的某个目录。一般是工作区根;一个仓库装了几个项目的,是各项目所在的子目录。主目录和需求副本都是项目根。
  - 数据目录是某个目录此刻读写数据的位置:并过旧数据的在项目目录,旧库模式在本地 `.cgraphx/`。
- 「是不是副本、主目录在哪」只给版本流程和 features 用(见「需求副本」),和数据放哪无关。
- 口径(定于 2026-11-05-数据按项目放用户目录):
  - K1 认项目:有 origin 的按规整后的 origin 比,ssh 和 https 两种写法、末尾的 `.git`、末尾的 `/` 都不看;没有 origin 的按项目名称。算:`git@github.com:demo/app.git` 和 `https://github.com/demo/app/` 是同一个项目。不算:同名但 origin 不同的仓库。
  - K6 项目名称管哪些目录:在哪个目录指定,就管这个目录、它的 worktree 和之后从它复制出来的目录;别的 clone、之前复制出来的照旧,已经记下的数据不挪。install 时根没有 origin、或根在仓库的子目录里,才需要名字(交互时问,`-y` 用目录名)。
  - K18 提交记到哪:在哪个仓库提交,就记到那个仓库的项目,不看是哪个会话里提交的。一个仓库装了几个项目的,改了哪个子目录下的文件就记到哪个项目,几个都改了各记一条,只改仓库根目录文件的不记。
  - K7 项目目录名:按 origin 认的,取地址里的主机、组织、仓库名用 `-` 连起来,如 `github.com-demo-app`。子目录项目再接上名字,如 `github.com-demo-platform-server`,显示成 `github.com/demo/platform#server`。只按名字认的就是名字。撞名时加 `-2`、`-3`,哪个目录是哪个项目以目录里的 `identity.json` 为准。
  - K14、K15 列出与删除:`project list` 列用户目录里的每个项目,目录已经不在了的也列。`project remove <目录名>` 删整个项目:事件、会话、任务绑定、上报进度、项目级配置、备份。删之前先列出会删的内容,确认后才删;非交互终端要加 `--yes`。
  - K13 卸载:只删这个目录的 hook 配置和本地 `.cgraphx/`;项目的数据不删,哪怕这是这个项目在本机的最后一个目录。

## 关键约束与陷阱

- **项目目录只经 `ensureProjectDir` 建,读的地方不建**:
  - 写数据的入口才建目录:hook 记事件、`db init`、install。
  - 读的地方一律不建目录、不写并过记号:timeline 用 `openTimelineDbForRead`,task 用 `openTaskDbReadOnly`,sync 用 `openSyncDbForRead`(库在、sync 表不在也当未初始化);web 全程只读。
  - `ensureDataDir`、`openTaskDb` 在装过的目录里会建出项目目录、写上并过记号;只读的调用方(如 `sync status`)用了它们,就会「读」出一个项目目录来。
- **没装过的目录,项目目录已经在才记进去**:另一份 clone、没装过的 worktree,只要项目目录已经在就照记;项目一次都没装过的,不建目录、不记。
- **会话按开始的目录认根,之后的 hook 不再跑 git**:
  - 会话开始的 hook 认一次,写进 `~/.cgraphx/sessions/<会话>.json`,登记 7 天后清掉;之后的 hook 按这份登记找根。
  - 所以会话 cd 到别的项目里调用的工具,也记在会话开始的那个项目。
  - 登记还没有时,认根的起点先用 `CLAUDE_PROJECT_DIR`。
- **提交事件的 cwd 记的是工作区根,不是项目根**:子目录项目的根是「工作区根/子目录」。按 cwd 给提交找根时,要拼上项目根在仓库里的相对位置;sync 算产出归属、timeline 给提交归根时都会碰到这一点。
- **上报归属不能看当前根**:同一项目里哪个目录触发 sync,结果都要一样(spec D13)。归属只看「改它的根」「提交的根」;有待推送提交的会话每轮都会重算,一依赖当前根,产出清单就会来回变。
- **linked worktree 里的 git 钩子带绝对路径的 `GIT_DIR`**:钩子进程到别的目录再跑 git,读到的还是钩子所在的那个仓库。
- **`timeline_roots` 是项目的根清单**:每记一条事件,在同一个事务里 upsert 一次,根按 realpath 存。`project show`、改名提示,以及 task、sync 的根汇总都从这张表来。
- **项目名称存在本地 git 配置里**:工作区根的项目是 `cgraphx.projectName`,子目录项目是 `[cgraphx "<子目录>"] projectName`;不在 git 里的目录存 `.cgraphx/project.json` 的 `name`。worktree 共用这份配置,`cp -R` 和副本带着走,新 clone 没有;uninstall 不删它。
- **改名只影响之后**:之前记的留在原来的项目目录,`project name` 会提示「之前记的 N 条还在 <旧名> 下」。旧库模式的目录不能改名(退出码 2),先 install 并过去。
- `~/.cgraphx/` 根下不放 `cgraphx.db`。`~/.cgraphx/db-profiles.json` 是用户级的 db-query 配置,和数据目录里的项目级配置两层合并。

## 代码入口

- 基础层 `src/core/`:
  - `project-identity.ts`:规整 origin、读写项目名称。
  - `repo-projects.ts`:一个仓库里装着的几个项目,同仓库还装着的其他目录。
  - `user-data-dir.ts`:项目目录的查找与建立、`identity.json`。
  - `session-registry.ts`:会话登记。
  - `data-location.ts`:数据位置、旧库模式判定、`.cgraphx/project.json`。
  - `root-match.ts`:按根匹配路径。
- `src/core/project/`:`cgraphx project` 子系统(show / name / list / remove),以及 install 用的问名字、并旧数据。
- `src/core/timeline/git-commit.ts`:提交按工作区根认项目,一个仓库几个项目时按文件分;`src/core/timeline/roots.ts`:读 `timeline_roots`。
- `src/core/task/roots.ts`:`collectProjectRoots`,汇总 timeline 记下的根、当前根和这些根上的副本登记。
- `src/core/sync/artifacts.ts`:上报产出按「改它的根」「提交的根」归属。

## 相关表

- 项目库 `~/.cgraphx/projects/<目录名>/cgraphx.db`:`timeline_*`(含 `timeline_roots`)、`task_*`、`sync_*`。本地 `.cgraphx/cgraphx.db` 只留知识库的 `markdown_*`,旧库模式的目录除外。
- 文件:
  - 项目目录里的 `identity.json`(`version`、`origin`、`name`、`createdAt`)和 `backups/`。
  - 本地的 `.cgraphx/project.json`(`mergedAt`、`mergedInto`、`name`)。
