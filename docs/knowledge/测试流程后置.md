# 测试流程后置

## Summary

cgraphx 的单元测试与接口测试是**代码完成后的独立流程**,不进 plan、不在实现期写:单元测试走 `write-unit-test-spec → write-unit-test-code`,接口测试走 `write-api → run-api-test`,各自从 spec 派生。plan 不排测试任务(无 `-04-test.md`、无"默认合并测试");implementation/subagent-implement 实现期**不作者新测试**,唯一测试职责是完成定义——**既有测试不被弄红**(改动弄红的既有测试须同步修正)。本条记录"测试职责单一来源"这一决策的取舍:把"该测什么/怎么测/产规格代码报告"集中到独立流程,消除 plan 提前拍死测试决策、与独立测试 skill 职责重叠的问题。

## 决策与背景

- 原 write-plan 把测试排成实现任务:有"测试"phase、"默认合并:测试并入实现任务(同 implementer 写码 + 测试)"、默认产出 `-04-test.md`(必测路径/测试命令)、强制引用映射含 testing-standards。这等于在 plan 阶段就提前拍死"测什么、何时测",与两个独立测试 skill(write-unit-test-spec 零代码依赖、write-api+run-api-test 要求实现完成)**职责重叠**。
- 决策(2026-08-01,用户拍板"彻底分离"):测试职责单一来源——新增测试覆盖**只**由代码完成后的独立流程负责;plan/implementation 对测试只剩"既有测试不红"这一完成定义。

## 备选方案(为何不选)

- **保留实现期自测**(implementer 可为自己的代码附带单测,但不排独立测试流程):更贴合"写码顺手测",但 plan 里仍留测试痕迹、测试职责仍两处(实现期 + 独立流程),边界模糊——与"单一来源"相悖,否决。
- **仅对齐措辞**(不大动结构,只解释 plan 排的是实现期自测、不是独立流程):`-04-test.md` 等结构仍在,"提前感"只是被解释掉、没被消除,否决。

## 关键边界(修旧 ✅ / 写新 ❌)

- ✅ implementer **可修正被自己改动弄红的既有测试**(改名/改签名/挪模块/改了它断言的行为)——这是"保绿"所必需,否则"既有测试不红"这条 DoD 没人兜(独立测试流程代码后才跑,管不到实现中途被搞挂的老测试;小步提交也要求每个独立提交任务完成后仓库可工作)。
- ❌ implementer **不为新写逻辑补全新测试**——那是独立流程的事。
- testing-standards.md 仍存在(init-project-guides 生成),但**不由 plan 读/结晶**,改由测试流程(write-unit-test-code / run-api-test)自读。

## 代码入口

- `assets/claude-template/skills/write-plan/SKILL.md` — 「测试不进 plan」规则(拆分规则节);适用规范表无测试行。
- `assets/claude-template/skills/implementation/SKILL.md` — 质量底线:新增逻辑测试覆盖归独立流程,实现期不写新测试,改动弄红的既有测试已同步修正。
- `assets/claude-template/FLOW-MAP.md` — 单元/接口测试均为"代码完成后"独立流程;testing-standards 归测试流程自读。
