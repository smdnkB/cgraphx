# 并旧数据

## Summary

并旧数据是升级到「数据按项目放用户目录」之后,由新版 `cgraphx install` 完成的一步,又称旧库合并:把一个目录原来记在本地 `.cgraphx/cgraphx.db` 里的 timeline、task、sync 数据(旧库),并进用户目录里这个项目的库。
- 并之前,先把旧库连同 -wal、-shm 文件备份进项目目录的 `backups/`。
- 并完,在本地 `.cgraphx/project.json` 写上并过记号(`mergedAt`),再删掉本地库里的旧表,只留知识库索引。
- 每个目录只并一次,再装时提示「已经并过」。几个目录各有旧库的,各并各的;同一个会话的同一条事件只留一份;上报进度和任务绑定接着用。
- 还没并过的目录走旧库模式:新版照旧读写本地库,数据既不丢,也不分家。
- uninstall 删本地 `.cgraphx/` 之前,也会先并一次。

## 触发与前置

- 触发:
  - 在一个目录里跑新版 `cgraphx install`,在问项目名称之后、生成 db-query 模板之前。
  - `cgraphx uninstall` 删本地 `.cgraphx/` 之前(没给 `--keep-data` 时)。
- 前置:
  - 这个目录是旧库模式:本地 `.cgraphx/cgraphx.db` 里还有 `timeline_*`、`task_*` 或 `sync_*` 表,`.cgraphx/project.json` 里没有 `mergedAt`。
  - 认得出项目标识(见「项目」),认不出就是 `failed`。

## 参与者与系统

- 编排:`src/core/project/merge.ts`;锁、备份和文件类数据:`src/core/project/merge-files.ts`。
- 各子系统并自己的表:timeline `createTimelineMerger`、task `mergeTaskTables`、sync `mergeSyncTables`,都只经各自的门面调用。
- 安装器:`src/cli/installer/project-steps.ts` 负责调用并输出结果提示。

## 主链路与状态流转

旧库模式 → 取 `merge.lock` → 备份 → 两段并 → 写并过记号 → 删旧表 → 项目库模式。

- 结果有四种:
  - `merged`:提示「已把 N 条事件、M 个会话并进项目 <项目>」。
  - `already`:提示「已经并过」。
  - `nothing`:没有旧数据,不输出。
  - `failed`:旧库原样留着,下次 install 再并。
- 两段并:先并到某个事件 id,再拿写锁并剩下的尾巴(并的同时 hook 可能还在往旧库里写)。去重规则:
  - 普通事件按 ts 加其余各列去重;
  - git_commit 按 hash 去重。
- 旧事件 id 和新 id 的对照表,用来换算 sync 的上报进度和 task 的派生进度。
- 文件类数据随后并:轮次文件 `turns/`、db-query 的 `db-profiles.json` 和日志、task 接口配置。两边配置不一样时,留项目里已有的那份,并给出提示。

## 异常分支

- 并失败(拿不到锁、库坏了、认不出项目)→ `failed`,打出原因。本地旧库不动,这个目录照旧走旧库模式,下次 install 再并。
- uninstall 时并失败 → 不删本地 `.cgraphx/`,因为删了旧数据就丢了。
- 并到一半进程被杀 → 再装一次接着并,靠去重不会重复。持有 `merge.lock` 的进程已经不在、或锁超过 2 小时,就算过期。
- 恰好在并完那一刻,有 hook 往旧库里写 → hook 在写事务里重读并过记号,发现已经并过,就改写进项目库。

## 关键约束与陷阱

- **问名字、并旧数据必须排在生成 db-query 模板之前**:`db init` 走 `ensureDataDir`,会给装过、没有旧表的目录写上并过记号。顺序反了,第一次装就会被判成「已经并过」。
- **「恰好并完」以开库前拿到的数据位置为准**:记号一写上,`locateDataAtRoot` 马上就会回答项目库模式。在写事务里再去问数据位置,正好漏掉应该改写项目库的那一刻;写事务里只重读 `project.json` 的 `mergedAt`。
- **备份要带上 -wal、-shm**(见「cgraphx 库副本须带 WAL 文件」),否则备份里缺最近的写入。
- **sync 的会话进度只在同一个平台时才并**:服务地址和上报地址都相同,才并 `sync_sessions`;只换了 token 不算换平台。平台不同时,进度不并,接入配置留项目里已有的那份,并给出提示。
- **旧库模式的子目录项目,提交照旧不记**:install 时名字记下了、但并旧数据失败的子目录项目,在并过去之前的提交不记(spec D9);工作区根的项目照旧记进本地旧库。
- **旧库模式下不能改名**:`project name` 返回退出码 2,先 install 并过去,install 时也能直接改名。
- **旧版 cgraphx 仍能打开并过的本地库**:timeline 的 schema 版本没动,只新增了 `timeline_roots` 表。
