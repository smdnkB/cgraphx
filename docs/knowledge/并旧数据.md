# 并旧数据

## Summary

并旧数据是升级到「数据按项目放用户目录」之后,由新版 `cgraphx install` 完成的一步,又称旧库合并:把一个目录原来记在本地 `.cgraphx/cgraphx.db` 里的数据并进用户目录里这个项目的库。task、sync 的并表已随开发任务、平台上报下掉(见 `docs/features/2026-11-05-下掉web与平台同步/`),旧库里的 `task_*`、`sync_*` 表只在判定旧库模式时算数,并时随删旧表一起删。

- **只并提交记录(git_commit)与 `timeline_roots`**(2026-11-06 起收窄):hook 记的事件升级后会按会话文件**全量重建**,并进来就是白并——项目重建过之后,另一个目录再 install 也不会把旧事件带回来。id 对照与进度换算已随收窄删除,没有消费方。
- **重建(F6)只一次**:install 并完旧数据、或这个项目第一次查时间线时,清掉 hook 记的旧事件、按会话文件解析重建(记号 `timeline_meta.rebuilt_at`,跟着项目数据走,worktree / 副本再触发也不重来);删过的项目(`removed_projects` 有记录)只写记号不全量解析,之后的增量只收删除之后的事实。提交记录是 git 钩子记的,保留。
- 并之前,先把旧库连同 -wal、-shm 文件备份进项目目录的 `backups/`。
- 并完,在本地 `.cgraphx/project.json` 写上并过记号(`mergedAt`),再删掉本地库里的旧表,只留知识库索引。
- 每个目录只并一次,再装时提示「已经并过」。几个目录各有旧库的,各并各的;同一个仓库记下的同一条提交记录只留一份。
- 还没并过的目录走旧库模式:照旧读写本地库,数据既不丢,也不分家。
- uninstall 删本地 `.cgraphx/` 之前,也会先并一次。

## 触发与前置

- 触发:
  - 在一个目录里跑新版 `cgraphx install`,在问项目名称、判断重名之后、生成 db-query 模板之前;并完旧数据之后 install 还会顺势跑一次补录(第一次就是全量重建)。
  - `cgraphx uninstall` 删本地 `.cgraphx/` 之前(没给 `--keep-data` 时)。
- 前置:
  - 这个目录是旧库模式:本地 `.cgraphx/cgraphx.db` 里还有 `timeline_*`、`task_*` 或 `sync_*` 表,`.cgraphx/project.json` 里没有 `mergedAt`。
  - 认得出项目名称(见「项目」),认不出就是 `failed`。

## 参与者与系统

- 编排:`src/core/project/merge.ts`;锁、备份和文件类数据:`src/core/project/merge-files.ts`。
- 并表的只有 timeline(`createTimelineMerger`,经门面调用;只并提交记录与 `timeline_roots`)。
- 全量重建:`src/core/timeline/ingest/rebuild.ts`(临时库 + ATTACH 短事务,详见「开发时间线工具事件契约」与需求 spec D19)。
- 安装器:`src/cli/installer/project-steps.ts` 负责调用并输出结果提示,`src/cli/installer/index.ts` 并完调补录。

## 主链路与状态流转

旧库模式 → 取 `merge.lock` → 备份 → 两段并(提交记录与根)→ 写并过记号 → 删旧表 → 项目库模式 → (install 里顺势)全量重建。

- 结果有四种:
  - `merged`:提示已并的提交记录条数(「并了多少提交」)。
  - `already`:提示「已经并过」。
  - `nothing`:没有旧数据,不输出。
  - `failed`:旧库原样留着,下次 install 再并。
- 两段并:先并到某个事件 id,再拿写锁并剩下的尾巴(并的同时可能还有旧版进程往旧库里写)。去重规则:git_commit 按 commit_hash 去重(没有 hash 的提交记录按除 id 外各列比,NULL 用 IS 比)。
- 文件类数据随后并:db-query 的 `db-profiles.json` 和日志。两边配置不一样时,留项目里已有的那份,并给出提示。轮次文件 `turns/` 不再并(hook 已退役,重建时连数据目录下的 `turns/` 和 `~/.cgraphx/sessions/` 一起删)。

## 异常分支

- 并失败(拿不到锁、库坏了、认不出项目)→ `failed`,打出原因。本地旧库不动,这个目录照旧走旧库模式,下次 install 再并。
- uninstall 时并失败 → 不删本地 `.cgraphx/`,因为删了旧数据就丢了。
- 并到一半进程被杀 → 再装一次接着并,靠 hash 去重不会重复。持有 `merge.lock` 的进程已经不在、或锁超过 2 小时,就算过期。
- 重建中途杀进程 → 短事务失败即回滚,时间线还是旧的;`rebuilt_at` 必须写进事务里,中断不会误判「重建过」。

## 关键约束与陷阱

- **问名字、并旧数据必须排在生成 db-query 模板之前**:`db init` 走 `ensureDataDir`,会给装过、没有旧表的目录写上并过记号。顺序反了,第一次装就会被判成「已经并过」。install 记下名字后会做一次重名判断(判过写 sessions.db 的 `dirs_checked`),所以 install 结束之后的命令不会再提示一次。
- **重建只发生在「还没并过旧数据」之后**:补录入口先判 `hasUnmergedLegacyData`(经 project 门面取),没并过的目录提示先 install,不重建——不然刚升上来的目录会丢还没并的旧数据。
- **改名后新项目第一次全量重建不全量重读**(2026-11-06-项目按名称认 D5):`session_files` 里已经记到别的项目、且 `byte_offset > 0` 的会话文件直接跳过,保持偏移交给之后的增量——否则改名前的历史会同时出现在新旧两个项目;从没记过的文件、`project_dir` 为空的、偏移为 0 的照旧从头读,全新项目的历史补录不受影响。
- **「并旧数据只并提交」和「重建只一次」是配套的**:如果哪天把普通事件也并回来,重建清掉的就是并进来的数据,白并;动一处必须想另一处。
- **备份要带上 -wal、-shm**(见「cgraphx 库副本须带 WAL 文件」),否则备份里缺最近的写入。
- **旧库模式的子目录项目,提交照旧不记**:install 时名字记下了、但并旧数据失败的子目录项目,在并过去之前的提交不记(spec D9);工作区根的项目照旧记进本地旧库。
- **旧库模式下不能改名**:`project name` 返回退出码 2,先 install 并过去,install 时也能直接改名。
- **旧版 cgraphx 仍能打开并过的本地库**:timeline 的 schema 版本没动,只新增了 `timeline_roots` 表和 `source_key` 列(部分唯一索引)。
