# 知识库分类体系

## Summary

cgraphx 知识库(docs/knowledge/)frontmatter 的分类契约,2026-07-31 换血定稿(又称文档分类枚举/分类体系换血)。三个维度各回答一个问题:document_type = 「文档在讲什么」(主题语义,7 值:business-entity 业务实体 / business-flow 业务流程 / mechanism 技术机制含架构 / decision 决策 / rule 规则 / lesson 教训 / guide 指南含运维手册·教程·安装·FAQ·API);source_type = 「从哪个场景沉淀的」(沉淀场景语义,5 值:work_context 工作上下文 / batch_exploration 批量探索 / review 评审 / debugging 调查排障 / manual 手工);domains = 「属于哪个业务领域」(业务域语义,如合约/商品/礼包,自由词表不校验;服务模块信息放 tags 不放 domains)。枚举的单一事实源是 src/core/markdown/constants.ts,validator 强制校验,非法值索引时跳过。换血前的旧枚举(17 种 document_type,exploration 沦为默认桶)已整体废除,无双轨期,存量经 knowledge-migrate skill 按内容主题判定迁移(不按旧值机械映射)。

## 三个维度的语义取向

换血的核心决策:三个维度正交,各管一事——

- **document_type 是主题语义,不是生产语义**:旧枚举回答"知识怎么来的"(conversation/exploration/finding/analysis…),导致 57% 文档挤进 exploration 默认桶,真实主题溢出到 tags 并碎裂(business-flow/flow/biz-flow 三个标签表达同一语义)。新枚举回答"文档在讲什么",写知识时选型即选模板(knowledge-write 模板映射:business-entity→template-concept、business-flow→template-flow、mechanism/decision/rule/lesson→template-memory、guide→template-guide)。
- **source_type 是沉淀场景,不是知识形式**:5 个值对应 cgraphx 实际的沉淀入口(需求流收尾 / knowledge-init 批量探索 / 评审 / 排障 / 手工)。knowledge-init 建库默认来源是 batch_exploration(不走 ai_session→work_context 映射)。
- **domains 是业务域,不是服务模块**:validator 不校验 domains 枚举(通用工具不内置项目业务域名单),靠 knowledge-write skill 引导与召回反馈收敛。

## 关键约束

- **无兜底类型**(note 已废除):主题不明的文档不入库——宁可不写,不写进默认桶。
- **值合法 ≠ 归属准确**:同名保留值(decision/rule/lesson/guide/debugging/manual)换血后语义口径变了,存量复核与新写入判定都要按内容主题,不按值机械归类。
- **无双轨期**:废除值在 validator 即非法,重索引直接跳过;存量迁移必须与新版本配套(迁移工具:knowledge-migrate skill,dry-run 报告 → 用户确认 → 执行,剔除文档移出 docs/knowledge/)。
- **同步修订面**(改枚举必须同发布):constants.ts ↔ validator ↔ web TYPE_LABELS/TYPE_TONES ↔ knowledge-write/knowledge-init skill 文本 ↔ 接入项目存量。任一面滞后即不一致。

## 旧值映射(迁移参考,权威表在 knowledge-migrate skill)

concept→business-entity;exploration/finding/analysis 按内容主题分流;architecture→mechanism;warning 约束类→rule、复盘类→lesson;tutorial/runbook/installation/api/faq→guide;conversation/note 按主题,无主题则剔除。source_type:ai_session→work_context;architecture_review/code_review→review;human_note/external_summary→manual。
