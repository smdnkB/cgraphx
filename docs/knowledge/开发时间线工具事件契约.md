# 开发时间线工具事件契约

## Summary

timeline 的事件来源从 2026-11-06 起是**会话文件解析**:7 条 agent hook(含 precommit-check)已删,查时间线的四个命令、git 提交后的后台进程、install 并旧数据之后,都先经补录入口 `ensureTimelineUpToDate` 把各家 agent 自己留下的会话文件里新增的部分解析进项目库,再查询。

工具事件只剩一种:`post_tool_use`。`pre_tool_use` 与 `session_end` 不再有新数据(`--type` 选项与显示照旧认这两种,重建后的旧数据没了只是查不到)。一次调用一条:发出与结果按编号配对,`ts` 取结果行、`cwd` 取调用行(执行前的目录)、`duration_ms` 取两行时间差(`metadata.duration_source:'transcript'`,含等人——不是宿主自报的耗时);一直没有结果的死调用不记。轮次编号 `turn_id` 取本轮提问消息的 uuid(重新解析不变)。

工具事件有三个 JSON 列:调用参数 `tool_args`、工具结果摘要 `tool_result_summary`(简称摘要)、`metadata`。这三列在任何时候都必须是合法 JSON,超长时只截字段的值。

摘要按「摘要契约 v2」写入,形状为 `{"v":2,"success":…,"payload":{…}}`。Claude Code 和 CodeBuddy 共用这一份契约:取不到的字段就不写,不推测。

失败调用也记为 post_tool_use,摘要里 `success:false`。失败的来源只剩行内标记:

- Claude Code:结果行 tool_result 块 `is_error:true`(hook 时代的 PostToolUseFailure 事件已随 hook 体系删除);
- CodeBuddy:function_call_result 行 `status` 为 `incomplete`(实测权限拒绝、文件不存在、命令报错全是 incomplete;`completed` 即成功)。

没有 `v` 的旧摘要按 v1 理解。读取方解析失败时,按"摘要未知"处理。

## Context

2026-10-16 复核本地库时发现三类问题(约 15% 的 Bash 摘要因整串截断而无法解析、失败调用一条都没有、Read / Edit / Write / Agent 的摘要 payload 全为空),据此把摘要改为 v2 并在此成文。

2026-11-06 的「会话文件解析替代 hooks」需求把采集从 7 条 agent hook 改为解析会话文件。事件的列结构、摘要契约、参数净化与上限全部沿用;来源、时间口径、事件种类与失败标记按本文更新。完整机制见需求 spec。

## Findings

### 事件来源与去重

- 补录入口 `ensureTimelineUpToDate`(`timeline/ingest/ingest.ts`),三个调用方:timeline 四个查询命令(查询之前)、post-commit 后台进程(记完提交之后)、install 并旧数据之后。进度(每文件字节偏移)与文件索引存用户级 `~/.cgraphx/sessions.db`,不在项目库里。
- 解析事件按 `timeline_events.source_key` 部分唯一索引去重:提问 `<agent>:prompt:<uuid>`、工具 `<agent>:tool:<tool_use_id>`、轮次结束 `<agent>:stop:<回复 message.id>`、会话开始 `<agent>:start:<会话编号>`;写入 `INSERT OR IGNORE`。文件变短从头重读、跨趟重读都靠它不重复。git_commit 不带键,去重照旧走 commit_hash。schema 版本号不升。
- 开关 `CGRAPHX_NO_TIMELINE` 管采集(补录与重建都停),不管门禁。
- 升级后第一次 install 或第一次查时间线:清掉 hook 记的旧事件、按解析全量重建(每项目一次,记号 `timeline_meta.rebuilt_at`;提交记录保留)。

### 两家会话文件的格式差异(2026-11-06 实测)

Claude Code(`~/.claude/projects/`,行内 version 2.1.204;读本机 3,239 个 .jsonl 核对):

- 布局 `<项目目录>/<会话>.jsonl` 主文件,子 agent 在 `<会话>/subagents/agent-<id>.jsonl`(另有 workflows/ 嵌套布局与 .meta.json / .prefix.json,不列)。子 agent 文件行内 sessionId 是**主会话**编号、isSidechain=true,subagent.id 取行内 agentId。
- 行类型 20 多种且在增加;不认识的行类型单独跳过、不算错误(K11)。
- 时间戳是 ISO 8601 字符串。轮次结束取 `stop_reason === 'end_turn'` 的非侧链 assistant 行(ts 与 message.id)。
- 子 agent 交回的 user 行实测 316/316 都带 `Another Claude session sent a message:` 前缀且 `isMeta=true`——先剥这个前缀再过自动消息分类,不剥的话 agent_message 一条都对不上。
- queued_command 附件(type=attachment,`attachment.prompt` 存排队原文)是排队未送达的提问:排队先写附件、送达才写 user 行;附件文本(剥前缀后)没有对上本趟 user 行文本的才算一条提问。

CodeBuddy(`~/.codebuddy/projects/`,2.167.0;读本机 18 个 .jsonl 核对):

- 与 Claude Code 完全不同:行类型只有六种(message / reasoning / function_call / function_call_result / file-history-snapshot / session-meta),几乎每行都带 cwd。
- 时间戳是 epoch 毫秒数(不是 ISO)。
- **usage 行 = 轮次结束**:一轮只有最后一条带行级 message(usage 对象)的 assistant 回复,实测都恰在轮次末尾(中断的轮没有),作行内轮次结束标记。
- 子 agent 文件在 `<会话>/subagents/agent-<id>.jsonl`,行内 sessionId 是**独立子会话编号**(不是主会话编号)——按 K7「子 agent 里的调用算进发起它的会话」,按文件布局归到主会话(父目录名即主会话编号)。
- 工具配对:function_call 行与 function_call_result 行按 callId 配对;参数是 JSON 字符串(解析失败原样透传),结果载荷取 output。
- 斜杠命令:驱动 agent 的斜杠命令是人直接敲的原文(原样透传);本地 UI 命令是 `<command-name>…` 且 `providerData.skipRun=true`,**skipRun=true 一律不算提问**(没有真正跑模型)。

### 摘要 v2 的形状

| 字段 | 含义 |
|---|---|
| `v` | 契约版本,固定为 2(常量 `SUMMARY_VERSION`) |
| `success` | 行内是否报失败:is_error / status=incomplete / 被中断 / 退出码非 0,都记为 `false` |
| `payload` | 按工具区分的内容。取不到的字段不写,不写成 null |

### payload 字段与可得性

能从调用参数取的信息,一律取自调用参数,所以两个 agent 一致(摘要契约沿用 hook 时代的这条)。结果载荷的来源:claude 取结果行的行级 `toolUseResult`(与 hook 时代的 tool_response 同形状);codebuddy 取结果行的 `output`(各工具多为一段纯文本)。下表的可得性是 hook 时代的实测口径,解析侧的载荷来源已变,未逐项复测:

| 工具 | 字段 | Claude Code | CodeBuddy |
|---|---|---|---|
| Read / Edit / Write / MultiEdit | `file`(取自 `tool_input.file_path`) | ✓ | ✓ |
| NotebookEdit | `file`(`notebook_path`,没有则 `file_path`) | ✓ | 未实测 |
| Bash | `exit_code` | 失败时从错误文本 "Exit code N" 解析;**成功时没有** | ✓(hook 时代来自响应的 `exitCode`) |
| Bash | `stdout_preview` / `stderr_preview` | ✓ | ✗(宿主不给输出) |
| Bash | `category`(test / build / lint / git_write,按命令文本识别) | ✓ | ✓ |
| Bash | test 类的 `pass` / `fail`(从输出解析的测试数) | ✓ | ✗ |
| Bash | build / git_write 类的 `pass` / `fail`(由退出码推出) | 仅失败时有 | ✓ |
| Bash | `duration_ms`(测试运行器自报的耗时,不是事件耗时) | ✓ | ✗ |
| 任意工具 | `interrupted` | 只在为 true 时写;缺省表示未中断或未知 | 同左 |
| 任意工具(失败时) | `error` | ✓ | Bash 有;Read 失败只给错误码,不写 |
| 任意工具(失败时) | `exit_code` | 能从错误文本解析时写 | 响应带退出码时写 |
| Agent / Task | `subagent_type`(取自调用参数) | ✓ | ✓ |
| Skill | `skill`(取自调用参数) | ✓ | ✓ |
| WebFetch / WebSearch | `url`(取自调用参数;WebSearch 通常没有) | ✓ | ✓ |
| TaskCreate / TaskUpdate / TaskGet | `taskId` / `subject` / `status` | ✓ | 未实测 |
| 其它工具 | `response_preview` | ✓ | ✓ |

### metadata 的工具事件键

| 键 | 写入时机 |
|---|---|
| `tool_use_id` | post 写,行内给了就写(两个 agent 都给) |
| `subagent: {id, type}` | 事件发生在子 agent 文件里时写(claude 只有 id,codebuddy 有 id 与 type);只写入,读取方不展示;事件的 `session_id` 仍是主会话 |
| `duration_source` | 事件有 `duration_ms` 时写:`transcript` 表示解析侧两行时间差(现行);旧数据里 `host` 是宿主测量的值(Claude Code hook 时代)、`estimated` 是用 post 写库时刻减最近一条 pre 估算(CodeBuddy hook 时代,仅写类工具和 Bash) |

### 调用参数的净化

- Write 不存文件正文,改为记 `content_bytes` 和 `content_lines`。
- Edit 和 MultiEdit 的 `old_string` / `new_string` 保留,但单个片段截到 4KB。

净化(`sanitizeToolArgs`)与摘要(`summarizeToolResponse`)由补录管线在入库前统一调用,读取器只产原始事实。

### 上限常量(`src/core/timeline/constants.ts`)

| 常量 | 值 | 作用 |
|---|---|---|
| `RESULT_SUMMARY_MAX_BYTES` | 8KB | 摘要整体上限 |
| `SUMMARY_FIELD_MAX_BYTES` | 2KB | stdout / stderr / error / response 预览,每个字段的上限 |
| `ARGS_MAX_BYTES` / `ARGS_FIELD_MAX_BYTES` | 64KB / 16KB | 调用参数的整体上限 / 整体超限时单个字段的上限 |
| `METADATA_MAX_BYTES` / `METADATA_FIELD_MAX_BYTES` | 8KB / 2KB | metadata 同上 |
| `EDIT_SNIPPET_MAX_BYTES` | 4KB | Edit 片段上限 |

截断在 UTF-8 字符边界进行,并接上 `... [truncated]`。整体仍超限时,单字段上限减半后重试;实在放不下,就写入占位对象 `{"_truncated":true,"_original_bytes":N}`。不能解析的摘要入库时替换为 `{"_invalid":true}`。

### v1 与 v2 的区别

- v1 没有 `v` 字段。
- v1 中 Read / Edit / Write / Agent 的 payload 基本为空,字段缺失表示"当时没采到",不代表"真实为空"。
- 修复前的 v1 Bash 摘要可能是被截断的非法 JSON。
- v1 没有任何失败记录。
- v1 的 `lines_changed` 从来没采到过,v2 已删除。
- 存量数据不改写。hook 时代记的 v1 事件在升级重建后会被清掉(F6);并旧数据只并提交记录。

### 读取方规则

- 任何读取方解析摘要或 metadata 失败时,都按"该信息未知"处理,不报错、不中断展示或统计(store `rowToEvent`:摘要原样返回字符串;`tool_args` / `metadata` 解析失败时分别得到 null / `{}`)。
- 没有 `v` 的摘要按 v1 理解。

## Impact For Future Changes

- 新增摘要字段时,先写进本文的可得性表,再改生成器。字段只从生成器一处产出。
- 不要在摘要里依赖响应里的字段名:两个 agent 的响应形状不同,能取自 `tool_input` 的都取自 `tool_input`。
- 采集侧不再有 hook:新增事件来源改补录管线(`timeline/ingest/`);agent 升级改了会话文件格式,读取器按「不认识的行跳过、不算错误」处理,K11 提示让用户升级 cgraphx。
- 不升 timeline 的 schema 版本:新信息放进已有的 JSON 列。原因见「平台上报」中的旧版全局 cgraphx 约束。

## Reuse Guidance

在这些场景下先读本文:

- 读取或解析 `tool_result_summary`、`metadata`;
- 排查"摘要为空、无法解析、失败没记录"之类的问题;
- 排查"时间线缺事件 / 会话文件解析不出";
- 接入新 agent 的会话文件读取器,或改动事件的种类与时间口径。

## Open Questions

- Claude Code 被权限拒绝的调用在会话文件里的行内形状没有单独核对(是否 tool_result `is_error`);hook 时代这类调用只有一条 pre、没有 post,解析侧没有 pre。
- CodeBuddy 下 Task* 工具和 NotebookEdit 的响应形状,还没有实测。
- Claude Code 行类型在增加,新增类型按「不认识就跳过」处理,不追新。
