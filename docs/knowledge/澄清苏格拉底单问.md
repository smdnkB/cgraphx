# 澄清苏格拉底单问

## Summary

clarify-requirements 的默认交互节奏是**苏格拉底单问**:沿决策树一个分支一个分支走,**一次只问一个决策**,**每问先给 agent 的推荐答案**,用户确认或纠正后再进下一问;**事实自己查、只问决策**(读无界,决策有界)。这套机制是从开源社区的 grilling skill(极简拷问式澄清)适配性**吸收**进来的,不是新增平级 skill。本条记录吸收的取舍:grilling 的 4 条机制里,2 条 clarify 本就有(事实自查 = 读无界决策有界、共识前不动手 = HARD-GATE),只补真正缺的 2 条(一次一问的节奏 + 每问推荐答案),其余合并进既有单一事实源,不重复添加。

## 决策与背景

- grilling skill 流行于一派观点:"模型越来越聪明,不必用太多规范限制"。其精髓 4 条:① 沿决策树拷问至共识、每问给推荐答案;② 一次一问(连珠炮让人懵);③ 事实自查、只问决策;④ 共识前不动手。
- 对照 clarify:③ = 「读无界,决策有界」(已有);④ = HARD-GATE「确认业务边界前不采取行动」(已有)。真正缺的是 ① 的节奏(一次一问)与"每问推荐答案"。且 clarify 已有的「苏格拉底式」是个现成 leading word——把它从"假设 risky 时才用的子策略"**升格为默认节奏**,注入 grilling 的操作细节,即"适配"而非"bolt-on"。

## 备选方案(为何不选)

- **新增平级 grilling skill**(与 clarify 并列,用户二选一):多一个 skill 多一份 context load,且两 skill 共享底层原则(事实/决策二分、推荐 ≠ 确认、未确认不动手),会重复;clarify 的"确认式默认 3-5 问"与 grilling"一次一问"还会并存矛盾——否决,改为吸收。
- **clarify 维持原样**(确认式默认、苏格拉底式按需):丢了 grilling 真正更优的交互机制(一次一问 + 每问推荐答案;批量问用户会挑好答的答、漏其余),否决。

## 关键设计(按 writing-great-skills 规范)

- 用现成 leading word「苏格拉底」,不硬造新词;节奏全正面陈述(删去"不做清单审讯"这类 negation-elephant 与原"每轮 3-5 问"——后者与一次一问冲突)。
- 保留 clarify **可检的终止条件**,**不**采用 grilling 模糊的"达成共识"——模糊停止条件会诱发 premature completion(writing-great-skills 点名的失败模式)。
- 事实/决策二分指向定位「读无界,决策有界」单一事实源,不在策略节复述。
