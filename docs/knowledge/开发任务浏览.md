# 开发任务浏览

## Summary

cgraphx web 的开发任务页(侧栏「开发任务」,`/tasks` 与 `/tasks/<本地 id>`),在浏览器里按任务看投入与交付:会话、时长、commit、**任务产出**(交付了哪些文件)、**任务参考**(读过哪些知识库、代码地图等)。完全只读:数据只经 task 门面的只读函数取,打开页面时按「会话 + 绑定区间」现算,不存任何关联;不改已有页面,不做时间线按任务筛选。

## 触发与前置

- 用户在浏览器打开 `/tasks`;项目已 `cgraphx install` 且有 task 表。
- 没有 task 表的老项目:页面提示运行 `cgraphx install`,不建表,其它页面照常。

## 参与者与系统

- web:`src/web/pages-tasks.ts`(格式化 + 链接解析)、`src/web/task-templates.ts`;事件行复用时间线页的渲染。
- task 子系统:`src/core/task/report.ts`(汇总、详情、时长)、`src/core/task/artifacts.ts`(产出与参考)。
- 只经门面读 timeline(归属事件)、features(spec 头部任务声明)、markdown(知识库链接与概念)。

## 主链路与状态流转

列表:全部本地任务 + 汇总数字,按最近活动倒序,从未绑定的排最后。详情:任务信息 → 关联需求目录 → 合计 → 产出 → 参考 → 会话块(一条绑定一块,事件默认折叠,每块最多显示 500 条)→ 事件类型统计。口径见「开发任务投入时长口径」。

## 关键约束与陷阱

- **web 只能调只读函数**:`listTaskSummaries` / `getTaskReport` 经 `openTaskDbReadOnly` 打开库。既有的 `openTaskDb`(以及经它的 `listTasks` / `getTaskDetail`)会执行 `ensureTaskSchema`,web 调它们会给老项目建表,违反 web 只读契约。
- **不能用 `listTasks` 的「当前任务」**:它从进程环境变量读会话 id,web 若是在 Claude Code 会话里启动的,会把那个会话的任务错标成「当前」。
- **产出来源**:归属 commit 的文件 + 写类工具(Edit/Write/MultiEdit/NotebookEdit)改过的文件 + 关联需求目录下的文件,只列项目根内、现存的文件。Bash 生成且未提交的文件漏掉(提交后自动出现)。
- **参考只能推断**:实测 agent 读文件几乎全走 Bash(`cat` / `sed` / `grep`),Read 工具事件极少,所以参考栏要从 Bash 命令文本里匹配路径和 `--concept`,页面标「按命令记录推断」。命令里出现路径不等于读过(如 `git add`),含 `$` 的片段跳过。
- 一个文件既被参考又是产出,只出现在产出栏。
- 归属是现算的:补绑、改绑后产出与参考自动跟着走,不需要回填。
