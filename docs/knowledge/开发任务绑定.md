# 开发任务绑定

## Summary

开发任务绑定把一个 Claude Code 会话在某个时间区间内归到一个开发任务上,又称任务绑定 / 会话绑定。这个会话在区间内产生的 timeline 事件(包括 agent 发起的 git commit),就归属这个任务,这就是事件归属。绑定有两个来源:agent 执行 `cgraphx task use` 显式绑定;或者会话改动了 spec 头部声明 `> 任务:` 的需求目录,在会话尚未绑定时自动绑定。多个会话并行做不同任务时互不串号。绑定数据记在本地;接入研发管理平台后,绑定段按白名单上报到平台(接口任务报平台编号 `T-<n>`,手动任务在平台上算未归属),详见「平台上报」。平台上的补绑不回写本地。

## 触发与前置

- 前置:项目已 `cgraphx install`(task 表和两个 task hook 已接入),绑定所需的会话 id 能拿到(见「会话 id 来源约束」)。
- 会话开始时 task hook 只告诉 agent 已绑定的任务和当前会话 id,**不提示绑定**(不打扰原则,2026-10-14 决定)。归属完整性靠两点:需求目录自动绑定;首次绑定回溯到会话第一条事件,所以事后补绑不丢数据。
- 事后补绑:先用 `cgraphx timeline query --since <时间> --type user_prompt` 找到会话 id,再执行 `cgraphx task use <任务> --session <会话id>`。
- 显式绑定:agent 或用户执行 `cgraphx task use <编号或名称>`。
- 自动绑定:会话用 Edit / Write / MultiEdit / NotebookEdit 成功改动了某个需求目录里的文件,而该目录的主 spec 头部声明了任务。

## 参与者与系统

- Claude Code(hook 宿主、agent)
- task 子系统:`src/core/task/`
- timeline 子系统(提供事件和会话首事件时间,只经门面读)
- features 子系统(提供 spec 头部的任务声明,只经门面读)

## 主链路与状态流转

绑定的状态只有两种:**生效中**(`unbound_at` 为空)和**已结束**。一个会话同一时刻最多一条生效绑定,由存储层的部分唯一索引强制保证。

| 动作 | 会话当前状态 | 结果 |
|---|---|---|
| `task use` 同一任务 | 已绑定该任务 | 无变化 |
| `task use` 另一任务 | 已绑定其它任务 | 切换:旧绑定结束,新绑定开始,两者用同一时刻衔接 |
| `task use` / 自动绑定 | 未绑定 | 新建绑定 |
| 自动绑定 | 已绑定其它任务 | 不切换,向 agent 提醒一次 |
| `task clear` | 已绑定 | 结束绑定 |

## 异常分支

- 拿不到会话 id(不在会话内,也没给 `--session`):`task use` 报参数错误,退出码 3。
- hook 内的任何失败(未初始化、DB 异常、spec 读不到)都只写 stderr,不阻塞 Claude Code,也不影响 timeline 事件写入。
- 环境变量 `CGRAPHX_NO_TIMELINE` 打开时,timeline 记录、自动绑定、会话开始注入一起关闭;显式的 `cgraphx task` 命令不受影响。

## 关键约束与陷阱

- **归属口径**:事件属于任务 T,当且仅当它的 session_id 和时间落在 T 的某条绑定区间内。区间左闭右开(`bound_at ≤ ts < unbound_at`)。timeline 查询的 until 是闭区间,所以 task 侧要再剔除 `ts = unbound_at` 的事件。
- **首次绑定回溯**:会话第一次绑定任务时,区间起点取该会话最早一条 timeline 事件的时间,所以先聊后绑,前面的工作也算这个任务。之后的切换都从切换时刻开始。
- **自动绑定绝不覆盖已有绑定**:「检查未绑定」和「写入绑定」必须在同一个事务里完成('ifUnbound' 模式)。否则并发时可能切走别的进程刚绑上的任务。
- **提醒去重**:同一会话里同一对(已绑定任务 A,改动所属任务 B)只提醒一次,记在 `task_reminders`。
- **终端手动 commit 永远未归属**:它不在任何会话里,session_id 为空;也不按分支名推断。
- hook 里绝不发网络请求。外部任务接口只在 `cgraphx task` 命令里调用。
- 依赖方向只有 task → timeline / features。timeline 的 hook 约定 stdout 必须为空,task 的 hook 要往 stdout 输出 `hookSpecificOutput.additionalContext`,所以两者是各自独立的 hook 进程,不能合并。

## 代码入口

- `src/core/task/binding.ts`:绑定、切换、解除,首次回溯。
- `src/core/task/feature-link.ts`:需求目录自动绑定、提醒、按任务反查归属事件(`task show`)。
- `src/core/task/hooks.ts`:会话开始注入和自动绑定的两个 hook 入口。
- `src/core/task/cli.ts`:`cgraphx task` 命令组。
- `src/core/features/scanner.ts`:读主 spec 头部的 `> 任务:`(只认第一行,空值等同未声明)。
- 代码链路图:`docs/code-map/flows/开发任务绑定.md`。
