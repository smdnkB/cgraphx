# 开发任务绑定

## Summary

开发任务绑定把一个 Claude Code 会话在某个时间区间内归到一个开发任务上,又称任务绑定 / 会话绑定 / 自动关联。2026-10-18 起,归属由程序按会话**读写了哪个产出目录**(`docs/features/<feature-id>/`)自动派生,人和 agent 都不需要选任务:读 = 暂定绑定,写 = 确定绑定;暂定只在读到日期更新的目录时整段改正,确定后不再切换;首次绑定回溯到会话起点。手动 `cgraphx task use` 仍然最高优先,手动之后本会话的自动规则停止(R6),`task clear` 同样停止。派生结果落在 `task_auto_sessions`,本地展示与上报共用同一份「有效绑定」,用 bindingKey 区分手动段与派生段;agent 上下文里只注入会话 id,不再出现任何任务内容。这个会话在区间内产生的 timeline 事件(包括 agent 发起的 git commit),就归属这个任务,这就是事件归属。绑定数据记在本地;接入研发管理平台后按白名单上报,详见「平台上报」。

## 触发与前置

- 前置:项目已 `cgraphx install`(task 表和 hook 已接入),绑定所需的会话 id 能拿到(见「会话 id 来源约束」)。
- hook 只有两条生效:`SessionStart` 只注入当前会话 id;`Stop` 在每轮结束刷新自动派生。旧配置里的 `task-post-tool-use-hook` 保留为空操作,不再写绑定。
- 其它刷新点:`task list / current / show / clear` 执行前、sync 构造上报前。本地 web 只读,不主动刷新,读的是最近一次刷新结果。
- 读 / 写识别:写 = Edit / Write / MultiEdit / NotebookEdit 成功改动目录内文件;读 = Read 读取目录内文件,或 Bash 命令读取目录内文件(Bash 复用平台上报的「命令文本推断」口径,同一份实现)。只列目录、grep、glob 不算。目录必须存在且头部有 `> 负责人:` 才参与绑定。
- 手动绑定:agent 或用户执行 `cgraphx task use <编号或名称>`;事后补绑用 `timeline query` 找到会话 id 后带 `--session`。

## 参与者与系统

- Claude Code / CodeBuddy(hook 宿主、agent)
- task 子系统:`src/core/task/`
- timeline 子系统(提供事件与按会话的最大事件 id,只经门面读)
- features 子系统(提供目录负责人与头部任务声明,只经门面读)
- agents 子系统(按事件来源 agent 取写类工具名)
- sync 子系统(只读消费有效绑定,不反向被依赖)

## 主链路与状态流转

派生规则只有一处实现(`deriveSessionAutoBinding`),状态机:

| # | 当前状态 | 触发 | 结果 |
|---|---|---|---|
| R1 | 未绑定 | 读目录 D | 暂定绑定到 D,区间起点回溯到会话最早一条事件 |
| R2 | 暂定(D) | 读目录 D2,日期前缀更晚 | 暂定整段改为 D2(起点仍是会话起点) |
| R3 | 暂定(D) | 读目录 D2,日期相同或更早 | 不变 |
| R4 | 未绑定 / 暂定 | 写目录 D | 确定绑定到 D,整段改为 D |
| R5 | 确定(D) | 读或写其它目录 | 不变;写入文件记为该任务产出 |
| R6 | 任意 | `task use` / `task clear` | 以手动为准;此后本会话自动规则停止 |
| R7 | 未绑定 | 整个会话没碰过产出目录 | 保持未归属,不建任务 |

- 日期前缀取 feature-id 开头的 `YYYY-MM-DD`,取不到视为最早。
- 目录 → 任务:主 spec 头部 `> 任务: T-<n>` → 平台任务;否则 → 目录任务(任务键 = feature-id)。多个目录指向同一平台任务时按目录比较,改正后任务可能相同。
- 负责人 = 目录主 spec 头部 `> 负责人:`(没有主 spec 时取交接文件);等于本机 `git config user.name` 时才在平台上声明该目录任务,否则只上报绑定段。
- 有效绑定 = 手动 / 旧绑定(`task_sessions`)+ 派生绑定(`task_auto_sessions`)。派生段的结束点是「该会话保留手动绑定的最早起点」与「停止点」的较早者;结束点不晚于起点时不出现。bindingKey:手动 / 旧绑定为 `String(task_sessions.id)`,派生段为 `auto:<sessionId>`。
- 首轮历史派生会把被取代的旧绑定标记进 `task_superseded_bindings`(不删不改原行),上报时按零长度区间重报(见「平台上报」)。

## 异常分支

- 拿不到会话 id(不在会话内,也没给 `--session`):`task use` 报参数错误,退出码 3。
- hook 内的任何失败(未初始化、DB 异常、目录读不到)都只写 stderr,不阻塞 agent,也不影响 timeline 事件写入。
- 环境变量 `CGRAPHX_NO_TIMELINE` 打开时,timeline 记录、自动派生、会话开始注入一起关闭;显式 `cgraphx task` 命令不受影响。
- 目录在会话期间被删除:目录任务的绑定通过已持久化的 `task_feature_tasks` 行保留。头部写了 `T-<n>` 的目录没有目录任务行,删除后该段会丢失(见 Open Questions)。
- 会话恢复(`resume`)后 session id 不变,视为同一会话,沿用其派生 / 停止状态。
- 旧版全局 cgraphx 命中 PATH 时:task 的 hook 命令带 `2>/dev/null || true` 容错后缀;新表只加不升版本,旧二进制打开库不会报错。

## 关键约束与陷阱

- **归属口径**:事件属于任务 T,当且仅当它的 session_id 和时间落在 T 的某条绑定区间内。区间左闭右开(`bound_at ≤ ts < unbound_at`)。timeline 查询的 until 是闭区间,所以 task 侧要再剔除 `ts = unbound_at` 的事件。
- **派生只存目录,不存任务**:目录头部补 `> 任务:` 不需要重算历史;反过来,读取时任务必须由目录 + 头部解析出来。目录删除时只有目录任务行可兜底。
- **首轮只做一次**:`task_auto_meta.history_pass_done` 标记首轮历史派生;之后按「会话最大事件 id 是否变化」增量刷新。首轮单会话失败只跳过该会话,不影响其它会话。
- **手动优先级最高**:手动绑定存在时,派生段在手动起点处截止;`task use` 之后不再有新的自动段。`task clear` 在没有派生行时也会写入停止点,避免「clear 之后首次刷新又绑上」。
- **自动绑定不覆盖手动**:R6 只在手动操作时触发;确定绑定后的写不切换(R5)。
- **hook 预算**:hook 内不发网络请求、不等待子进程;DB 写入必须 await;stdout 只有 SessionStart 输出一行 `hookSpecificOutput`,Stop 与兼容 PostToolUse 的 stdout 必须为空。
- **依赖方向**:task → timeline / features / agents;sync 只经门面读 task;timeline / features 不反向依赖 task 或 sync。
- 目录任务不能手动绑定;`task use` 对 feature-id / 目录任务 id / 目录任务名 / 映射编号会明确拒绝,避免外键错误或静默新建手动任务。
- 终端手动 commit 永远未归属:它不在任何会话里,session_id 为空;也不按分支名推断。
- 2026-10-18 起,agent 上下文里不再注入任何任务内容;原「自动绑定提醒」逻辑已删除,`task_reminders` 表保留但不再写入。

## Open Questions

- 用 `claude --resume` 恢复会话后 session_id 是否沿用还没有实测;如果不沿用,恢复后的会话会重新派生。
- 头部 `> 任务: T-<n>` 的目录被删除后,没有目录任务行可兜底,已产生的绑定会丢失。完整修复需要把任务快照落库,与「派生只存目录」的设计冲突,待定案。
- 本地 web 不主动刷新派生,未安装 Stop hook 的旧项目需要先执行一次 task 命令或 sync 才能看到自动绑定。
