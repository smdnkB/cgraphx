# 需求副本

## Summary

需求副本是一个需求独占的工作目录:由 `/dev-start`(程序侧 `cgraphx replica create`)在主目录旁边写时复制出来、并在主目录登记过的整仓副本,目录名 `<主目录名>@<文件前缀>`(如 `cgraphx@订单导出`),又称副本 / replica / 写时复制副本。每个需求在自己的副本里、自己的需求分支(`feat/<文件前缀>`,bug 修复 `fix/`)上做,做完用 `/dev-merge` 合回主目录当前所在的分支,几个会话并行时不再挤在同一个分支上。副本的数据归主目录:副本 `.cgraphx/` 里的 `shared` 链接指回主目录的 `.cgraphx/`,共用数据经「数据目录」(`getDataDir`)读写主目录,所以副本里的会话、提交、任务归属都记在主目录、归到副本登记的需求;只有知识库索引和「我的需求」索引各目录各建各的。自己用 cp 复制的目录、git worktree 不算副本。

## 命名与边界

- 规范名「需求副本」,口语「副本」;代码里叫 replica(`src/core/replica/`,命令 `cgraphx replica`)。与它相对的是「主目录」:项目本来的目录,副本的登记和共用数据都在主目录的 `.cgraphx/` 下。
- 副本 vs 需求目录:需求目录 `docs/features/<feature-id>/` 是产物载体,副本是放整个仓库的工作目录;一个副本登记一个 feature-id,需求目录建在副本里,合入后才回到主目录。
- 口径(定于 2026-10-27-版本流程与需求副本):
  - K1 副本 = 经 `/dev-start` 开出、在主目录登记过的目录。算:`cgraphx@订单导出`;不算:自己用 cp 复制的目录(带着 `shared` 链接也不算)、git worktree。
  - K2 副本里的会话 = 会话开始时所在的目录在副本里。算:在 `cgraphx@订单导出` 里开的会话,中途 cd 到别处也还算;不算:在主目录开、只读过副本里文件的会话。
  - K3 已合入 = 需求分支自己做过提交,而且这些提交都已经在主目录当前所在的分支里(开了版本是版本分支,没开是主目录所在的分支)。「自己做的提交」= 登记的 `baseCommit`(开副本那一刻的提交)以来,需求分支第一父链上的非合并提交;同步进来的别人的提交在合并的第二个父提交那边,不算。合入后没再提交 → 已合入;合入后只同步过 → 仍是已合入;合入后又提交了 1 笔 → 未合入,差 1 个提交;刚开出来还没提交过(同步过也一样)→ 不算已合入,是「还没有提交」,不放进可删的那组。取法是两条第一父链计数:自己做的提交有几个,其中还不在主目录当前分支里的有几个。副本只用 `/dev-merge` 同步(合并提交);用 `git pull`、默认的 `git merge` 快进同步过,同步进来的主干提交落在第一父链上,会被当成自己做的。以前的登记没有 `baseCommit`,按旧口径只看最新提交。
  - K9 没提交的改动 = 改了没提交的已跟踪文件,加上新建了没被 git 跟踪的文件;被忽略的(`.env`、`node_modules`)不算。副本合入、删除前按它查;主目录一侧只查改了没提交的已跟踪文件,没被跟踪的新文件不拦,也不带进副本。

## 关键约束与陷阱

- **开出来的副本里有什么**:
  - 写时复制:macOS `cp -cR`(APFS 克隆)、Linux `cp -R --reflink=always`,本项目 4.1 GB 约 1 秒、几乎不占空间。macOS 的 `cp -c` 克隆不了时会悄悄退成整份复制、命令照样成功,所以复制前先看目标目录和主目录是否同卷、卷是不是 APFS;Linux 以 `--reflink=always` 失败为准。不能克隆就返回 `no_cow`(带需要的空间),问过用户才带 `--full-copy` 整份复制;Windows 返回 `unsupported_platform`。
  - 被忽略的本地文件(依赖包、`.env`)一起带过去,不用重装;没被跟踪的文件不带,只有 `docs/features/<feature-id>/` 下的(如讨论稿)移进副本。写死了主目录路径的(如 Python 虚拟环境的 `pyvenv.cfg`)开完会提示在副本里重建。
  - 各 agent 的配置目录(如 `.claude/`)里开副本时没被跟踪的部分(`git ls-files --others --exclude-standard --directory` 列出的每一项,去掉末尾 `/`)和 `.cgraphx` 写进副本自己的 `.git/info/exclude`,按被忽略的本地文件处理,K9 也不算它们——agent 配置目录里是 hook 配置,删了副本里的会话就记不下来。不能整个目录都写:团队把 `.claude/commands/` 这类提交进仓库时,副本里在那里新建的文件 git 会看不见,合入时不带、删副本时不拦,就丢了;也不能写成带末尾 `/` 的目录模式:`.claude` 是链接时匹配不上,会被当成没被跟踪的文件删掉。
  - 主目录这个需求目录里被忽略的文件留在原处(副本里已有一份);删掉的话只剩副本一份,K9 不看被忽略的文件,删副本时跟着丢。留下的空壳不影响查找:按 feature-id 找需求目录先找登记了它、目录还在的在用副本,没有再找主目录(和 `features list` 取副本那份同一口径)。
  - 副本的 `.cgraphx/` 只有 `.gitignore`、副本自己的知识库库文件和 `shared` 链接;需求分支从主目录当前所在的分支拉。
  - 登记:主目录 `.cgraphx/replicas/<副本目录名>.json`,一个副本一个文件,字段 `name`、`path`、`featureId`、`branch`、`baseBranch`、`baseCommit`、`movedFiles`(开副本时从主目录移进副本的需求文件)、`createdAt`、`removedAt`;删副本只填 `removedAt`,文件留着。登记每次都读文件、不缓存:原地改写了登记,web、sync 这类长驻进程下一次读就是新的。登记按目录名存,所以目录名已登记给别的需求时(副本在用、已删都算)开副本返回 `name_taken`:照开会覆盖旧需求的登记,旧会话重新算归属时就算到新需求头上;dev-start 请用户给新需求换个标题或加业务 ID。同一个需求删了副本再开照旧。
  - 复制失败时只有「克隆不了」才报 `no_cow`;读不了的文件、权限这类原因整份复制也会一样失败,照实报错。
- **数据目录解析的四种结果**(`resolveDataDir`):
  1. 没有 `.cgraphx/shared` 链接 → 用自己的 `.cgraphx/`(`own`)。
  2. 链接目标不存在(主目录挪了位置或改了名)→ `main-missing`:共用数据写不进,写共用数据的地方不建目录、不写,hook 照常放行;cgraphx 命令提示「副本关联的主项目不在 <主目录路径> 了」。在这里顺手 `mkdirSync({ recursive: true })` 会在旧位置重建 `.cgraphx/`,解析随之退成 `own`,数据悄悄写进副本本地。
  3. 链接目标下有本副本的登记、`path` 对得上、`removedAt` 为空 → 主目录的 `.cgraphx/`(`replica`)。
  4. 有链接但没登记、已删除或读不了 → 同 1,用自己的 `.cgraphx/`(手动复制的目录不会写进主目录)。
  - 走数据目录的:共享库(timeline、task、sync 的表)、timeline 轮次文件、task 接口配置、sync 的锁 / 触发 / 存活文件、db-query 连接配置与日志。固定用本地的:知识库库文件(`getLocalDatabasePath`)、`my-features.md`、`isInitialized` 的判断。
- **副本会话归属(K2)**:会话第一条事件的 cwd 在登记过的副本里 → 直接归副本登记的需求,强度记「写」,不看它读写了哪些文件(改了别的需求目录也照样归副本的需求,发版审核把这种改动列为疑似夹带);显式 `cgraphx task use` 优先。副本里没对上会话的提交(终端、不支持 hooks 的 agent)也由 `cgraphx task show <需求>` 算进副本登记的需求:全量刷新(task 命令、sync)时给在用副本登记的需求补建任务行(没有会话派生到它也查得到;spec 还没写时建的是目录任务);主 spec 头部声明了 `> 任务: T-n` 的,这些提交归 T-n(与上报一致),`task show <feature-id>` 也落到 T-n——声明之前建出的、还没有平台编号的目录任务,下一次全量刷新时删掉(已有平台编号的不删)。需求 → 本机任务行只有一处规则(`ensureFeatureTaskRow`):头部声明了平台编号 → 接口任务,否则 → 目录任务。
- **路径在读取时换算**:timeline 照原样记绝对路径和 cwd;task、sync、features 按「主目录 + 全部登记过的副本(含已删除)」取包含该路径的最长根,换成项目内路径;task、sync 在副本里执行时先换成主目录再算。登记删了也保留,所以副本删了,旧记录照样换算、照样归属。
  - 换算在 Stop hook 里每轮要比上万次:按字符串前缀比、不拼临时串,realpath 按目录缓存(路径不在时 realpath 要抛错,很慢)。登记 5 个副本时 Stop hook 约 45ms,预算 50ms;用 `path.relative` 加每条路径一次 realpath 时要 200ms。
  - 上报时产出只对上同一个根里的提交(各根的仓库相对路径相同,只比路径会对上别的根);副本里的提交推送过没有,主目录查不到就到副本仓库再查。开副本之前在主目录写、移进副本的需求文件(登记的 `movedFiles`)算那个副本的:合入后文件回到主目录,产出照样是 create 带副本里那笔提交;以前没有 `movedFiles` 的登记才按文件此刻在哪推断。
- 主目录的 `cgraphx features list` 也列出在用副本里的需求,标「在副本 <副本目录名>」;JSON 只在这些条目上加 `replica: { name, path }`,主目录自己的条目输出不变。
- 知识跟着分支走:副本里新写的知识这个副本马上召回得到,别处要等合入、同步之后重建索引。
- 副本的 `.cgraphx` 不能整个做成链接:macOS 上在副本里 `rm -rf .cgraphx/` 会顺着链接删光主目录的数据,`.cgraphx/` 这类忽略规则也盖不住链接。所以只链 `shared` 一个:在副本里 `rm -rf .cgraphx/`、`cgraphx uninstall` 只删副本自己的;`timeline uninstall --purge` 在副本里直接拒绝,要到主目录执行。
- 开副本、删副本只在主目录执行(否则 `not_main_dir`):在副本里、未初始化、项目根不是独立 git 仓库的根、detached HEAD 都不行。worktree、子模块的 `.git` 是文件,整仓复制出来会和原仓库共用引用,在副本里切分支会改到原仓库。
- **删副本前的五条核对**,任一条不符就不删(`unsafe_target` / `dirty`):
  1. 登记过且没删;
  2. 目录就是登记的 `path`,不是主目录、也不是主目录的上级;
  3. 目录名是 `<主目录名>@…`;
  4. 目录里的 `.cgraphx/shared` 指向本主目录的 `.cgraphx/`;
  5. 没有 K9 改动。
  - 只核对登记不够:登记文件的 `path` 被改错就可能删到别处。删除用 `fs.rmSync`,不跟随链接,不进废纸篓;删完填 `removedAt`,登记和数据都留着;目录已经被手动删掉 → 只填 `removedAt`,状态「已不在」(`missing`)。

## 命令

- `cgraphx replica create <feature-id> --prefix <文件前缀> --branch <分支> [--full-copy] [--json]`:开副本;这个需求的副本已经有了 → `created: false`,不重建。
- `cgraphx replica list [--all] [--json]`:列副本的状态(在 / 已不在 / 已删除)、是否已合入(K3:`merged` 为 false、`ahead` 为 0 是还没有提交,null 是 git 判断不了)、自己做的提交里差几个没合入、没提交的文件(K9);`--all` 含已删除的;在副本里也能跑。
- `cgraphx replica remove <副本目录名或 feature-id> [--json]`:五条核对都过才删。

## 代码入口

- `src/core/replica/`:replica 子系统门面 `index.ts` 与 `cgraphx replica` 命令;开副本 `create.ts`、登记读写 `registry.ts`、删副本前的核对 `remove.ts`;路径换算 `listProjectRoots` / `matchProjectRoot` / `replicaOfCwd` / `locateFeatureRoot` 经门面给 task、sync、features 用。
- `src/core/directory.ts`:`resolveDataDir` / `getDataDir`,数据目录解析;链接名 `shared`、登记目录名 `replicas` 只在这里定义。
- `src/core/db/index.ts`:`getDatabasePath` 走数据目录,`getLocalDatabasePath` 固定本地。
- `src/core/task/auto-binding.ts`:副本会话归属(K2)的派生。
- `assets/claude-template/skills/dev-start/SKILL.md`、`assets/claude-template/skills/dev-merge/SKILL.md`:定需求目录名和分支、开副本后建两份索引、合入与同步、删副本前问用户。

## Open Questions
