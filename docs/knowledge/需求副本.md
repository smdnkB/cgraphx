# 需求副本

## Summary

需求副本是一个需求独占的工作目录:由 `/dev-start`(程序侧 `cgraphx replica create`)在主目录旁边开出、并在主目录登记过的 git worktree,目录名 `<主目录名>@<文件前缀>`(如 `cgraphx@订单导出`),又称副本 / replica / worktree 副本。每个需求在自己的副本里、自己的需求分支(`feat/<文件前缀>`,bug 修复 `fix/`)上做,做完用 `/dev-merge` 合回主目录当前所在的分支,几个会话并行时不再挤在同一个分支上。副本和主目录是同一个项目(按项目名称认——副本带着主目录记下的名字,见「项目」),副本里的会话、提交和主目录记进同一个项目的数据(`~/.cgraphx/projects/<目录名>/`);副本 `.cgraphx/` 里的 `shared` 链接指回主目录的 `.cgraphx/`,只给版本流程、features 与 project 的重名判断用;知识库索引和「我的需求」索引各目录各建各的。自己用 `git worktree add` 开的目录、`cp` 复制的目录不算副本。

## 命名与边界

- 规范名「需求副本」,口语「副本」;代码里叫 replica(`src/core/replica/`,命令 `cgraphx replica`)。与它相对的是「主目录」:项目本来的目录,副本的登记在主目录的 `.cgraphx/replicas/` 下(2026-11-05 起共用数据不再放主目录,见「项目」)。
- 副本 vs 需求目录:需求目录 `docs/features/<feature-id>/` 是产物载体,副本是放整个仓库的工作目录;一个副本登记一个 feature-id,需求目录建在副本里,合入后才回到主目录。
- 口径(定于 2026-10-27-版本流程与需求副本):
  - K1 副本 = 经 `/dev-start` 开出、在主目录 `.cgraphx/replicas/` 登记过的 git worktree。算:`cgraphx@订单导出`;不算:自己 `git worktree add` 开的目录、`cp` 复制的目录。
  - K2 副本里的会话 = 会话开始时所在的目录在副本里。算:在 `cgraphx@订单导出` 里开的会话,中途 cd 到别处也还算;不算:在主目录开、只读过副本里文件的会话。
  - K3 已合入 = 需求分支自己做过提交,而且这些提交都已经在主目录当前所在的分支里(开了版本是版本分支,没开是主目录所在的分支)。「自己做的提交」= 登记的 `baseCommit`(开副本那一刻的提交)以来,需求分支第一父链上的非合并提交;同步进来的别人的提交在合并的第二个父提交那边,不算。合入后没再提交 → 已合入;合入后只同步过 → 仍是已合入;合入后又提交了 1 笔 → 未合入,差 1 个提交;刚开出来还没提交过(同步过也一样)→ 不算已合入,是「还没有提交」,不放进可删的那组。取法是两条第一父链计数:自己做的提交有几个,其中还不在主目录当前分支里的有几个。副本只用 `/dev-merge` 同步(合并提交);用 `git pull`、默认的 `git merge` 快进同步过,同步进来的主干提交落在第一父链上,会被当成自己做的。以前的登记没有 `baseCommit`,按旧口径只看最新提交。
  - K9 没提交的改动 = 改了没提交的已跟踪文件,加上新建了没被 git 跟踪的文件;被忽略的(`.env`、`node_modules`)不算。副本合入、删除前按它查;主目录一侧只查改了没提交的已跟踪文件,没被跟踪的新文件不拦,也不带进副本(主目录有改动只提示,不拦)。

## 关键约束与陷阱

- **开出来的副本里有什么**:
  - worktree:和主目录同一个仓库,`git worktree add` 秒级开出来,不复制工作区;依赖和构建产物**不带**,第一次要在副本里安装、构建一次。Windows 返回 `unsupported_platform`。
  - 带 agent 配置:各已登记 agent 的配置目录(`configDirName`,如 `.claude/`)、指引文件(`instructionsFileName`,如 `CLAUDE.md`)和额外配置(Claude Code 的 `.mcp.json`),只带**没被 git 跟踪**的部分:这几项去重后在主目录 `git ls-files --others --directory` 列出的每一项(去掉末尾 `/`)拷进副本,新增一家 agent 登记描述就一起带。agent 自己开的 worktree(不管在哪家配置目录里)跳过。
  - 带清单文件:主目录根下的 `.worktreeinclude`,gitignore 语法(一行一个路径,`#` 注释,可用通配),路径相对项目根;cgraphx 不创建、不提交,项目自己决定要不要提交(提交了团队共用);取的是清单模式匹配到、又被 git 忽略的文件,已被 git 跟踪的文件 worktree 本来就有,跳过;清单里的行主目录没有 → 提示、不带;`.cgraphx/` 下的不带。
  - 对 git 隐藏:带进来的文件在副本里用副本自己的 `core.excludesFile`(`<副本>/.cgraphx/replica-exclude`,内容是用户级忽略文件原文 + 这些路径)藏起来,主仓库为此开 `extensions.worktreeConfig`;主目录照常看得见;不写共享的 `.git/info/exclude`(worktree 共用,写进去会盖住主目录)。这条也让 K9 不把带进来的 `.env`、`.mcp.json` 算成没提交。
  - 需求目录:这个需求目录下没被跟踪的文件拷进副本,其他步骤都成功后删主目录那份;删不掉提示手动删;内嵌的 git 仓库不删。
    - 被忽略的文件留在主目录(副本里已有一份);删掉的话只剩副本一份,K9 不看被忽略的文件,删副本时跟着丢。留下的空壳不影响查找:按 feature-id 找需求目录先找登记了它、目录还在的在用副本,没有再找主目录(和 `features list` 取副本那份同一口径)。
  - 副本的 `.cgraphx/` 只有 `.gitignore`、副本自己的知识库库文件和 `shared` 链接;需求分支从主目录当前所在的分支拉。
  - 登记:主目录 `.cgraphx/replicas/<副本目录名>.json`,一个副本一个文件,字段 `name`、`path`、`featureId`、`branch`、`baseBranch`、`baseCommit`、`movedFiles`(开副本时从主目录移进副本的需求文件)、`createdAt`、`removedAt`;删副本只填 `removedAt`,文件留着。登记每次都读文件、不缓存:原地改写了登记,读它的功能(features、replica 命令)下一次读就是新的。登记按目录名存,所以目录名已登记给别的需求时(副本在用、已删都算)开副本返回 `name_taken`:照开会覆盖旧需求的登记,旧会话重新算归属时就算到新需求头上;dev-start 请用户给新需求换个标题或加业务 ID。同一个需求删了副本再开照旧;删副本时留下的分支,重开同一个需求会接上,`baseCommit` 沿用第一次那条,差几个提交照旧算(K15)。
- **2026-11-05 起数据不再经 `shared` 链接**(需求「数据按项目放用户目录」):timeline、task、sync 的库和文件按项目放在 `~/.cgraphx/projects/<目录名>/`,副本和主目录按项目名称认成同一个项目,数据位置见「项目」。
  - `shared` 链接只剩版本流程、features 与 project 的重名判断用:`replicaLinkOf` 判断是不是副本、主目录在哪,结果是 `own`、`replica`、`main-missing` 三种,判定和原来相同。
  - 副本登记改读主目录本地的 `.cgraphx/replicas/`。
  - 原来的「主目录不在了,共用数据写不进」的提示随之删掉。
- **副本会话归属(K2)与副本提交算进需求**:已随开发任务、平台上报下掉,见 `docs/features/2026-11-05-下掉web与平台同步/`;原口径保留在「开发任务绑定」「平台上报」。
- **路径在读取时换算**:timeline 照原样记绝对路径和 cwd;按项目的根汇总取包含该路径的最长根,换成项目内路径。根汇总 = timeline 记下的根 + 当前根 + 这些根上的副本登记(含已删除),2026-11-05 起不再先换成主目录再算;登记删了也保留,副本删了旧记录照样换算。原先走这条链路的读取方是 task、sync(Stop hook 每轮比对上万条路径:按字符串前缀比、不拼临时串,realpath 按目录缓存,登记 5 个副本约 45ms),已随子系统下掉,见 `docs/features/2026-11-05-下掉web与平台同步/`;换算助手(`listProjectRoots` / `matchProjectRoot` 等)仍由 replica 门面导出。
- 主目录的 `cgraphx features list` 也列出在用副本里的需求,标「在副本 <副本目录名>」;JSON 只在这些条目上加 `replica: { name, path }`,主目录自己的条目输出不变。
- 知识跟着分支走:副本里新写的知识这个副本马上召回得到,别处要等合入、同步之后重建索引。
- 副本的 `.cgraphx` 不能整个做成链接:macOS 上在副本里 `rm -rf .cgraphx/` 会顺着链接删光主目录的数据,`.cgraphx/` 这类忽略规则也盖不住链接。所以只链 `shared` 一个:在副本里 `rm -rf .cgraphx/`、`cgraphx uninstall` 只删副本自己的;2026-11-05 起 `timeline uninstall --purge` 不再删数据,项目的数据用 `cgraphx project remove` 删。
- 开副本、删副本只在主目录执行(否则 `not_main_dir`):在副本里、未初始化、项目根不是独立 git 仓库的根(含 worktree、子模块的 `.git` 是文件)、detached HEAD 都不行。这些位置开出来的 worktree 不是需求副本(`/dev-start` 用 `replica create` 登记),不算副本。
- **删副本前的六条核对**,任一条不符就不删(`unsafe_target` / `dirty`):
  1. 登记过且没删;
  2. 目录就是登记的 `path`,不是主目录、也不是主目录的上级;
  3. 目录名是 `<主目录名>@…`;
  4. 目录里的 `.cgraphx/shared` 指向本主目录的 `.cgraphx/`;
  5. 确实是本仓库的 worktree(`git worktree list` 里有它);
  6. 没有 K9 改动。
  - 只核对登记不够:登记文件的 `path` 被改错就可能删到别处,第 5 条再拦一次「目录在、但不是本仓库的 worktree」。删除用 `git worktree remove --force`(副本里常有被忽略的依赖和 `.env`,不带 force 会被拒绝),删完把登记填 `removedAt`,登记留着,副本里记下的会话和提交在项目的数据里。
  - 需求分支按合入情况(K3)处理:已合入、或还没有提交的删掉;差提交的留着,并在结果里给分支名和删除前的 `tip`;判断不了的留着;分支删不掉只提示(`warnings`)。
  - 目录已经被手动删掉 → `git worktree prune`,同样按上面的规则处理分支,再只填 `removedAt`,状态「已不在」(`missing`)。

## 命令

- `cgraphx replica create <feature-id> --prefix <文件前缀> --branch <分支> [--json]`:开 worktree、带 agent 配置与清单文件、登记;接上删副本时留下的分支(`reattached`)。这个需求已有在用副本 → 报 `feature_has_replica`,不开第二个(已删、目录不在的照常另开)。
- `cgraphx replica list [--all] [--json]`:列副本的状态(在 / 已不在 / 已删除)、是否已合入(K3:`merged` 为 false、`ahead` 为 0 是还没有提交,null 是 git 判断不了)、自己做的提交里差几个没合入、没提交的文件(K9);`--all` 含已删除的;在副本里也能跑。
- `cgraphx replica remove <副本目录名或 feature-id> [--json]`:六条核对都过才删;结果带 `branch`(需求分支是删了还是留着、删之前的 `tip`)。

## 代码入口

- `src/core/replica/`:replica 子系统门面 `index.ts` 与 `cgraphx replica` 命令;开 worktree 的 `create.ts`、带 agent 配置与清单文件并把这些文件对 git 藏起来的 `carry.ts`、合入判断(K3 读主目录本地分支)的 `status.ts`、删 worktree 与需求分支的 `remove.ts`、登记读写的 `registry.ts`;路径换算 `listProjectRoots` / `matchProjectRoot` / `replicaOfCwd` / `locateFeatureRoot` 经门面导出(原先的调用方 task、sync 已随子系统下掉,features 只用登记与 `replicaLinkOf`)。
- `src/core/replica/main-dir.ts`:`replicaLinkOf`,判断是不是副本、主目录在哪;链接名 `shared`、登记目录名 `replicas` 定义在 `src/core/directory.ts`。
- `assets/claude-template/skills/dev-start/SKILL.md`、`assets/claude-template/skills/dev-merge/SKILL.md`:定需求目录名和分支、开副本后建两份索引、合入与同步、删副本前问用户。
