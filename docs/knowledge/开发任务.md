# 开发任务

## Summary

开发任务是项目管理意义上的工作项,是 timeline 事件归属的对象,由 cgraphx 的 task 子系统(`cgraphx task` 命令组)管理,又称 task / 工作项。它有两种来源:接口任务(从外部任务接口拉取,有外部编号)和手动任务(没配接口时由用户输入名称建立,没有外部编号)。开发任务不等于需求目录:一个任务可以被多个 `docs/features/` 需求目录在 spec 头部用 `> 任务:` 声明;它也和 Claude Code 自带的 Task 工具无关。

## 命名与边界

- 规范名「开发任务」;代码里叫 task(`TaskItem`、`task_items` 表),命令为 `cgraphx task`。
- **开发任务 vs 需求目录**:需求目录是 spec/plan 的产物载体,开发任务是工作项;两者通过 spec 头部 `> 任务:` 多对一关联,关联关系只以 spec 头部为准,不另外存储。
- **开发任务 vs Claude Code 的 Task / TaskCreate 工具**:后者是 agent 会话内的待办,timeline 里记成 tool_name,和本实体无关。
- **接口任务 vs 手动任务**:由 `source` 区分(`api` / `manual`)。接口任务按外部编号去重,手动任务按名称去重。

## 关键约束与陷阱

- 事件属于哪个开发任务**不存在事件上**:`timeline_events` 没有任务列,归属在查询时用「会话 + 绑定时间区间」join 派生。所以事后补绑、改绑都不需要回填事件。
- 外部接口不再返回的任务**保留不删**,因为历史绑定还要能查到。
- 配置了外部接口后,手动任务必须显式 `--manual` 才能建,目的是防止编号输错时悄悄建出一个手动任务。
- spec 声明的任务值在本地找不到时会自动建:配了接口就建一个接口任务占位(名称等于编号,下次 `task list` 刷新时更新),没配接口就建手动任务。
- 外部任务接口的契约由 cgraphx 规定(`GET` 地址加配置里的 headers,返回 `{"tasks":[{id,name,url?,status?}]}`),「我名下」由接口根据认证信息判定。对接方按这个契约提供接口,或自己建一层转接。

## 代码入口

- `src/core/task/index.ts`:task 子系统门面,外部只能经它调用。
- `src/core/task/store.ts`、`src/core/task/schema.sql`:任务与绑定的持久化。
- `src/core/task/source.ts`:外部任务接口配置(`.cgraphx/task-source.json`)与拉取。
- `src/core/task/resolve.ts`:「用户输入的值 → 哪个任务」的解析规则。
- `src/core/task/report.ts`:只读的任务汇总与报告(投入时长、产出、参考),web 开发任务页经它取数;只读调用方必须用这一组,不要用会建表的 `openTaskDb` 路径。

## 相关表

包内 SQLite `.cgraphx/cgraphx.db`:`task_items`(任务本体)、`task_sessions`(会话绑定)、`task_reminders`(提醒去重)、`task_schema_versions`。表结构以 `src/core/task/schema.sql` 为准。
