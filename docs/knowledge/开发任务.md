# 开发任务

## Summary

开发任务是项目管理意义上的工作项,是 timeline 事件归属的对象,由 cgraphx 的 task 子系统(`cgraphx task` 命令组)管理,又称 task / 工作项。它有三种来源:接口任务(从外部任务接口拉取,有外部编号)、手动任务(没配接口时由用户输入名称建立)和目录任务(2026-10-18 起,由产出目录 `docs/features/<feature-id>/` 派生,任务键 = feature-id,名称 = 去掉日期前缀的文件前缀)。开发任务不等于产出目录:一个目录对应一个目录任务;目录主 spec 头部写了 `> 任务: T-<n>` 时,该目录对应平台上的那个任务而不是目录任务。它也和 Claude Code 自带的 Task 工具无关。

## 命名与边界

- 规范名「开发任务」;代码里叫 task(`TaskItem`、`task_items` 表),命令为 `cgraphx task`。
- **开发任务 vs 产出目录**:产出目录是 spec / plan / 交接文件的产物载体,目录任务是「这个目录对应的工作项」。一个产出目录最多对应一个任务;平台上一个需求下可以挂多个任务,两者不是同义词。
- **接口任务 vs 手动任务 vs 目录任务**:由 `source` 区分(`api` / `manual` / `feature`)。接口任务按外部编号去重,手动任务按名称去重;目录任务单独成表,按 feature-id 去重,id 从 `FEATURE_TASK_ID_BASE` 起,与 `task_items` 的 id 空间不重叠。
- **目录 → 任务**:主 spec 头部 `> 任务:` 的值匹配 `T-<n>` → 平台任务(本地没有则建接口任务占位);否则 → 目录任务(本地没有则按需创建)。目录负责人取主 spec 头部 `> 负责人:`,没有主 spec 时取交接文件;目录没有负责人头部时不对应任何任务。
- **开发任务 vs Claude Code 的 Task / TaskCreate 工具**:后者是 agent 会话内的待办,timeline 里记成 tool_name,和本实体无关。

## 关键约束与陷阱

- 事件属于哪个开发任务**不存在事件上**:`timeline_events` 没有任务列,归属在查询时用「会话 + 绑定时间区间」join 派生。所以事后补绑、改绑、历史重新派生都不需要回填事件。
- 2026-10-18:**会话归属改为从 timeline 事件按产出目录派生**,派生只存「哪个目录 + 读 / 写 + 区间」,不存「对应哪个任务」;任务在读取时解析。好处是目录头部补 `> 任务:` 不需要重算历史;代价是目录被删除后要用已持久化的目录任务兜底(见「开发任务绑定」)。
- 目录任务 id 空间(`1000000001` 起)一旦进入本地 web 链接与上报就不能再改;`task_items` 的 CHECK 仍只有 `api` / `manual`,目录任务不得写进 `task_items`。
- 目录任务**不能手动绑定**:`task_sessions.task_id` 外键指向 `task_items`,手动绑定也无法表达「由目录决定任务」的语义。`task use` 对目录任务 id / feature-id / 目录任务名称 / 映射编号会明确拒绝,而不是触发外键错误或静默建手动任务。
- task schema 2026-10-18 只加表、不升版本(`TASK_SCHEMA_VERSION` 仍为 1):旧版全局 cgraphx 打开库时不能因为新表报错。新表:目录任务、派生会话、被取代绑定、派生元信息。
- 外部接口不再返回的任务**保留不删**,因为历史绑定还要能查到。
- 配置了外部接口后,手动任务必须显式 `--manual` 才能建,目的是防止编号输错时悄悄建出一个手动任务。
- spec 声明的任务值在本地找不到时会自动建:配了接口就建一个接口任务占位(名称等于编号,下次 `task list` 刷新时更新),没配接口就建手动任务。
- 外部任务接口的契约由 cgraphx 规定(`GET` 地址加配置里的 headers,返回 `{"tasks":[{id,name,url?,status?}]}`),「我名下」由接口根据认证信息判定。对接方按这个契约提供接口,或自己建一层转接。
- 2026-10-16:**外部任务接口返回的 `id` 不要用纯数字**。`task use` / `findTask` 对纯数字值先按本地 `task_items.id` 匹配,命中就不再看外部编号——外部 id 为 `12` 而本地恰好有 id=12 的任务时,会绑到本地那个任务上。研发管理服务端因此对外一律返回 `T-<n>`(如 `T-12`)。
- 2026-10-16:**`.cgraphx/task-source.json` 同时是平台上报的凭据**。`cgraphx sync connect` 接入研发管理平台时,会自动写好这个文件,指向平台的「我的任务列表」并带上报凭据;拉任务和上报共用这一份,`sync disconnect` 会把它删掉(已拉到本地的接口任务保留)。手工改坏或删除这个文件,等于断开平台。见「平台上报」。
- 2026-10-18:**目录任务映射到平台编号后,`task list` 是 `task_items ∪ task_feature_tasks` 的无去重并集**。如果 task-source 随后也拉到同一个平台任务,本地会同时出现接口任务与目录任务;当前未去重,见 Open Questions。

## 代码入口

- `src/core/task/index.ts`:task 子系统门面,外部只能经它调用。
- `src/core/task/store.ts`、`src/core/task/schema.sql`:任务、绑定、目录任务、派生会话与元信息的持久化。
- `src/core/task/auto-binding.ts`:R1~R7 派生的唯一实现与刷新入口。
- `src/core/task/feature-task.ts`:目录资格、目录 → 任务解析、负责人声明、平台映射写回。
- `src/core/task/feature-name.ts`:feature-id 的日期前缀与目录任务名称。
- `src/core/task/source.ts`:外部任务接口配置(`.cgraphx/task-source.json`)与拉取。
- `src/core/task/resolve.ts`:「用户输入的值 → 哪个任务」的解析规则。
- `src/core/task/report.ts`:只读的任务汇总与报告(有效绑定、投入时长、产出、参考),web 开发任务页经它取数;只读调用方必须用这一组,不要用会建表的 `openTaskDb` 路径。

## 相关表

包内 SQLite `.cgraphx/cgraphx.db`:`task_items`(接口 / 手动任务)、`task_sessions`(手动 / 旧绑定)、`task_feature_tasks`(目录任务)、`task_auto_sessions`(每会话派生结果)、`task_superseded_bindings`(首轮历史被取代的旧绑定)、`task_auto_meta`(首轮历史标记)、`task_reminders`(提醒去重,保留不再写入)、`task_schema_versions`。表结构以 `src/core/task/schema.sql` 为准。
